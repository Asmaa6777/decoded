# Codes and Floating Point

Bits have no meaning by themselves. `01000111` could be the number 71, the letter G or part of an instruction. A **code** is an agreement about what a pattern stands for, and different jobs call for different codes.

<CodeTable />

## BCD: decimal digits, one at a time

Binary-coded decimal gives each decimal digit its own 4 bits. The number 83 becomes `1000 0011`, not the binary `1010011`. Each group uses the weights 8, 4, 2, 1, which is why it's also called the **8421 code**. It wastes a few patterns, but converting to a display is easy, so calculators and digital clocks like it.

**Excess-3** is BCD with 3 added to every digit, so 5 is `1000`. Its use is that a digit's 9's complement is just its bits flipped, which makes decimal subtraction easy.

## Gray code: one bit at a time

Going from 3 to 4 in binary means `011` becomes `100`, so all three bits change. Real hardware never changes them at exactly the same moment, and a sensor reading mid-change could report any pattern at all.

**Gray code** reorders the numbers so that neighbours differ by exactly one bit. Turn the shaft below in each mode and count the flips.

<GrayEncoder />

To convert binary to Gray, keep the first bit, then XOR each neighbouring pair. So `10110` becomes `11101`. You will see this code again in [Karnaugh maps](/courses/logic-design/karnaugh-maps), where it does a very different job.

## ASCII: text

ASCII gives each character a number. G is 71, which is `01000111`. The original code uses 7 bits for 128 characters, of which the first 32 are control codes. Unicode extends the idea to cover the world's writing systems.

## Floating point: very large and very small numbers

Scientific notation writes the speed of light as $2.998 \times 10^8$: a few significant digits, plus how far to slide the point. Floating point does the same thing in binary. A 32-bit single-precision number has three fields:

| Field | Bits | Meaning |
|---|---|---|
| Sign | 1 | 0 is positive, 1 is negative |
| Exponent | 8 | How far to slide the point, stored with 127 added so it's never negative |
| Fraction | 23 | The digits after the point. The leading `1.` isn't stored, because it's always there |

Type a number and see its bits.

<FloatExplorer />

The speed of light, 299,800,000, is $1.0001\ldots \times 2^{28}$ in binary. So the sign is 0 and the exponent is $28 + 127 = 155$, or `10011011`. The fraction holds the bits after the dropped leading 1.

Try 0.1 and notice the warning. There are only 23 bits for the digits, so most decimal fractions get rounded. For money, that's why programs count in whole cents.
