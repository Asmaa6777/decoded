# Relations, Equivalence and Order

"Follows" on a social network, "depends on" in a package manager, "is less than" on numbers, "has the same remainder as" in modular arithmetic. Each one connects some elements to others. A relation is the general idea, and a handful of properties decide what you can do with one: group things into classes, put them in order, or neither.

## What a relation is

A **relation** $R$ from $A$ to $B$ is any subset of $A \times B$, the [Cartesian product](/courses/discrete-mathematics/sets#cartesian-products). If $(a, b) \in R$ we say $a$ is related to $b$ and write $a \mathrel{R} b$. A relation from a set $A$ to itself is called a relation **on** $A$.

Unlike a [function](/courses/discrete-mathematics/functions#what-a-function-is), a relation has no rules: an element can be related to nothing, to one thing or to many. Every function is a relation, but not the other way round.

There are three standard pictures of a relation on a small set:

- a **list of pairs**: $\{(1,2), (2,3)\}$,
- a **matrix**: row $a$, column $b$, a 1 where $a \mathrel{R} b$,
- a **directed graph**: an arrow from $a$ to $b$ for each pair.

The lab below uses the matrix. Click any cell to switch a pair on or off.

## The four properties

Four properties sort almost every relation you'll meet, and each one can be read straight off the **relation matrix**, the grid with a 1 wherever $a$ is related to $b$. For a relation $R$ on a set $A$:

| Property | Definition | In the matrix |
|---|---|---|
| **Reflexive** | $\forall a:\ a \mathrel{R} a$ | the whole diagonal is 1 |
| **Symmetric** | $a \mathrel{R} b \to b \mathrel{R} a$ | the matrix mirrors across the diagonal |
| **Antisymmetric** | $a \mathrel{R} b \land b \mathrel{R} a \to a = b$ | no off-diagonal pair is 1 both ways |
| **Transitive** | $a \mathrel{R} b \land b \mathrel{R} c \to a \mathrel{R} c$ | every two-step path has a direct shortcut |

When a property fails, the lab names the pair that breaks it and outlines the cells involved. Try each preset, then break one with a single click.

<Callout tone="orange" label="Antisymmetric is not the opposite of symmetric">
A relation can be both: equality is. It can also be neither: $\{(1,2), (2,1), (1,3)\}$ isn't symmetric, because $1 \to 3$ has no reverse, and isn't antisymmetric, because 1 and 2 point at each other. Antisymmetric only forbids two *different* elements pointing at each other; "not symmetric" only means at least one arrow is missing its reverse.
</Callout>

## Equivalence relations

A relation that is reflexive, symmetric and transitive is an **equivalence relation**. It says two things are "the same in some respect": the same remainder, the same colour, the same lowercase spelling.

An equivalence relation splits the set into **equivalence classes**: groups where everything is related to everything else in the group and to nothing outside it. The class of $a$ is written $[a] = \{x \mid x \mathrel{R} a\}$. Every element is in exactly one class, so the classes form a **partition**: non-overlapping pieces that cover the whole set.

Load **a ≡ b (mod 3)**. The matrix shows three blocks and the lab lists the classes $\{1, 4\}$, $\{2, 5\}$, $\{3, 6\}$: the numbers with remainder 1, 2 and 0. This is [congruence](/courses/computational-mathematics/modular-arithmetic#congruence), and the reason modular arithmetic works is that you can calculate with a whole class at once by picking any member.

## Partial orders

A relation that is reflexive, **antisymmetric** and transitive is a **partial order**, often written $\preceq$. It describes "comes before or is the same as."

- $\le$ on numbers is a partial order, and a **total** one too: any two numbers can be compared.
- "divides" on $\{1, \dots, 6\}$ is a partial order but not total: neither $2 \mid 3$ nor $3 \mid 2$. Those two are **incomparable**.
- $\subseteq$ on sets is a partial order. $\{a\}$ and $\{b\}$ are incomparable.

"Partial" means some pairs have no order between them. That's exactly the situation with tasks that depend on each other: compile `utils` before `api`, but `parser` and `net` can go in either order. Turning a partial order into a full sequence that respects it is a [topological sort](/courses/discrete-mathematics/paths-and-dags#topological-sort).

A partial order is usually drawn as a **Hasse diagram**: put smaller elements lower, draw a line only for direct steps, and leave out the loops and shortcuts that reflexivity and transitivity imply anyway.

## Closures

If a relation is missing a property, you can add the fewest pairs needed to give it that property. The result is a **closure**. The interesting one is the **transitive closure**: add $(a, c)$ whenever there's a path from $a$ to $c$.

Load **b = a + 1** and press **Transitive closure**. "Is one more than" becomes "is less than": $1 \to 2 \to 3$ gains the shortcut $1 \to 3$, and so on. The lab uses Warshall's algorithm, which tries each element in turn as a stepping stone between every pair, $O(n^3)$ steps in all.

<PracticalApplication title="Reachability" tool="Graph databases, git">
"Can user A see user B's post through friends of friends?" and `git merge-base --is-ancestor` are transitive-closure questions.
</PracticalApplication>
<PracticalApplication title="Version ordering" tool="npm, semver">
Version numbers are compared part by part, which is a total order. Dependencies between packages form a partial order, which is why installers must sort them first.
</PracticalApplication>
</ApplicationsGrid>
