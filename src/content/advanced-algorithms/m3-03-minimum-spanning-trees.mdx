# Minimum Spanning Trees: Prim and Kruskal

This lesson proves that [greedy algorithms](/courses/advanced-algorithms/greedy-algorithms#a-short-list-of-algorithm-types) **really do** find a minimum spanning tree, and builds the two classic ones: **Prim's** and **Kruskal's**.

[Minimum spanning trees](/courses/algorithm-design-and-analysis/greedy-and-mst#minimum-spanning-trees) are introduced without these proofs in Algorithm Design and Analysis.

## Graphs (review)

A **graph** $G = (V, E)$ is

- a set $V$ of **vertices** (singular: vertex), and
- a set $E \subseteq V \times V$ of **edges**.

In an **undirected** graph, $(u, v)$ and $(v, u)$ are the same edge. In a **directed** graph (digraph), they're different.

In either case, $|E| = O(V^2)$. Moreover, if $G$ is connected, then $|E| \ge |V| - 1$, which implies that $\lg |E| = \Theta(\lg V)$. (We often write $V$ and $E$ for $|V|$ and $|E|$.)

### Adjacency-matrix representation

The **adjacency matrix** of $G = (V, E)$, where $V = \{1, 2, \dots, n\}$, is the matrix $A[1 \dots n, 1 \dots n]$ given by

$$
A[i, j] =
\begin{cases}
1 & \text{if } (i, j) \in E \\
0 & \text{if } (i, j) \notin E
\end{cases}
$$

For the directed graph with edges $1 \to 2$, $1 \to 3$, $2 \to 3$ and $4 \to 3$:

| A | 1 | 2 | 3 | 4 |
| --- | --- | --- | --- | --- |
| **1** | 0 | 1 | 1 | 0 |
| **2** | 0 | 0 | 1 | 0 |
| **3** | 0 | 0 | 0 | 0 |
| **4** | 0 | 0 | 1 | 0 |

It takes $\Theta(V^2)$ storage, so it's a **dense** representation.

### Adjacency-list representation

An **adjacency list** of a vertex $v \in V$ is the list $Adj[v]$ of the vertices adjacent to $v$. For the same graph:

$$
Adj[1] = \{2, 3\} \qquad Adj[2] = \{3\} \qquad Adj[3] = \{\} \qquad Adj[4] = \{3\}
$$

For undirected graphs, $|Adj[v]| = degree(v)$. For digraphs, $|Adj[v]| = \text{out-degree}(v)$.

**Handshaking lemma:** $\sum_{v \in V} degree(v) = 2|E|$ for undirected graphs, since every edge is counted once from each end. So adjacency lists use $\Theta(V + E)$ storage, which makes them a **sparse** representation (good for most graphs in practice).

## Minimum spanning trees

**Input:** a connected, undirected graph $G = (V, E)$ with a weight function $w : E \to \mathbb{R}$. For simplicity, assume all edge weights are **distinct**. (The textbook covers the general case.)

**Output:** a **spanning tree** $T$, a tree that connects all the vertices, of **minimum weight**:

$$
w(T) = \sum_{(u, v) \in T} w(u, v)
$$

## Optimal substructure

Take an MST $T$ (the other edges of $G$ aren't shown). **Remove any edge $(u, v) \in T$.** Then $T$ splits into two subtrees, $T_1$ and $T_2$.

<Callout tone="violet" label="Theorem (optimal substructure)">
The subtree $T_1$ is an MST of $G_1 = (V_1, E_1)$, the subgraph of $G$ **induced** by the vertices of $T_1$:

$$
V_1 = \text{vertices of } T_1, \qquad E_1 = \{\, (x, y) \in E : x, y \in V_1 \,\}
$$

Similarly for $T_2$.
</Callout>

**Proof (cut and paste):** $w(T) = w(u, v) + w(T_1) + w(T_2)$. If $T_1'$ were a lower-weight spanning tree than $T_1$ for $G_1$, then $T' = \{(u, v)\} \cup T_1' \cup T_2$ would be a lower-weight spanning tree than $T$ for $G$, which is impossible. ∎

**Do we also have overlapping subproblems?** Yes. Great, then [dynamic programming](/courses/advanced-algorithms/dynamic-programming) may work! But MSTs have **another powerful property** that leads to an even more efficient algorithm.

## The hallmark of greedy algorithms

<Callout tone="mint" label="Greedy-choice property">
A **locally optimal** choice is **globally optimal**.
</Callout>

<Callout tone="violet" label="Theorem">
Let $T$ be the MST of $G = (V, E)$, and let $A \subseteq V$. Suppose that $(u, v) \in E$ is the **least-weight edge connecting $A$ to $V - A$**. Then $(u, v) \in T$.
</Callout>

**Proof.** Suppose $(u, v) \notin T$. **Cut and paste.**

- $T$ is a spanning tree, so it contains a unique simple path from $u$ to $v$.
- $u \in A$ and $v \in V - A$, so somewhere along that path an edge crosses from $A$ to $V - A$.
- **Swap** $(u, v)$ with the first such edge on the path. The result $T'$ is still a spanning tree, and since $(u, v)$ is the *least-weight* edge crossing, $T'$ weighs **less** than $T$.
- That contradicts $T$ being minimum. ∎

### The same idea, in terms of cuts and safe edges

The textbook says it slightly more generally:

- A **cut** $(S, V - S)$ of $G$ is a partition of $V$ into two parts.
- An edge $(u, v)$ **crosses** the cut if one endpoint is in $S$ and the other is in $V - S$.
- A cut **respects** a set $A$ of edges if no edge in $A$ crosses it.
- An edge is a **light edge** crossing a cut if its weight is the minimum of all the edges crossing the cut.
- If $A$ is a subset of some MST, an edge $(u, v)$ is **safe** for $A$ if $A \cup \{(u, v)\}$ is still a subset of some MST.

<Callout tone="sky" label="Theorem (safe edges)">
Let $A$ be a subset of $E$ that's included in some MST of $G$, and let $(S, V - S)$ be any cut of $G$ that respects $A$. If $(u, v)$ is a **light edge** crossing $(S, V - S)$, then $(u, v)$ is **safe** for $A$.
</Callout>

**Proof.** Let $T$ be an MST that includes $A$.

- If $(u, v) \in T$, then it's safe for $A$.
- If not, then $T$'s path from $u$ to $v$ contains an edge $(x, y)$ that crosses the cut, and $T \cup \{(u, v)\}$ has a cycle.
- Build $T' = T - \{(x, y)\} \cup \{(u, v)\}$. It's a spanning tree that includes $A$.
- $w(T') = w(T) - w(x, y) + w(u, v)$. Since $(u, v)$ is a light edge, $w(u, v) \le w(x, y)$, so $w(T') \le w(T)$.
- $T$ is minimum, so $w(T') = w(T)$, and $T'$ is also an MST. So $(u, v)$ is safe for $A$. ∎

**Corollary.** If $C$ is one connected component (tree) of the forest $G_A = (V, A)$, and $(u, v)$ is a light edge connecting $C$ to another tree of $G_A$, then $(u, v)$ is safe for $A$. (Use the cut $(V_C, V - V_C)$: it respects $A$, and $(u, v)$ is a light edge for it.)

Both algorithms below are just two ways of picking light edges.

## Prim's algorithm

Prim's algorithm keeps the edges in $A$ as **one single tree**. The tree starts from any root you like and grows until it spans all the vertices. At each step it adds a **light edge** connecting the tree to a vertex not yet in it.

**Idea:** maintain $V - A$ as a **priority queue** $Q$. Key each vertex in $Q$ with the weight of the least-weight edge connecting it to a vertex in $A$.

```text
Q ← V
key[v] ← ∞ for all v ∈ V
key[s] ← 0 for some arbitrary s ∈ V
while Q ≠ ∅
    do u ← EXTRACT-MIN(Q)
       for each v ∈ Adj[u]
           do if v ∈ Q and w(u, v) < key[v]
               then key[v] ← w(u, v)        ⊳ DECREASE-KEY
                    π[v] ← u
```

At the end, $\{(v, \pi[v])\}$ forms the MST.

Here is the lecture's example graph, with its eight vertices named a to h. Prim starts at f (the vertex the lecture gives key 0). Each step adds the cheapest edge leaving the tree: f–c (7), c–b (5), b–a (6), b–h (8), h–e (3), c–d (9), and last f–g (15). The total is **53**.

### Analysis of Prim

- Building $Q$ and setting the keys: $\Theta(V)$.
- The `while` loop runs $|V|$ times, and each time does one EXTRACT-MIN.
- The `for` loop runs $degree(u)$ times for each $u$. By the handshaking lemma, that's $\Theta(E)$ implicit DECREASE-KEYs in total.

$$
\text{Time} = \Theta(V) \cdot T_{\text{EXTRACT-MIN}} + \Theta(E) \cdot T_{\text{DECREASE-KEY}}
$$

| $Q$ | $T_{\text{EXTRACT-MIN}}$ | $T_{\text{DECREASE-KEY}}$ | Total |
| --- | --- | --- | --- |
| array | $O(V)$ | $O(1)$ | $O(V^2)$ |
| binary heap | $O(\lg V)$ | $O(\lg V)$ | $O(E \lg V)$ |
| Fibonacci heap | $O(\lg V)$ amortized | $O(1)$ amortized | $O(E + V \lg V)$ worst case |

## Kruskal's algorithm

Kruskal's algorithm builds a **forest** of trees and keeps joining them:

- Start with every vertex as its own tiny tree.
- Repeatedly **connect two trees**, always choosing the **least-weight** edge that does so, until all the nodes are covered.

If $C_1$ and $C_2$ are the two trees joined by $(u, v)$, then $(u, v)$ is a light edge connecting $C_1$ to some other tree. So by the corollary it's **safe**. Kruskal's is a greedy algorithm because at each step it adds the edge of **least possible weight**.

```text
MST-KRUSKAL(G, w)
    A = ∅
    for each vertex v in V[G]
        do MAKE-SET(v)
    sort the edges of E in nondecreasing order by weight w
    for each edge (u, v) in E, taken in nondecreasing order by weight
        do if FIND-SET(u) ≠ FIND-SET(v)     ⊳ u and v are in different trees
            then A = A ∪ {(u, v)}
                 UNION(u, v)
    return A
```

It uses the **disjoint-set** ([union-find](/courses/data-structures/union-find#a-forest-in-an-array)) data structure to tell whether two vertices are already in the same tree.

On the same graph, Kruskal takes the edges in order of weight: e–h (3), b–c (5), a–b (6), c–f (7), b–h (8), c–d (9). It skips f–h (10), a–c (12) and b–e (14), because each would close a cycle, and finishes with f–g (15). It ends with the same tree, total 53, but builds it in a different order.

<Callout tone="orange" label="Two usual slips">
- **Prim: taking the cheapest edge anywhere.** Prim only looks at edges with **one end in the tree**. In the example, $e$–$h$ (3) is the cheapest edge in the whole graph, but Prim from $f$ can't take it until $h$ is in the tree. It takes $f$–$c$ (7) first. Taking cheap edges anywhere is Kruskal's rule, and then you need a cycle check.
- **Kruskal: skipping the cycle check.** After $e$–$h$, $b$–$c$, $a$–$b$, $c$–$f$ and $b$–$h$, the next edge is $f$–$h$ (10). Both ends are already in the same tree ($f$–$c$–$b$–$h$), so adding it would close a cycle. Without the FIND-SET test it gets added, and the result isn't a tree.
</Callout>

**What if two edges have the same weight?** Then the MST may not be **unique**: two different trees can have the same total. Prim and Kruskal still find *a* minimum spanning tree; they just may pick different ones, depending on how ties are broken.

### Analysis of Kruskal

$$
T(n) = \underbrace{O(1)}_{A = \emptyset} + \underbrace{O(V)}_{\text{MAKE-SET}} + \underbrace{O(E \lg E)}_{\text{sorting}} + \underbrace{O(E \lg V)}_{\text{FIND / UNION}}
$$

So Kruskal is $O(E \lg E)$. You could also say $O(E \lg V)$, because $E \le V^2$, so $\lg E \le 2 \lg V$.

## MST algorithms, summed up

- **Prim's:** $O(E \lg V)$ with a binary heap.
- **Kruskal's:** uses the disjoint-set data structure, and runs in $O(E \lg V)$.
- **Best to date:** a randomized algorithm (Karger, Klein and Tarjan, 1993) runs in $O(V + E)$ **expected** time.

### Part 2: Final exam questions

**1.** *(Finals 2018, and an exam-examples sheet)* Find the MST with Prim's algorithm (from the start node $A$) and with Kruskal's algorithm. Name the nodes $A$ to $H$: $A$ top-left (start), $B$ top-middle, $C$ the inner node on the left, $D$ bottom-left, $E$ bottom-middle, $F$ top-right, $G$ the inner node on the right, $H$ bottom-right. Edges: A–B 12, A–C 2, A–D 5, B–C 9, C–D 8, C–E 7, B–E 3, D–E 1, B–F 8, B–G 1, F–G 9, F–H 11, G–H 5, E–G 3, E–H 10.

<ModelAnswer>
**Prim from A** (always the cheapest edge leaving the tree): A–C (2), A–D (5), D–E (1), E–B (3), B–G (1), G–H (5), B–F (8).

**Kruskal** (edges by weight, skipping any that close a cycle): B–G (1), D–E (1), A–C (2), B–E (3), then E–G (3) is **skipped** because E and G are already joined through B. Then A–D (5), G–H (5), and finally B–F (8). Every later edge would close a cycle.

Both give the same tree, with **total weight 25**. (B–E and E–G tie at 3. Taking E–G first gives a different tree with the same total, so either is accepted.)
</ModelAnswer>
