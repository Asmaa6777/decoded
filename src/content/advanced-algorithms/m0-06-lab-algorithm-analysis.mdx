# Lab: Analyzing Algorithms with Recurrences

This lab practises the skill from the last lesson: **write down the recurrence** for an algorithm, then **solve it**. We'll use two problems, computing a power and sorting, and then a lab task where we need the *exact* number of comparisons, not just the [Big-O](/courses/advanced-algorithms/asymptotic-notation#big-o).

## Part I: Analysis and recurrence relations

### Problem 1: computing $a^b$

We want $a^b$, where $a$ and $b$ are positive integers. The definition gives a recursive algorithm straight away, $a^b = a \cdot a^{b-1}$:

```cpp
long long power(long long a, int b) {
    if (b == 1)
        return a;
    return a * power(a, b - 1);
}
```

That makes $b - 1$ multiplications, which is $\Theta(b)$. Here's a better idea: $a^b = (a^2)^{b/2}$. Square the base and **halve** the exponent.

Watch out when $b$ is odd. $a^{10} = (a^2)^5$ is fine, but $a^5 \ne (a^2)^2 = a^4$. Integer division loses one factor of $a$, so multiply it back in: $a^5 = a \cdot (a^2)^2$.

```cpp
long long fastPower(long long a, int b) {
    if (b == 1)
        return a;
    long long c = a * a;
    long long ans = fastPower(c, b / 2);
    if (b % 2 == 1)
        return a * ans;
    return ans;
}
```

#### Worst-case analysis by counting

Say it takes $k$ halvings to bring $b$ down to 1. Dividing $b$ by 2 a total of $k$ times is the same as dividing by $2^k$:

$$
\frac{b}{2^k} = 1 \;\Longrightarrow\; b = 2^k \;\Longrightarrow\; \log_2 b = \log_2 (2^k) \;\Longrightarrow\; k = \log_2 b
$$

Each level does at most one extra multiplication (when $b$ is odd), so the running time is $f(b) = \log b + 1 = \Theta(\log b)$. That's **constant work per binary digit of $b$**.

#### The same thing with a recurrence

There's one recursive call on $\lfloor b/2 \rfloor$, plus zero or one extra multiplication. In the worst case, assume there's always one:

$$
T(b) = T(\lfloor b/2 \rfloor) + 1 \quad\approx\quad T(b) = T(b/2) + 1
$$

(Dropping the floor doesn't change the answer.) The [master method](/courses/advanced-algorithms/solving-recurrences#four-methods-for-solving-recurrences) gives $T(b) = O(\log b)$.

<Callout tone="violet" label="Two ways to number the master method's cases">
This lab writes the master method with $f(n) = O(n^d)$ and compares $a$ with $b^d$:

| Lab version | Condition | Result | Same as the lecture's |
| --- | --- | --- | --- |
| Case 1 | $a = b^d$ | $O(n^d \log n)$ | Case 2 (a tie) |
| Case 2 | $a < b^d$ | $O(n^d)$ | Case 3 (the root wins) |
| Case 3 | $a > b^d$ | $O(n^{\log_b a})$ | Case 1 (the leaves win) |

It's the same theorem: $a$ vs. $b^d$ is the same comparison as $\log_b a$ vs. $d$. Only the case numbers differ. For $T(b) = T(b/2) + 1$ we have $a = 1$, $b = 2$, $d = 0$, so $a = b^d = 1$: the lab's Case 1, the lecture's Case 2, and the answer is $O(\log b)$ either way.
</Callout>

<Callout tone="orange" label="The usual slip">
Writing `return fastPower(a, b / 2) * fastPower(a, b / 2);` looks the same, but it makes **two** recursive calls for the same number. The recurrence becomes $T(b) = 2T(b/2) + 1$, which is $\Theta(b)$: no faster than the slow version. Compute the half power **once**, store it, and square it (or square the base first, as `fastPower` does).
</Callout>

### Problem 2.1: insertion sort

```text
for j = 2 to A.length
    // ...
    while i > 0 and A[i] > key
        // ...
```

The inner loop is bounded by the outer loop's index. On the $j$-th pass of the outer loop, the inner loop runs at most $j$ times. Adding these up gives an arithmetic series:

$$
1 + 2 + 3 + \dots + n = \frac{n(n+1)}{2}, \qquad f(n) = \tfrac12(n^2 + n) = O(n^2)
$$

**As a recurrence:** sorting $n$ elements costs sorting the first $n - 1$, plus inserting the $n$-th element into place, which is up to $n$ steps:

$$
T(n) = T(n-1) + O(n)
$$

The master method **can't** solve this: the problem shrinks by *subtracting* 1, not by dividing. It also can't solve [recurrences](/courses/advanced-algorithms/solving-recurrences) with different-sized pieces, like $T(n) = 2T(n/4) + T(n/2) + O(n)$.

But **substitution** works well here. Start from $n$ and work backwards. It's like induction in reverse:

$$
\begin{aligned}
t_n &= t_{n-1} + n \\
t_{n-1} &= t_{n-2} + (n-1) \\
t_{n-2} &= t_{n-3} + (n-2) \\
&\;\;\vdots \\
t_2 &= t_1 + 2 \\
t_1 &= 1
\end{aligned}
$$

Plug each line into the one above:

$$
\begin{aligned}
t_n &= t_{n-1} + n \\
    &= t_{n-2} + (n-1) + n \\
    &= t_{n-3} + (n-2) + (n-1) + n \\
    &= t_1 + 2 + \dots + (n-2) + (n-1) + n \\
    &= 1 + 2 + \dots + n = \sum_{i=1}^{n} i = \frac{n(n+1)}{2}
\end{aligned}
$$

<Callout tone="sky" label="Which method when?">
- The recursive term is **$T(n - k)$**: use substitution or iteration.
- The recursive term is **$T(n / k)$**: the master method is the most direct.
- The recursive terms have different sizes: use a recursion tree.
</Callout>

### Problem 2.2: merge sort

Sorting $n$ elements means sorting two halves of size $n/2$, then spending $n$ operations merging them:

$$
T(n) = 2T(n/2) + O(n)
$$

Here $a = 2$, $b = 2$, $d = 1$, so $a = b^d$. That's the tie case (the lab's Case 1, the lecture's Case 2), and the answer is **$O(n \log n)$**.

With a recursion tree: there are $\log n$ levels, and each does at most $n$ operations, so $n \log n$ in total. The recursion tree is the more powerful method, because it also works on recurrences the master method can't handle.

## Part II: Extra problems

### Problem 1: order by growth rate

Put these in increasing order, so that $g(n)$ comes after $f(n)$ only if $f(n) = O(g(n))$:

$$
\text{a. } n^2 \log n \qquad \text{b. } 2^n \qquad \text{c. } 2^{2^n} \qquad \text{d. } n^{\log n} \qquad \text{e. } n^2
$$

**Answer:** $n^2 \;<\; n^2 \log n \;<\; n^{\log n} \;<\; 2^n \;<\; 2^{2^n}$.

- $n^2 = O(n^2 \log n)$, because you're multiplying by something that grows.
- $n^2 \log n = O(n^{\log n})$. The exponent of $n^{\log n}$ keeps growing, so it soon passes 3, and $n^2 \log n < n^3$.
- $n^{\log n} = O(2^n)$. Both are exponential, but write $n^{\log n}$ as a power of 2: $n^{\log n} = (2^{\log n})^{\log n} = 2^{(\log n)^2}$. Its exponent $(\log n)^2$ grows much more slowly than $n$.
- $2^n = O(2^{2^n})$, because the exponent $2^n$ is itself much bigger than $n$.

A useful trick is to **take logarithms** and compare those. With $\lg$ (base 2), the five functions become $2\lg n$, $2\lg n + \lg\lg n$, $(\lg n)^2$, $n$ and $2^n$, and that order is easy to see.

<Callout tone="orange" label="The usual slip">
$n^{\log n}$ is not $n \log n$. One multiplies by $\log n$; the other raises $n$ to the power $\log n$. At $n = 1024$, $n \lg n = 10{,}240$, while $n^{\lg n} = 1024^{10} = 2^{100}$, a 31-digit number.
</Callout>

### Problem 2: 3-way merge sort

Instead of splitting into halves, split into **thirds**, sort each third, and combine them with a three-way merge. What's the running time?

- The merge still takes linear time: $O(n)$ per level.
- Dividing by 3 each time gives $\log_3 n$ levels.
- **Total:** $O(n \log_3 n)$, which is the same as $O(n \log n)$, since logs of different bases differ only by a constant factor.

As a recurrence, $T(n) = 3T(n/3) + O(n)$: $a = 3 = b^d = 3^1$, the tie case.

### Problem 3: merging $k$ sorted arrays one at a time

You have $k$ sorted arrays, each with $n$ elements. Merge the first two, then merge the third into the result, then the fourth, and so on. How long does this take?

The merges handle $2n$ elements, then $3n$, then $4n$, …, up to $kn$:

$$
2n + 3n + \dots + kn = n\,(2 + 3 + \dots + k) = n\left(\frac{k(k+1)}{2} - 1\right) = \Theta(nk^2)
$$

*Can you do better?* Merge the arrays **in pairs**, like [merge sort](/courses/advanced-algorithms/analysis-of-algorithms#merge-sort-recursion-first) does. There are $\log k$ rounds, and each round touches all $kn$ elements, so it's $O(nk \log k)$.

## Part III: Lab task

**Task:** write an algorithm that finds **both** the smallest and the largest of $n$ numbers. The obvious way, comparing each number with the current min and the current max, uses about $2n$ comparisons. Find a method that uses at most **$1.5n$**, and show the full analysis.

### Algorithm 1: pairs first

```text
for i in 0 to n/2 − 1:                 # n/2 comparisons
    if x[2i] > x[2i+1]:
        swap(x, 2i, 2i+1)
global_min = min(x[0], x[2], x[4], …)  # n/2 − 1 comparisons
global_max = max(x[1], x[3], x[5], …)  # n/2 − 1 comparisons
```

After the first loop, each pair is ordered small-then-big. The overall minimum must be one of the **small** ones and the overall maximum one of the **big** ones, so each half only has to be searched once. Finding the minimum of $n/2$ numbers takes $n/2 - 1$ comparisons (the first one is free), so the lab's "n/2" on those two lines is rounded up.

$$
\frac{n}{2} + \left(\frac{n}{2} - 1\right) + \left(\frac{n}{2} - 1\right) = 1.5n - 2
$$

Step through it on the lab's 16 numbers:

<MinMaxVisualizer input={[11, 3, 5, 7, 1, 9, 5, 2, 0, 8, 10, 13, 21, 5, 4, 1]} />

**What if $n$ is odd?** One number has no partner. Pair up the other $n - 1$. Then the leftover number joins both searches: it's compared with the smallest of the small ones, and with the largest of the big ones. That's $\frac{n-1}{2}$ pair comparisons plus $\frac{n-1}{2}$ for the minimum and $\frac{n-1}{2}$ for the maximum, $\frac{3(n-1)}{2}$ in all. For $n = 5$: 2 + 2 + 2 = 6. Forgetting the leftover number is the usual bug: the loop `for i in 0 to n/2 − 1` skips the last element.

### Algorithm 2: merge the pairs

1. Make ordered pairs by comparing each two neighbours, as before.
2. Merge neighbouring pairs, like merge sort, but compare **only the first elements** (the mins) and **only the last elements** (the maxes) of the two pieces. Swap as needed, so the min of the merged piece sits at its front and the max at its back.
3. Keep merging until the whole array is one piece. The min is then the first element and the max is the last.

Here it is on the lab's 16 numbers. Each round merges pieces twice as long, and each merge makes 2 comparisons: front against front, back against back.

| Round | Array after the round | Comparisons |
| --- | --- | ---: |
| start | `11 3 · 5 7 · 1 9 · 5 2 · 0 8 · 10 13 · 21 5 · 4 1` | |
| step 1: order each pair | `3 11 · 5 7 · 1 9 · 2 5 · 0 8 · 10 13 · 5 21 · 1 4` | 8 |
| merge into 4s | `3 7 5 11 · 1 5 2 9 · 0 8 10 13 · 1 4 5 21` | 4 × 2 = 8 |
| merge into 8s | `1 7 5 9 3 5 2 11 · 0 8 10 13 1 4 5 21` | 2 × 2 = 4 |
| merge into 16 | `0 7 5 9 3 5 2 11 1 8 10 13 1 4 5 21` | 1 × 2 = 2 |

Take the merge into 8s on the left half. The fronts are 3 and 1, and 1 is smaller, so they swap. The backs are 11 and 9, and 11 is bigger, so they swap too. Only the two ends matter; the middle numbers are never sorted.

The minimum 0 ends at index 0 and the maximum 21 at index 15, after $8 + 8 + 4 + 2 = 22$ comparisons, which is exactly $1.5 \times 16 - 2$.

Step through the same run. The bright window is the piece being merged; only its two ends are compared:

<Callout tone="sky" label="If you're checking against the lab sheet">
The sheet's last row starts again from the row before the merge into 8s, and gets `0 7 5 11 1 5 2 9 3 8 …`. The minimum and maximum come out the same, but the middle doesn't match a real run. The table above is the run done step by step.
</Callout>

**Analysis.** Unlike merge sort, the work per level isn't the same. The top level (the final merge) does 2 comparisons, the level below does 4, then 8, and so on down to $n/2$ comparisons at the bottom:

$$
2 + 4 + 8 + \dots + \frac{n}{2} = \left(1 + 2 + 4 + \dots + \frac{n}{2}\right) - 1
$$

A full binary tree with $k$ leaves has exactly $2k - 1$ nodes, which means $1 + 2 + 4 + \dots + k = 2k - 1$. With $k = n/2$, the bracket is $n - 1$, so the merging takes $n - 2$ comparisons. Add the $n/2$ from step 1:

$$
(n - 2) + \frac{n}{2} = 1.5n - 2
$$

The recurrence is $T(n) = 2T(n/2) + 2$: two halves, then 2 comparisons to combine their mins and maxes. The master method says $O(n)$, but it **can't give the exact constant** 1.5. That's why we counted by hand.

## Practice from past exams

### Part 1: Midterm questions

**1.** *(Midterms 2021, 2022)* How would you compute $p^k$ as fast as possible, where $k$ is a non-negative integer? What is the complexity?

<ModelAnswer>
Use divide and conquer, as in `fastPower`: $p^k = (p^{k/2})^2$ when $k$ is even, and $p \cdot (p^{(k-1)/2})^2$ when $k$ is odd. Compute the half power **once** and square it.

$$
T(k) = T(k/2) + \Theta(1) \;\Longrightarrow\; T(k) = \Theta(\lg k)
$$

(Master method: $a = 1$, $b = 2$, $f(k) = 1 = \Theta(k^{\log_2 1})$, Case 2.)
</ModelAnswer>

**2.** *(Midterm 2017; also a final)* You have $k$ sorted arrays of $n$ elements each. Merge the first two, then merge the third into the result, then the fourth, and so on. What is the running time, as a function of $k$ and $n$?

<ModelAnswer>
The merges handle $2n$, then $3n$, and so on up to $kn$ elements:

$$
2n + 3n + \dots + kn = n\left(\frac{k(k+1)}{2} - 1\right) = \Theta(nk^2)
$$

(Merging in pairs, like merge sort, would be $\Theta(nk \lg k)$.)
</ModelAnswer>

**3.** *(Midterms 2017, 2018)* A **unimodal** array of $n$ distinct elements increases up to its maximum, then decreases. Give an $O(\log n)$ algorithm to find the maximum.

<ModelAnswer>
[Binary search](/courses/algorithm-design-and-analysis/linear-and-binary-search#binary-search-throw-away-half) on the **slope**. Look at the middle element and its right neighbour:

- if $A[mid] < A[mid + 1]$, we're still going up, so the maximum is to the right: search $A[mid+1 \dots r]$;
- otherwise we're going down (or at the peak), so the maximum is at $mid$ or to its left: search $A[l \dots mid]$.

Stop when $l = r$; that's the maximum. Each step halves the range: $T(n) = T(n/2) + O(1) = O(\log n)$.
</ModelAnswer>

**4.** *(Midterm 2022)* $A[1 \dots n]$ holds distinct integers in increasing order. Decide whether there is an index $i$ with $A[i] = i$.

<ModelAnswer>
Binary search again. Look at $A[mid]$:

- if $A[mid] = mid$, you're done;
- if $A[mid] > mid$, the answer can only be to the **left**. The integers are distinct and increasing, so each step right raises $A[j]$ by at least 1, just as it raises $j$ by 1. So $A[j] > j$ stays true from here on;
- if $A[mid] < mid$, by the same argument the answer can only be to the right.

$O(\log n)$ time.
</ModelAnswer>

### Part 2: Final exam questions

**5.** *(Final 2019)* Write a recursive function that computes $a^b$ for positive integers $a$ and $b$, and find its complexity with the master method.

<ModelAnswer>
```cpp
long long power(long long a, int b) {
    if (b == 1) return a;
    long long half = power(a, b / 2);   // computed once
    return (b % 2 == 0) ? half * half : half * half * a;
}
```

One recursive call on $b/2$, plus constant work: $T(b) = T(b/2) + 1$. Master method: $a = 1$, $b = 2$, $f(b) = 1 = \Theta(b^0)$, Case 2, so $T(b) = \Theta(\lg b)$.
</ModelAnswer>

**6.** *(Final 2019)* Write an algorithm that finds both the smallest and the largest of $n$ numbers with fewer than $2n$ comparisons.

<ModelAnswer>
Use Algorithm 1 from this lab. Compare the numbers in pairs ($\frac n2$ comparisons), then find the minimum among the smaller ones and the maximum among the bigger ones ($\frac n2 - 1$ each). The total is $1.5n - 2$. For odd $n$, the leftover number joins both searches: $\frac{3(n-1)}{2}$.
</ModelAnswer>

**7.** *(Final 2018, and an exam-examples sheet)* Merge sort that splits into **thirds**, sorts each third, and merges them with a three-way merge. What is its running time?

<ModelAnswer>
The three-way merge still takes $O(n)$, and splitting into thirds gives $\log_3 n$ levels: $T(n) = 3T(n/3) + O(n) = O(n \log_3 n) = O(n \log n)$. The base of the log is only a constant factor.
</ModelAnswer>
