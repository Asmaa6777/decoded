# Balanced Search Trees and Red-Black Trees

An ordinary [binary search tree](/courses/data-structures/binary-search-trees#the-ordering-rule) (BST) is fast only when it's **bushy**. Insert keys in sorted order and it degrades into a long chain of height $n$, so every operation becomes $O(n)$. You saw this already with BST buckets in the [hashing](/courses/advanced-algorithms/hashing) lessons.

A **balanced search tree** is a search-tree data structure that *guarantees* a height of $O(\lg n)$ for a dynamic set of $n$ items, whatever order they arrive in. Examples:

- AVL trees,
- 2-3 trees,
- 2-3-4 trees,
- B-trees,
- **red-black trees**: the subject of this lesson and the next.

## Red-black trees

A red-black tree is a BST with **one extra bit per node**: its **color**, red or black. The colors must follow four rules.

<Callout tone="violet" label="Red-black properties">
1. Every node is either **red** or **black**.
2. The **root** and the **leaves** (the NIL pointers) are **black**.
3. If a node is **red**, then its **parent is black**. In other words, there are never two reds in a row on a path.
4. All simple paths from any node $x$ down to a descendant leaf contain the **same number of black nodes**. That number is the **black-height** of $x$, written $bh(x)$.
</Callout>

Some books list five properties: they split property 2 into "every leaf (NIL) is black" and "the root is black". Note that NIL leaves count as real (black) leaves, so every key-holding node has **two** children.

Here's the example from the lecture. Turn on the NIL leaves to check property 4: from the root, every path down to a NIL passes through the same number of black nodes. That number is 2, if you count the NIL at the end but not the root itself: for example 7 → 3 → NIL, or 7 → 18 → 10 → 8 → NIL.

<RBTreeVisualizer start={[7, 3, 18, 10, 22, 8, 11, 26]} />

**Black-height** counts the black nodes on a path from a node down to a leaf, not counting the node itself but counting the NIL leaf. A NIL leaf itself has $bh = 0$.

**What's the minimum black-height of a node with height $h$?** Red nodes can never be next to each other (property 3). So at least half the nodes on any path down are black. A node of height $h$ therefore has **black-height $\ge h/2$**.

## The height of a red-black tree

<Callout tone="mint" label="Theorem">
A red-black tree with $n$ keys has height

$$
h \le 2 \lg(n + 1)
$$
</Callout>

**Intuition: merge the red nodes into their black parents.** Each red node gets absorbed into the black node above it. What's left is a tree where:

- each node has **2, 3 or 4 children** (a black node plus up to two absorbed red children), so it's a **2-3-4 tree**,
- all the leaves are at the **same depth** $h'$, because of property 4.

Now:

- $h' \ge h/2$, because at most half the nodes on any path are red, and the red ones disappear.
- The number of leaves in both trees is $n + 1$ (a binary tree with $n$ keys has $n + 1$ NIL leaves).
- A tree where every node has at least 2 children and all leaves are at depth $h'$ has at least $2^{h'}$ leaves.

$$
n + 1 \ge 2^{h'} \;\Longrightarrow\; \lg(n + 1) \ge h' \ge h/2 \;\Longrightarrow\; h \le 2\lg(n + 1)
$$

**The induction proof** (as in the textbook). First show by induction on the height of $x$ that **the subtree rooted at any node $x$ contains at least $2^{bh(x)} - 1$ internal nodes** (nodes that hold keys).

- **Base:** if $x$ is a NIL leaf, $bh(x) = 0$ and the subtree has $2^0 - 1 = 0$ internal nodes. ✓
- **Step:** if $x$ holds a key, it has two children. Each child has black-height $bh(x)$ if it's red, or $bh(x) - 1$ if it's black, so at least $bh(x) - 1$ either way. By the hypothesis each child's subtree has at least $2^{bh(x)-1} - 1$ internal nodes. Add both children and $x$ itself:

$$
2\left(2^{bh(x)-1} - 1\right) + 1 = 2^{bh(x)} - 1 \;✓
$$

Then, at the root:

$$
\begin{aligned}
n &\ge 2^{bh(\text{root})} - 1 \\
n &\ge 2^{h/2} - 1 && \text{since } bh(\text{root}) \ge h/2 \\
\lg(n + 1) &\ge h/2 \\
h &\le 2\lg(n + 1)
\end{aligned}
$$

So $h = O(\lg n)$.

<Callout tone="orange" label="The usual slip">
"Balanced" doesn't mean every path has the same length. A red-black tree only promises that no path is more than **twice** as long as another. The shortest path can be all black, and the longest can alternate black, red, black, red. Check the example above: 7 → 3 → NIL is 2 steps, while 7 → 18 → 10 → 8 → NIL is 4. Both pass the same number of black nodes, so both are allowed.
</Callout>

## Query operations

Since the height is $O(\lg n)$, the usual BST queries all run in **$O(\lg n)$** time on a red-black tree with $n$ nodes:

- SEARCH,
- MINIMUM and MAXIMUM,
- SUCCESSOR and PREDECESSOR.

## Modifying operations

INSERT and DELETE also take $O(\lg n)$ time, but they need special care because they **change** the tree. The changes are:

- the operation itself (an ordinary BST insert or delete),
- **color changes**,
- restructuring the links of the tree with **rotations**.

## Rotations

A rotation is a small local change of structure that keeps the BST order:

<RotationDemo />

Rotations **keep the in-order ordering of the keys**. If $a \in \alpha$, $b \in \beta$ and $c \in \gamma$, then before and after the rotation

$$
a \le A \le b \le B \le c
$$

Only the subtree $\beta$ changes parent: it moves from $A$'s right side to $B$'s left side (or back). $\alpha$ and $\gamma$ stay attached to the same nodes.

**What does the code for a rotation actually do?** A lot of pointer manipulation! For `leftRotate(x)`, with $z$ the right child of $x$:

- $x$ keeps its left child,
- $z$ keeps its right child,
- $z$'s left child becomes $x$'s right child,
- the parents of $x$ and $z$ change.

```cpp
// returns the new root; requires x->right != nullptr
Node* leftRotate(Node* root, Node* x) {
    Node* z = x->right;
    x->right = z->left;                    // z's left subtree (beta) moves to x
    if (z->left != nullptr)
        z->left->parent = x;
    z->parent = x->parent;                 // z takes x's place
    if (x->parent == nullptr)              // x was the root
        root = z;
    else if (x == x->parent->left)
        x->parent->left = z;
    else
        x->parent->right = z;
    z->left = x;                           // move x down
    x->parent = z;
    return root;
}
```

`rightRotate` is the mirror image: swap every `left` and `right`.

<Callout tone="orange" label="Watch the root update">
Only set `root = z` when $x$ **was** the root. Some printed versions of this code (in Java) run `root = z;` after the `if`, on every call. Then rotating any node deep in the tree would make that node the new root of the whole tree. The rest of the tree would be lost.
</Callout>

**What is the running time?** A fixed number of pointer changes, whatever the size of the tree: **$O(1)$**.

<ApplicationsGrid>
  <PracticalApplication title="Ordered maps and sets" tool="std::map · std::set · TreeMap">
    C++'s `std::map` and `std::set`, and Java's `TreeMap` and `TreeSet`, are red-black trees. That's why they guarantee $O(\log n)$ and iterate in sorted order.
  </PracticalApplication>
  <PracticalApplication title="The Linux kernel" tool="CFS SCHEDULER · MEMORY MAPS">
    Linux's [scheduler](/courses/operating-systems/cpu-scheduling-basics#the-cpu-scheduler) keeps runnable tasks in a red-black tree ordered by how much CPU time they've had, so "pick the task that has run the least" is just "take the leftmost node".
  </PracticalApplication>
</ApplicationsGrid>

## Practice from past exams

### Part 1: Midterm questions

**1.** *(Midterms 2019, 2020, and an undated one)* What are the properties of a red-black tree? How do you find the maximum of the tree and the predecessor of any key? Write pseudocode for both.

<ModelAnswer>
**Properties:** every node is red or black; the root and the NIL leaves are black; a red node's children are black; every path from a node down to a NIL leaf has the same number of black nodes. Together they keep the height at most $2\lg(n + 1)$.

**Maximum:** keep going right.

```text
TREE-MAXIMUM(x)
    while x.right ≠ NIL
        x ← x.right
    return x
```

**Predecessor:** if $x$ has a left subtree, the predecessor is the maximum of that subtree. If not, go up until you arrive from a **right** child; that parent is the predecessor.

```text
PREDECESSOR(x)
    if x.left ≠ NIL
        return TREE-MAXIMUM(x.left)
    y ← x.p
    while y ≠ NIL and x = y.left
        x ← y
        y ← y.p
    return y
```

Both follow one path, so they take $O(h) = O(\lg n)$. (The 2019 answer sheet gives only the first case of PREDECESSOR. A node with no left child still has a predecessor, unless it's the smallest key.)
</ModelAnswer>

**2.** *(Midterm 2025)* Prove that a red-black tree with $n$ keys has height $h \le 2\lg(n + 1)$.

<ModelAnswer>
First, by induction on height, the subtree rooted at any node $x$ has at least $2^{bh(x)} - 1$ internal nodes:

- **Base:** a NIL leaf has $bh = 0$ and $2^0 - 1 = 0$ internal nodes.
- **Step:** each child of $x$ has black-height at least $bh(x) - 1$, so it holds at least $2^{bh(x)-1} - 1$ internal nodes. Two children plus $x$ give at least $2(2^{bh(x)-1} - 1) + 1 = 2^{bh(x)} - 1$.

On any path from the root down, at least half the nodes are black (no two reds in a row), so $bh(\text{root}) \ge h/2$. Then:

$$
n \ge 2^{bh(\text{root})} - 1 \ge 2^{h/2} - 1 \;\Longrightarrow\; \lg(n + 1) \ge h/2 \;\Longrightarrow\; h \le 2\lg(n + 1)
$$
</ModelAnswer>
