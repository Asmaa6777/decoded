# Dynamic Programming

**Dynamic programming** (DP) is a general technique for designing algorithms. It was invented by the American mathematician **Richard Bellman** in the 1950s to solve **optimization** problems. "Programming" here means **planning** (filling in a table), not writing code.

<Callout tone="violet" label="The main idea">
1. Set up a **recurrence** that relates the solution of a larger instance to solutions of some **smaller instances**.
2. Solve each smaller instance **once**.
3. **Record** the solutions in a **table**.
4. **Extract** the solution to the original instance from that table.
</Callout>

Divide and conquer also splits a problem into smaller ones. The difference is that DP's subproblems **overlap**: the same small instance is needed again and again. Saving each answer in a table means it's never computed twice.

## Example: Fibonacci numbers

$$
f(0) = 0, \qquad f(1) = 1, \qquad f(n) = f(n-1) + f(n-2)
$$

**Top-down (recursively):** $f(n)$ calls $f(n-1)$ and $f(n-2)$. Then $f(n-1)$ calls $f(n-2)$ *again*, plus $f(n-3)$, and so on. The same values are recomputed an exponential number of times.

**Bottom-up (iteratively):** fill a table from the smallest instance up, so each value is computed once:

$$
f(0) = 0,\; f(1) = 1,\; f(2) = 0 + 1 = 1,\; f(3) = 1 + 1 = 2,\; f(4) = 1 + 2 = 3,\; f(5) = 2 + 3 = 5,\; \dots,\; f(n) = f(n-1) + f(n-2)
$$

## Examples of dynamic programming algorithms

- the coin-row problem,
- computing binomial coefficients,
- coin collection by a robot,
- the longest common subsequence (LCS),
- some instances of difficult discrete optimization problems, like the **0-1 knapsack** problem.

## The coin-row problem

There's a row of $n$ coins whose values are positive integers $c_1, c_2, \dots, c_n$, not necessarily all different. The goal is to pick up the **maximum amount of money**, with the rule that **no two coins next to each other** in the row can both be picked up.

**Example:** for `5, 1, 2, 10, 6, 2`, the best selection is 5, 10, 2, giving the maximum amount of **17**.

### The DP solution

Let $F(n)$ be the maximum amount that can be picked up from the first $n$ coins. To find a recurrence, split all the allowed selections into two groups:

- **those without the last coin**: the best of these is $F(n-1)$,
- **those with the last coin**: then coin $n-1$ can't be taken, so the best is $c_n + F(n-2)$.

$$
F(n) = \max\{\, c_n + F(n-2),\; F(n-1) \,\} \quad \text{for } n > 1, \qquad F(0) = 0, \quad F(1) = c_1
$$

| | |
| --- | --- |
| **Max amount** | $F(6) = 17$ |
| **Coins of the optimal solution** | $c_1, c_4, c_6$, found by backtracing: at each $i$, did we take coin $i$? |
| **Time efficiency** | $\Theta(n)$ |
| **Space efficiency** | $\Theta(n)$ |

**Note:** all the smaller instances were solved along the way. $F(i)$ is the answer for the first $i$ coins, for every $i$.

## Computing a binomial coefficient

Binomial coefficients are the coefficients of the binomial formula:

$$
(a + b)^n = C(n, 0)\,a^n b^0 + \dots + C(n, k)\,a^{n-k} b^k + \dots + C(n, n)\,a^0 b^n
$$

$C(n, k)$ is also the number of ways to choose $k$ elements from an $n$-element set ($0 \le k \le n$).

**Recurrence.** Split the $k$-element subsets into two groups:

- **those without the last element**: there are $C(n-1, k)$ of these,
- **those with the last element**: choose the other $k-1$ from the first $n-1$, so $C(n-1, k-1)$.

$$
C(n, k) = C(n-1, k) + C(n-1, k-1) \quad \text{for } n > k > 0, \qquad C(n, 0) = 1, \quad C(n, n) = 1
$$

The value of $C(n, k)$ can be computed by filling a table **row by row**. Each cell needs only the cell above it and the one above-left: this is **Pascal's triangle**.

**Time efficiency:** $\Theta(nk)$. **Space efficiency:** $\Theta(nk)$.

## Coin collection by a robot

Several coins are placed in cells of an $n \times m$ board. A robot starts in the **upper-left** cell and needs to collect as many coins as possible on its way to the **bottom-right** cell. On each step, the robot can move **one cell to the right or one cell down**.

Let $F(i, j)$ be the largest number of coins the robot can collect on its way to cell $(i, j)$. It can only arrive **from above**, $(i-1, j)$, or **from the left**, $(i, j-1)$:

$$
F(i, j) = \max\{\, F(i-1, j),\; F(i, j-1) \,\} + c_{ij}
$$

where $c_{ij} = 1$ if there's a coin in cell $(i, j)$ and 0 otherwise, and $F(0, j) = F(i, 0) = 0$ outside the board. The green dots mark the coins:

**Time efficiency:** $\Theta(nm)$. **Space efficiency:** $\Theta(nm)$.

## Longest common subsequence (LCS)

A **subsequence** of a string $S$ is what you get by deleting zero or more symbols from $S$. Some subsequences of "president" are *pred*, *sdn* and *predent*. The letters of a subsequence appear **in order** in $S$, but they don't have to be **consecutive**.

The **longest common subsequence problem** is to find a longest subsequence that two sequences have in common.

- "president" and "providence": the LCS is **priden**.
- "algorithm" and "alignment": one LCS is **algm**. (There can be more than one. The backtrace below finds *algt*, which is just as long.)

### How to compute the LCS

Let $A = a_1 a_2 \dots a_m$ and $B = b_1 b_2 \dots b_n$, and let $len(i, j)$ be the length of an LCS of $a_1 a_2 \dots a_i$ and $b_1 b_2 \dots b_j$. With $len(i, 0) = len(0, j) = 0$:

$$
len(i, j) =
\begin{cases}
len(i-1, j-1) + 1 & \text{if } a_i = b_j \\
\max\{\, len(i-1, j),\; len(i, j-1) \,\} & \text{if } a_i \ne b_j
\end{cases}
$$

- If the last letters **match**, they can end the common subsequence, so extend the diagonal.
- If they **don't**, one of them isn't in the LCS, so drop it and take whichever choice is better.

**What is the corresponding LCS?** The table only stores *lengths*. To get the letters, use the **backtracing algorithm**: start at $len(m, n)$ and walk back. On a match, take the letter and move diagonally. Otherwise move to the neighbour (above or left) that holds the same value.

**Running time and memory:** $O(mn)$ and $O(mn)$.

## The 0-1 knapsack problem

Given $n$ items with

- integer **weights** $w_1, w_2, \dots, w_n$,
- **values** $v_1, v_2, \dots, v_n$,

and a knapsack of **capacity** $W$, find the most valuable subset of the items that fits into the knapsack.

Consider the smaller instance made of the first $i$ items and capacity $j$ (with $j \le W$). Let $V[i, j]$ be the optimal value of that instance. Then

$$
V[i, j] =
\begin{cases}
\max\{\, V[i-1, j],\; v_i + V[i-1, j - w_i] \,\} & \text{if } j - w_i \ge 0 \\
V[i-1, j] & \text{if } j - w_i < 0
\end{cases}
$$

with the initial conditions $V[0, j] = 0$ and $V[i, 0] = 0$. In words: either leave item $i$ out (same value as with $i - 1$ items), or put it in, which uses $w_i$ of the capacity and adds $v_i$.

**Example:** capacity $W = 5$.

| item | weight | value |
| --- | --- | --- |
| 1 | 2 | \$12 |
| 2 | 1 | \$10 |
| 3 | 3 | \$20 |
| 4 | 2 | \$15 |

<KnapsackTable />

**Backtracing** finds the actual optimal subset. Start from the last cell, $V[4, 5] = 37$. If it equals the value **above** it, item 4 is **not** in the knapsack, so go up a row with the same $j$. Otherwise item 4 **is** in, so go up a row to $j - w_4$. Repeat for each row. Here the best subset is items 1, 2 and 4, worth \$37.

```text
Algorithm DPKnapsack(w[1..n], v[1..n], W)
    var V[0..n, 0..W], P[1..n, 1..W]: int
    for j := 0 to W do V[0, j] := 0
    for i := 0 to n do V[i, 0] := 0
    for i := 1 to n do
        for j := 1 to W do
            if w[i] ≤ j and v[i] + V[i−1, j−w[i]] > V[i−1, j] then
                V[i, j] := v[i] + V[i−1, j−w[i]];  P[i, j] := j − w[i]
            else
                V[i, j] := V[i−1, j];  P[i, j] := j
    return V[n, W] and the optimal subset by backtracing
```

**Running time and space:** $O(nW)$.
