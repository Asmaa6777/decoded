# Shortest Paths: Dijkstra's Algorithm

Every map app answers the same question millions of times a second: **what's the cheapest way from here to there?** This lesson defines shortest paths properly. Then it solves the problem with **Dijkstra's algorithm**, a [greedy algorithm](/courses/advanced-algorithms/greedy-algorithms#a-short-list-of-algorithm-types), and proves that it's correct.

## Paths in graphs

Consider a **directed** graph $G = (V, E)$ with an edge-weight function $w : E \to \mathbb{R}$. The **weight** of a path $p = v_1 \to v_2 \to \dots \to v_k$ is the sum of its edge weights:

$$
w(p) = \sum_{i=1}^{k-1} w(v_i, v_{i+1})
$$

**Example:** a path $v_1 \xrightarrow{4} v_2 \xrightarrow{-2} v_3 \xrightarrow{-5} v_4 \xrightarrow{1} v_5$ has weight $w(p) = 4 - 2 - 5 + 1 = -2$. Weights can be negative, like a toll you're *paid* to drive.

## Shortest paths

A **shortest path** from $u$ to $v$ is a path of minimum weight from $u$ to $v$. The **shortest-path weight** from $u$ to $v$ is

$$
\delta(u, v) = \min\{\, w(p) : p \text{ is a path from } u \text{ to } v \,\}
$$

**Note:** $\delta(u, v) = \infty$ if no path from $u$ to $v$ exists.

### Optimal substructure

<Callout tone="violet" label="Theorem">
A subpath of a shortest path is a shortest path.
</Callout>

**Proof (cut and paste).** If some piece of a shortest path could be replaced by a shorter path between the same two vertices, then the whole path would get shorter. That's impossible, because it was already shortest. ∎

### Triangle inequality

<Callout tone="violet" label="Theorem">
For all $u, v, x \in V$:

$$
\delta(u, v) \le \delta(u, x) + \delta(x, v)
$$
</Callout>

**Proof.** Going from $u$ to $x$ by a shortest path, then from $x$ to $v$ by a shortest path, is *one* way to get from $u$ to $v$. The shortest way can't be longer than that. ∎

### Well-definedness of shortest paths

If a graph $G$ contains a **negative-weight cycle**, some shortest paths may not exist. Going round the cycle once more always makes the path cheaper, so there's no minimum.

## Single-source shortest paths

**Problem.** From a given source vertex $s \in V$, find the shortest-path weights $\delta(s, v)$ for **all** $v \in V$.

If all the edge weights $w(u, v)$ are **non-negative**, all the shortest-path weights must exist.

**Idea: greedy.**

1. Maintain a set $S$ of vertices whose shortest-path distances from $s$ are **known**.
2. At each step, add to $S$ the vertex $v \in V - S$ whose **distance estimate** from $s$ is minimal.
3. Update the distance estimates of the vertices adjacent to $v$.

## Dijkstra's algorithm

```text
d[s] ← 0
for each v ∈ V − {s}
    do d[v] ← ∞
S ← ∅
Q ← V                       ⊳ Q is a priority queue maintaining V − S
while Q ≠ ∅
    do u ← EXTRACT-MIN(Q)
       S ← S ∪ {u}
       for each v ∈ Adj[u]
           do if d[v] > d[u] + w(u, v)
               then d[v] ← d[u] + w(u, v)     ⊳ relaxation step
                    π[v] ← u                  ⊳ (implicit DECREASE-KEY)
```

The `if` test is called **relaxing** the edge $(u, v)$: *is going through $u$ a shortcut to $v$?* If yes, lower $v$'s estimate, and remember $u$ as $v$'s **predecessor** $\pi[v]$.

### Example

The lecture's graph has non-negative edge weights. Step through it:

1. **Initialize:** $d[A] = 0$, everything else $\infty$.
2. **"A" ← EXTRACT-MIN(Q).** $S = \{A\}$. Relax all edges leaving A: $d[B] = 10$, $d[C] = 3$.
3. **"C" ← EXTRACT-MIN(Q).** $S = \{A, C\}$. Relax all edges leaving C: $d[B] = 7$, $d[D] = 11$, $d[E] = 5$.
4. **"E" ← EXTRACT-MIN(Q).** $S = \{A, C, E\}$. Relax all edges leaving E: D stays 11.
5. **"B" ← EXTRACT-MIN(Q).** $S = \{A, C, E, B\}$. Relax all edges leaving B: $d[D] = 9$.
6. **"D" ← EXTRACT-MIN(Q).** $S = \{A, C, E, B, D\}$.

## Correctness

### Part I

<Callout tone="sky" label="Lemma">
Initializing $d[s] \leftarrow 0$ and $d[v] \leftarrow \infty$ for all $v \in V - \{s\}$ establishes $d[v] \ge \delta(s, v)$ for all $v \in V$, and this invariant is maintained over **any** sequence of relaxation steps.
</Callout>

The estimates are always **too high or exactly right**, never too low.

**Proof.** Suppose not. Let $v$ be the first vertex for which $d[v] < \delta(s, v)$, and let $u$ be the vertex that caused $d[v]$ to change: $d[v] = d[u] + w(u, v)$. Then

$$
\begin{aligned}
d[v] &< \delta(s, v) && \text{supposition} \\
&\le \delta(s, u) + \delta(u, v) && \text{triangle inequality} \\
&\le \delta(s, u) + w(u, v) && \text{a shortest path} \le \text{this specific path} \\
&\le d[u] + w(u, v) && v \text{ is the first violation}
\end{aligned}
$$

So $d[v] < d[u] + w(u, v)$, which contradicts $d[v] = d[u] + w(u, v)$. ∎

### Part II

<Callout tone="sky" label="Lemma">
Let $u$ be $v$'s predecessor on a shortest path from $s$ to $v$. If $d[u] = \delta(s, u)$ and the edge $(u, v)$ is relaxed, then $d[v] = \delta(s, v)$ after the relaxation.
</Callout>

**Proof.** Observe that $\delta(s, v) = \delta(s, u) + w(u, v)$, by [optimal substructure](/courses/advanced-algorithms/huffman-and-activity-selection#steps-in-designing-a-greedy-algorithm). Suppose $d[v] > \delta(s, v)$ before the relaxation (otherwise we're done). Then the test $d[v] > d[u] + w(u, v)$ succeeds, because

$$
d[v] > \delta(s, v) = \delta(s, u) + w(u, v) = d[u] + w(u, v)
$$

and the algorithm sets $d[v] = d[u] + w(u, v) = \delta(s, v)$. ∎

### Part III

<Callout tone="mint" label="Theorem">
Dijkstra's algorithm terminates with $d[v] = \delta(s, v)$ for all $v \in V$.
</Callout>

**Proof.** It's enough to show that $d[v] = \delta(s, v)$ for every $v \in V$ **at the moment $v$ is added to $S$**, because by Part I, estimates never go below the true distance afterwards.

Suppose $u$ is the **first** vertex added to $S$ with $d[u] > \delta(s, u)$. Let $y$ be the first vertex in $V - S$ along a shortest path from $s$ to $u$. Let $x$ be the vertex just before $y$ on that path; $x$ is in $S$. Look at the moment just before $u$ is added to $S$.

- Since $u$ is the first violation, $d[x] = \delta(s, x)$.
- When $x$ was added to $S$, the edge $(x, y)$ was relaxed, so by Part II, $d[y] = \delta(s, y)$.
- Edge weights are non-negative and $y$ comes before $u$ on a shortest path to $u$, so $\delta(s, y) \le \delta(s, u)$.

$$
d[y] = \delta(s, y) \le \delta(s, u) < d[u]
$$

But $u$ was chosen by EXTRACT-MIN, so $d[u] \le d[y]$. **Contradiction.** ∎

This is exactly where **non-negative weights** are needed. With a negative edge further along the path, $\delta(s, y)$ could be *bigger* than $\delta(s, u)$, and the argument breaks.

<Callout tone="orange" label="The usual slip: negative edges">
Running Dijkstra on a graph with a negative edge. Take $A \xrightarrow{1} B$, $A \xrightarrow{3} C$, $C \xrightarrow{-3} B$, $B \xrightarrow{1} D$. Dijkstra finishes $B$ at 1, then $D$ at 2, and only then looks at $C$. The edge $C \to B$ lowers $d[B]$ to 0, but $D$ has already been finished and is never fixed. It reports $d[D] = 2$, while the real shortest path $A \to C \to B \to D$ costs $3 - 3 + 1 = 1$. With negative edges, use the Bellman–Ford algorithm instead.
</Callout>

## Analysis of Dijkstra

- The `while` loop runs $|V|$ times, each with one EXTRACT-MIN.
- The `for` loop runs $degree(u)$ times for each $u$. By the handshaking lemma that's $\Theta(E)$ implicit DECREASE-KEYs.

$$
\text{Time} = \Theta(V) \cdot T_{\text{EXTRACT-MIN}} + \Theta(E) \cdot T_{\text{DECREASE-KEY}}
$$

**Note:** it's the same formula as in the analysis of Prim's MST algorithm, because the two algorithms have the same shape. Only the key is different: the *edge weight* for Prim, and the *path length so far* for Dijkstra.

| $Q$ | $T_{\text{EXTRACT-MIN}}$ | $T_{\text{DECREASE-KEY}}$ | Total |
| --- | --- | --- | --- |
| array | $O(V)$ | $O(1)$ | $O(V^2)$ |
| binary heap | $O(\lg V)$ | $O(\lg V)$ | $O(E \lg V)$ |
| Fibonacci heap | $O(\lg V)$ amortized | $O(1)$ amortized | $O(E + V \lg V)$ worst case |

## Unweighted graphs

Suppose $w(u, v) = 1$ for all $(u, v) \in E$. **Can Dijkstra's algorithm be improved?**

Yes:

- Use a simple **FIFO queue** instead of a [priority queue](/courses/data-structures/heaps#the-interface). Vertices come out in order of distance automatically, because every edge adds exactly 1.
- That's **breadth-first search**:

```text
while Q ≠ ∅
    do u ← DEQUEUE(Q)
       for each v ∈ Adj[u]
           do if d[v] = ∞
               then d[v] ← d[u] + 1
                    ENQUEUE(Q, v)
```

**Analysis:** time $= O(V + E)$.

**The lecture's example** is a *directed* graph on $a$ to $i$, with these edges:

$a \to b,\ a \to d,\ b \to c,\ b \to e,\ d \to b,\ d \to e,\ e \to c,\ e \to g,\ e \to i,\ f \to d,\ f \to h,\ g \to f,\ g \to i,\ h \to g,\ i \to h$

Start at $a$ with $d[a] = 0$. Each vertex that comes off the queue gives distance $d[u] + 1$ to every neighbour still at $\infty$:

| dequeue $u$ | new vertices, with $d$ | queue afterwards |
| --- | --- | --- |
| | $a = 0$ | `a` |
| $a$ (0) | $b = 1$, $d = 1$ | `b d` |
| $b$ (1) | $c = 2$, $e = 2$ | `d c e` |
| $d$ (1) | none: $b$ and $e$ already have a distance | `c e` |
| $c$ (2) | none: $c$ has no outgoing edges | `e` |
| $e$ (2) | $g = 3$, $i = 3$ | `g i` |
| $g$ (3) | $f = 4$ | `i f` |
| $i$ (3) | $h = 4$ | `f h` |
| $f$ (4), $h$ (4) | none | empty |

The vertices come out in the order `a b d c e g i f h`, with distances 0, 1, 1, 2, 2, 3, 3, 4, 4. The distances never go down, exactly as Dijkstra would take them. Note that $f$ is at distance 4 even though the edge $f \to d$ touches $d$: edges only count in their own direction.
