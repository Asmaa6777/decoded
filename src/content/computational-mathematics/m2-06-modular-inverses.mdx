# Modular Inverses

Modular arithmetic has no fractions, so how do you divide? You multiply by an **inverse**: a number $x$ with $a \cdot x \equiv 1 \pmod n$. Every [affine cipher](/courses/computational-mathematics/affine-ciphers) later in this course depends on finding one, and so does every RSA key.

## When an inverse exists

If $\gcd(a, n) = 1$, the equation $a \cdot x \equiv b \pmod n$ has a solution, and it's unique modulo $n$. So $a$ has an inverse exactly when it's [coprime](/courses/computational-mathematics/divisibility-and-euclid#greatest-common-divisor) to $n$. For example, 2 has no inverse modulo 4, because $2x$ is always even and can't equal 1 modulo an even number.

## The extended Euclidean algorithm

The whole method rests on one fact: if $g = \gcd(a, b)$, there are integers $x$ and $y$ with

$$
a x + b y = g
$$

To find them, run [Euclid's algorithm](/courses/computational-mathematics/divisibility-and-euclid#the-euclidean-algorithm) down, and then climb back up. On each row, replace the smaller remainder using the division on that row. The expression stays equal to $g$ the whole way:

<ExtendedEuclidVisualizer />

For $\gcd(130, 61)$ this gives $130 \cdot 23 + 61 \cdot (-49) = 1$. Check it: $2990 - 2989 = 1$.

<CodeTabs>

```matlab
[g, x, y] = gcd(130, 61)    % three outputs: g = 1, x = 23, y = -49
```

```python
def extended_gcd(a, b):
    """Returns g, x, y with a*x + b*y = g."""
    if b == 0:
        return a, 1, 0
    g, x, y = extended_gcd(b, a % b)  # run Euclid down...
    return g, y, x - (a // b) * y     # ...and climb back up

print(extended_gcd(130, 61))  # (1, 23, -49)
```

</CodeTabs>

## From there to the inverse

To solve $17x \equiv 1 \pmod{61}$, find $x$ and $y$ with $17x + 61y = 1$. The algorithm gives:

$$
17 \cdot 18 + 61 \cdot (-5) = 1
$$

Now look at this equation modulo 61. The second term is a multiple of 61, so it vanishes and leaves $17 \cdot 18 \equiv 1 \pmod{61}$. So the inverse of 17 is 18.

MATLAB returns the coefficients if you ask for three outputs from `gcd`:

<CodeTabs>

```matlab
[g, x, y] = gcd(17, 61)    % g = 1, x = 18, y = -5
inverse = mod(x, 61)       % 18
```

```python
# Since Python 3.8, pow finds the inverse directly with an exponent of -1
print(pow(17, -1, 61))  # 18
```

</CodeTabs>

<Callout tone="sky" label="Negative answers are fine">
If $x$ comes out negative, take `mod(x, n)`. For example, if $x = -5$ with $n = 18$, the same inverse is $13$.
</Callout>

Division modulo a prime protects some of the most sensitive training in machine learning. **Federated learning** trains one model across thousands of phones without collecting anyone's data: each phone sends only an update. **Secure aggregation** goes further, so the server learns only the sum of everyone's updates and not any single one. Those protocols must survive phones dropping out midway, and they use **Shamir secret sharing** to do it.

The idea fits in a line. Hide the secret as the value at $x = 0$ of a line, say $f(x) = 23 + 17x$ modulo 97, and hand out points on it as shares. One point says nothing, since infinitely many lines pass through it, but any two pin the line down and give back $f(0)$. Drawing that line means dividing by $x_2 - x_1$, which modulo a prime means multiplying by its inverse:

<CodeTabs>

```matlab
p = 97;
x1 = 1;  y1 = 40;     % two shares: points on f(x) = 23 + 17x mod 97
x2 = 2;  y2 = 57;

[~, d] = gcd(x2 - x1, p);                   % d is the inverse of x2 - x1
secret = mod((y1*x2 - y2*x1) * d, p)

secret =
    23
```

```python
p = 97
(x1, y1), (x2, y2) = (1, 40), (2, 57)  # points on f(x) = 23 + 17x, modulo 97

secret = (y1 * x2 - y2 * x1) * pow(x2 - x1, -1, p) % p
print(secret)  # 23
```

</CodeTabs>
