# Stream Ciphers

Computers store everything as [bits](/courses/computer-organization/bits-and-bytes), so the simplest cipher for them works on one bit at a time. All it takes is [XOR](/courses/logic-design/logic-gates) and a good source of random-looking bits.

## How it works

In a **stream cipher**, the message units are bits. A secret key seeds a random bit generator, which produces a long **key stream** $k$. Each plaintext bit is combined with one key bit using XOR:

$$
c_i = m_i \oplus k_i
$$

XOR gives 1 when two bits differ and 0 when they match. It also undoes itself, which is what makes the scheme work:

$$
(m \oplus k) \oplus k = m
$$

XOR also has a famous place in the history of AI. The earliest neural network, the **perceptron**, decides by drawing one straight line through its inputs, and no straight line can separate XOR's outputs: on the four corners of a square, the 1s sit on one diagonal and the 0s on the other. A 1969 book on perceptrons by Minsky and Papert made that limit famous, and enthusiasm for neural networks cooled for years. The fix is a **hidden layer**. One hidden unit computes OR and another computes AND, and the output says "OR but not AND", which is XOR. That's the whole reason networks need depth and a non-linear step:

<CodeTabs>

```matlab
X = [0 0; 0 1; 1 0; 1 1];          % the four possible inputs
step = @(v) double(v > 0);          % the non-linear step

h = step(X * [1; 1] - 0.5);         % hidden unit 1: OR
g = step(X * [1; 1] - 1.5);         % hidden unit 2: AND
step(h - g - 0.5)'                  % OR but not AND: 0 1 1 0
```

```python
import numpy as np

X = np.array([[0, 0], [0, 1], [1, 0], [1, 1]])  # the four possible inputs
step = lambda v: (v > 0).astype(int)             # the non-linear step

h = step(X @ np.array([1, 1]) - 0.5)  # hidden unit 1: OR
g = step(X @ np.array([1, 1]) - 1.5)  # hidden unit 2: AND
print(step(h - g - 0.5).tolist())  # [0, 1, 1, 0]
```

</CodeTabs>

So decryption is the same operation as encryption, with the same key stream. The receiver just needs the same generator and the same seed. Run it in both directions:

<XorStreamVisualizer />

<CodeTabs>

```matlab
m = [0 1 1 0];  k = [1 1 0 0];
c = xor(m, k)          % 1 0 1 0
xor(c, k)              % 0 1 1 0, the message again

% On real text, bitxor works on whole bytes
key = uint8([90 195]);
cipher = bitxor(uint8('HI'), key);
char(bitxor(cipher, key))     % HI
```

```python
import numpy as np

# XOR is ^ in Python, and it works on whole NumPy arrays
m = np.array([0, 1, 1, 0])
k = np.array([1, 1, 0, 0])
c = m ^ k

print(c.tolist())  # [1, 0, 1, 0]
print((c ^ k).tolist())  # [0, 1, 1, 0]

# On real text, bytes XOR one at a time
key = bytes([0x5A, 0xC3])
cipher = bytes(t ^ s for t, s in zip(b"HI", key))
print(bytes(t ^ s for t, s in zip(cipher, key)))  # b'HI'
```

</CodeTabs>

<Callout tone="orange" label="Never reuse a key stream">
If two messages use the same key stream, an attacker can XOR the ciphertexts. The key cancels, leaving $m_1 \oplus m_2$, which is often enough to recover both messages. WEP, an early Wi-Fi security standard, was broken partly because its key streams repeated.
</Callout>

The generator in this visualizer is a toy, a small linear-feedback [shift register](/courses/logic-design/registers#shift-registers). Its output looks random, but an attacker who sees a little of it can work out the rest, so real systems use far stronger generators.

Machine learning needs random bits too, but of a different kind. Shuffling data and initialising weights need numbers that are fast and statistically even, and ML libraries pick generators built for exactly that. A stream cipher also needs numbers nobody can predict, which is a much stronger demand, so it uses a **cryptographically secure** generator. Swapping one for the other is a classic security bug.

If the key stream is truly random, as long as the message, and never reused, you have the **one-time pad**, which is provably unbreakable. It's rarely practical, because sharing that much key is as hard as sharing the message.
