# Stream Ciphers

Computers store everything as [bits](/courses/computer-organization/bits-and-bytes), so the simplest cipher for them works on one bit at a time. All it takes is [XOR](/courses/logic-design/logic-gates) and a good source of random-looking bits.

## How it works

In a **stream cipher**, the message units are bits. A secret key seeds a random bit generator, which produces a long **key stream** $k$. Each plaintext bit is combined with one key bit using XOR:

$$
c_i = m_i \oplus k_i
$$

XOR gives 1 when two bits differ and 0 when they match. It also undoes itself, which is what makes the scheme work:

$$
(m \oplus k) \oplus k = m
$$

So decryption is the same operation as encryption, with the same key stream. The receiver just needs the same generator and the same seed. Run it in both directions:

<Callout tone="orange" label="Never reuse a key stream">
If two messages use the same key stream, an attacker can XOR the ciphertexts. The key cancels, leaving $m_1 \oplus m_2$, which is often enough to recover both messages. WEP, an early Wi-Fi security standard, was broken partly because its key streams repeated.
</Callout>

The generator in this visualizer is a toy, a small linear-feedback [shift register](/courses/logic-design/registers#shift-registers). Its output looks random, but an attacker who sees a little of it can work out the rest, so real systems use far stronger generators.

If the key stream is truly random, as long as the message, and never reused, you have the **one-time pad**, which is provably unbreakable. It's rarely practical, because sharing that much key is as hard as sharing the message.

## In Python

XOR is `^` in Python, and it works on whole NumPy arrays. The `bytes` type lets you run the cipher on real text:

```python
import numpy as np

m = np.array([0, 1, 1, 0])
k = np.array([1, 1, 0, 0])
c = m ^ k

print(c.tolist())  # [1, 0, 1, 0]
print((c ^ k).tolist())  # [0, 1, 1, 0]

text = b"HI"
key = bytes([0x5A, 0xC3])
cipher = bytes(t ^ s for t, s in zip(text, key))

print(bytes(t ^ s for t, s in zip(cipher, key)))  # b'HI'
```

## In machine learning

XOR has a special place in ML history. A single-layer perceptron draws one straight line through its inputs, and no straight line can separate XOR's outputs. Minsky and Papert's 1969 book on perceptrons discussed this limit. Adding a hidden layer solves it, and this is why networks need depth and non-linearity:

```python
import numpy as np

X = np.array([[0, 0], [0, 1], [1, 0], [1, 1]])
step = lambda v: (v > 0).astype(int)

h = step(X @ np.array([1, 1]) - 0.5)
g = step(X @ np.array([1, 1]) - 1.5)

print(step(h - g - 0.5).tolist())  # [0, 1, 1, 0]
```

Here `h` is OR and `g` is AND, two hidden units, and the output means "OR but not AND", which is XOR.

Random bits matter here as well. Good training needs pseudorandom numbers, but not cryptographic ones: ML libraries choose fast generators with good statistics, while a stream cipher also needs a generator that nobody can predict.
