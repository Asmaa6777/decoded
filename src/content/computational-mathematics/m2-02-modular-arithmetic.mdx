# Modular Arithmetic

You already do modular arithmetic when you work out that 5 hours after 10 o'clock is 3 o'clock. Numbers wrap around once they reach a limit, and that wrapping is what makes cryptography possible.

## The mod operation

$a \bmod n$ is the remainder when $a$ is divided by $n$, and the positive integer $n$ is called the **modulus**:

$$
a = \left\lfloor \frac{a}{n} \right\rfloor \cdot n + (a \bmod n)
$$

So $11 \bmod 7 = 4$ and $-11 \bmod 7 = 3$. Picture a clock with $n$ positions: positive numbers walk clockwise and negative numbers walk the other way.

<ModClock />

<CodeTabs>

```matlab
mod(-28, 81)              % 53
mod(7653, 915)            % 333
mod(4357667512, 565349)   % 522769
mod([-4 -1 7 9], 3)       % 2  2  1  0
mod(1:10, 5)              % 1 2 3 4 0 1 2 3 4 0
```

```python
import numpy as np
import pandas as pd

# Python's % matches MATLAB's mod, negative numbers included
print(-28 % 81)  # 53
print(7653 % 915)  # 333
print(4357667512 % 565349)  # 522769
print(np.mod([-4, -1, 7, 9], 3).tolist())  # [2, 2, 1, 0]
print((np.arange(1, 11) % 5).tolist())  # [1, 2, 3, 4, 0, 1, 2, 3, 4, 0]

# pandas columns work the same way, e.g. wrapping hours past midnight
print((pd.Series([23, 24, 25]) % 24).tolist())  # [23, 0, 1]
```

</CodeTabs>

<Callout tone="orange" label="A trap in other languages">
In C, Java and JavaScript, the `%` operator keeps the sign of the first number, so `-11 % 7` gives `-4`. MATLAB's `mod` and Python's `%` give `3`. This difference is a common source of bugs.
</Callout>

Mod helps machine learning models handle huge numbers of categories. A recommendation system cannot store a separate column for each of a billion user IDs. The **hashing trick** maps each identifier to a number, then reduces that number modulo the count of buckets. Every ID lands in one of, say, 1000 columns. The code below shows a simple string hash. It multiplies the running total by 31 and adds the character code of each letter:

<CodeTabs>

```matlab
s = 'user_42';
% double(s) turns characters into ASCII integer codes (e.g. 'u' -> 117)
h = sum(double(s) .* 31 .^ (numel(s)-1:-1:0));
bucket = mod(h, 1000)

bucket = 794
```

```python
s = "user_42"
h = sum(ord(c) * 31 ** (len(s) - 1 - i) for i, c in enumerate(s))
print(h % 1000)  # 794

# Real systems use a fast stable hash such as zlib.crc32 or MurmurHash.
# Avoid Python's built-in hash() for this: it gives strings different values
# each time the program runs, so a model trained with it breaks on the next run.
```

</CodeTabs>

Two different IDs sometimes share a bucket, and the model tolerates the collision. A [hash table](/courses/advanced-algorithms/hashing) makes the same compromise.

## Congruence

Two integers are **congruent modulo $n$** if they leave the same remainder when divided by $n$, written $a \equiv b \pmod{n}$. They land on the same spot on the clock. For example, $73 \equiv 4 \pmod{23}$ because $73 = 3 \cdot 23 + 4$. Similarly, $21 \equiv -9 \pmod{10}$ because $21 = 2 \cdot 10 + 1$ and $-9 = -1 \cdot 10 + 1$.

Why does having the same remainder match condition 1 below? If $a = q_1 n + r$ and $b = q_2 n + r$, subtracting them yields $a - b = (q_1 - q_2)n$, a multiple of $n$. Conversely, if $a - b = k n$, then $a = b + kn$, so $a$ and $b$ differ by whole circuits around the clock.

Congruence behaves much like equality. Properties 2 to 4 below make it an [equivalence relation](/courses/discrete-mathematics/relations#equivalence-relations), which splits the integers into $n$ classes, one per remainder:

1. $a \equiv b \pmod n$ exactly when $n \mid (a - b)$.
2. $a \equiv a$, for any $n$.
3. If $a \equiv b$ then $b \equiv a$.
4. If $a \equiv b$ and $b \equiv c$, then $a \equiv c$.

The clock representation solves a practical problem in machine learning. Feeding a model the hour of day as a raw number makes 23:00 and 00:00 appear far apart, even though they differ by one hour. The fix places each hour on a circle and gives the model the resulting coordinates $(x, y)$. Hours close on the clock stay close in Euclidean space:

<CodeTabs>

```matlab
hours = [23 0 12];
angle = 2 * pi * hours / 24;
P = [sin(angle') cos(angle')];

norm(P(1,:) - P(2,:))     % 23:00 to 00:00, about 0.26
norm(P(1,:) - P(3,:))     % 23:00 to 12:00, about 1.98
```

```python
import numpy as np

hours = np.array([23, 0, 12])
angle = 2 * np.pi * hours / 24
P = np.column_stack([np.sin(angle), np.cos(angle)])

print(round(np.linalg.norm(P[0] - P[1]), 2))  # 0.26
print(round(np.linalg.norm(P[0] - P[2]), 2))  # 1.98
```

</CodeTabs>

Transformers use a related idea to tell a model where each word sits in a sentence. Their **positional encodings** are sines and cosines at many different speeds, a whole set of clocks, so every position gets its own pattern of angles.

## You can reduce at any time

Addition, subtraction and multiplication all respect the modulus:

$$
\begin{aligned}
(a + b) \bmod n &= (a_n + b_n) \bmod n \\
(a - b) \bmod n &= (a_n - b_n) \bmod n \\
(a \cdot b) \bmod n &= (a_n \cdot b_n) \bmod n
\end{aligned}
$$

where $a_n = a \bmod n$ and $b_n = b \bmod n$. You can reduce numbers midway through a calculation and preserve the result. We verify all three operations with $11 \bmod 8 = 3$ and $15 \bmod 8 = 7$:

- **Addition:** $[(11 \bmod 8) + (15 \bmod 8)] \bmod 8 = (3 + 7) \bmod 8 = 2$. Directly: $(11 + 15) \bmod 8 = 26 \bmod 8 = 2$.
- **Subtraction:** $[(11 \bmod 8) - (15 \bmod 8)] \bmod 8 = (3 - 7) \bmod 8 = 4$. Directly: $(11 - 15) \bmod 8 = -4 \bmod 8 = 4$.
- **Multiplication:** $[(11 \bmod 8) \cdot (15 \bmod 8)] \bmod 8 = (3 \cdot 7) \bmod 8 = 5$. Directly: $(11 \cdot 15) \bmod 8 = 165 \bmod 8 = 5$.

That also makes big powers easy. To find $10^7 \bmod 17$, square repeatedly and reduce remainders along the way:

$$
\begin{aligned}
10^2 &= 100 = 5 \cdot 17 + 15 \\
&\equiv -2 \pmod{17} \quad (15 - 17 = -2) \\
10^4 &= (10^2)^2 \equiv (-2)^2 \\
&= 4 \pmod{17} \\
10^7 &= 10 \cdot 10^2 \cdot 10^4 \\
&\equiv 10 \cdot (-2) \cdot 4 \\
&= -80 = -5 \cdot 17 + 5 \\
&\equiv 5 \pmod{17}
\end{aligned}
$$

(Computing $10^7$ uses all three factors $10^1 \cdot 10^2 \cdot 10^4$. Positive factors give $10 \cdot 15 \cdot 4 = 600 = 35 \cdot 17 + 5 \equiv 5 \pmod{17}$.) Similarly, for $10^{10} \bmod 17$:

$$
\begin{aligned}
10^8 &= (10^4)^2 \equiv 4^2 = 16 \\
&\equiv -1 \pmod{17} \\
10^{10} &= 10^8 \cdot 10^2 \equiv (-1) \cdot (-2) \\
&= 2 \pmod{17}
\end{aligned}
$$

[Fast Exponentiation](/courses/computational-mathematics/fast-exponentiation) turns this trick into an algorithm that handles exponents hundreds of digits long.

<CodeTabs>

```matlab
mod(mod(11, 8) + mod(15, 8), 8)    % 2, addition reducing first
mod(11 + 15, 8)                    % 2, addition directly
mod(mod(11, 8) - mod(15, 8), 8)    % 4, subtraction reducing first
mod(11 - 15, 8)                    % 4, subtraction directly
mod(mod(11, 8) * mod(15, 8), 8)    % 5, multiplication reducing first
mod(11 * 15, 8)                    % 5, multiplication directly
mod(10^10, 17)                     % 2, exponentiation
```

```python
print((11 % 8 + 15 % 8) % 8, (11 + 15) % 8)  # 2 2
print((11 % 8 - 15 % 8) % 8, (11 - 15) % 8)  # 4 4
print((11 % 8) * (15 % 8) % 8, 11 * 15 % 8)  # 5 5

# Python's three-argument pow reduces as it goes
print(pow(10, 7, 17))   # 5
print(pow(10, 10, 17))  # 2
```

</CodeTabs>

## Be careful when cancelling

If $(a + b) \equiv (a + c) \pmod n$, you can always cancel $a$ by subtracting it from both sides to get $b \equiv c$.

Multiplication allows cancellation only under specific conditions. If $a \cdot b \equiv a \cdot c \pmod n$, then $n$ divides $a(b - c)$. When $a$ and $n$ are [coprime](/courses/computational-mathematics/divisibility-and-euclid#greatest-common-divisor) ($\gcd(a, n) = 1$), $n$ shares no factors with $a$. That forces $n$ to divide $b - c$, which gives $b \equiv c \pmod n$. When $\gcd(a, n) = d > 1$, the shared factor $d$ absorbs part of $n$. That leads to the general cancellation rule:

$$
\begin{aligned}
a \cdot b &\equiv a \cdot c \pmod n \implies \\
b &\equiv c \pmod{\frac{n}{\gcd(a, n)}}
\end{aligned}
$$

For instance, $2 \cdot 3 \equiv 2 \cdot 7 \pmod 8$, because both equal 6 modulo 8. Because $\gcd(2, 8) = 2$, cancelling 2 changes the modulus from 8 to $8/2 = 4$. That gives $3 \equiv 7 \pmod 4$, even though $3 \not\equiv 7 \pmod 8$.

<Callout tone="orange" label="Common errors">
- **Reducing exponents modulo $n$:** Bases can be reduced at any step, but exponents cannot. As you'll see in [Primality and Euler's Totient](/courses/computational-mathematics/primality-and-the-totient#eulers-totient-function), powers repeat modulo $\phi(n)$ (the count of coprime residues), not modulo $n$. For example, $2^5 \bmod 3 = 32 \bmod 3 = 2$. Reducing the exponent modulo 3 gives $2^{5 \bmod 3} = 2^2 = 4 \equiv 1 \pmod 3$, which is incorrect.
- **Cancelling factors without dividing the modulus:** If $2x \equiv 6 \pmod 8$, dividing both sides by 2 gives $x \equiv 3 \pmod 4$, not $x \equiv 3 \pmod 8$. In the original modulus 8, there are two solutions: $x = 3$ and $x = 7$.
</Callout>
