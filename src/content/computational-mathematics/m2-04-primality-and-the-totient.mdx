# Primality Tests and Euler's Totient

[Trial division](/courses/computational-mathematics/primes-and-the-sieve#you-only-need-to-check-up-to-the-square-root) stops working when numbers have hundreds of digits. This lesson covers three classic theorems that say something about primes without searching for factors, and the third one is the engine inside RSA.

## Wilson's theorem

An integer $n > 1$ is prime if and only if

$$
(n - 1)! \equiv -1 \pmod{n}
$$

The proof is a good picture. Modulo a prime, every number from 1 to $n - 1$ has a partner it multiplies with to give 1, its [inverse modulo $n$](/courses/computational-mathematics/modular-inverses). These pairs all cancel, except for 1 and $n - 1$, which are their own partners:

<WilsonVisualizer />

<CodeTabs>

```matlab
mod(factorial(13 - 1), 13) - 13    % -1, so 13 is prime
```

```python
import math

# Python's integers never overflow, so even large factorials stay exact
print(math.factorial(13 - 1) % 13 - 13)  # -1
```

</CodeTabs>

<Callout tone="orange" label="Beautiful, and useless in practice">
Wilson's theorem is an exact test, but you'd have to compute a factorial. MATLAB's `factorial` is only exact up to $21!$ because it uses doubles, and even exact arithmetic would take far too long for large $n$.
</Callout>

## Fermat's Little Theorem

If $n$ is prime and $\gcd(a, n) = 1$, then

$$
a^{n-1} \equiv 1 \pmod{n}
$$

For $a = 7$ and $n = 19$: $7^2 \equiv 11$, $7^4 \equiv 7$, $7^8 \equiv 11$, $7^{16} \equiv 7$, and so $7^{18} = 7^{16} \cdot 7^2 \equiv 7 \cdot 11 \equiv 1 \pmod{19}$. Squaring repeatedly like this is the idea behind [fast exponentiation](/courses/computational-mathematics/fast-exponentiation).

It's also a shortcut for big powers. To show $5^{38} \equiv 4 \pmod{11}$, use $5^{10} \equiv 1$:

$$
5^{38} = (5^{10})^3 \cdot 5^8 \equiv 1^3 \cdot (5^2)^4 \equiv 3^4 = 81 \equiv 4 \pmod{11}
$$

<CodeTabs>

```matlab
powermod(7, 18, 19)     % 1, as the theorem predicts
powermod(5, 38, 11)     % 4
powermod(2, 560, 561)   % 1, yet 561 = 3 * 11 * 17
% powermod needs the Symbolic Math Toolbox
```

```python
# Python's three-argument pow is modular exponentiation, built in
print(pow(7, 18, 19))  # 1
print(pow(5, 38, 11))  # 4
print(pow(2, 560, 561))  # 1
```

</CodeTabs>

So if $a^{n-1} \not\equiv 1$, then $n$ is definitely composite. The reverse doesn't always hold: rare composites called Carmichael numbers, such as 561, pass this test for every coprime $a$, as the last line shows. Real systems use the stronger Miller-Rabin test for that reason.

Miller-Rabin is a **randomised** test: it tries random bases, and a composite number slips through each round with a probability of at most 1 in 4. Forty rounds push the chance of a mistake below one in a trillion trillion, far less likely than a hardware fault, at a tiny fraction of the cost of a proof. Machine learning makes the same bargain. **Stochastic gradient descent** works out the gradient from a small random batch of examples instead of the whole dataset: the answer is slightly noisy, but it's thousands of times cheaper, and over many steps the noise averages out.

## Euler's totient function

$\phi(n)$ counts the positive integers less than $n$ that are [coprime](/courses/computational-mathematics/divisibility-and-euclid#greatest-common-divisor) to $n$. Some values follow directly:

- If $p$ is prime, $\phi(p) = p - 1$. An integer $n > 1$ is prime exactly when $\phi(n) = n - 1$.
- For a prime power, $\phi(p^k) = p^k - p^{k-1}$.
- In general, if $p_1, \dots, p_r$ are the distinct primes dividing $n$:

$$
\phi(n) = n \left(1 - \frac{1}{p_1}\right)\left(1 - \frac{1}{p_2}\right) \cdots \left(1 - \frac{1}{p_r}\right)
$$

So $\phi(23) = 22$, $\phi(81) = 81 \cdot \tfrac{2}{3} = 54$, and $\phi(100) = 100 \cdot \tfrac{1}{2} \cdot \tfrac{4}{5} = 40$. Slide $n$ and watch the coprime numbers change. Primes light up almost the whole grid:

<TotientGrid />

The direct count takes a few lines of MATLAB, using the fact that $\gcd$ is quick:

<CodeTabs>

```matlab
n = 1000;
z = 0;
for i = 1:n-1
    if gcd(i, n) == 1
        z = z + 1;
    end
end
fprintf('Euler Phi (n) = %1.0f\n', z)    % 400
```

```python
import math
import numpy as np

n = 1000
print(sum(1 for i in range(1, n) if math.gcd(i, n) == 1))  # 400

# NumPy's gcd works on a whole array at once, so no loop is needed
print(int(np.sum(np.gcd(np.arange(1, n), n) == 1)))  # 400
```

</CodeTabs>

The totient guards some of the most private data in machine learning. Hospitals or phones may want to train one shared model without anyone seeing their raw records. **Paillier encryption**, built on the same modular arithmetic as RSA, lets a server add numbers it can't read, so it can sum encrypted model updates from many clients and only ever see the total. Its security rests on keeping $\phi(n)$ secret, which is the same as keeping the prime factors of $n$ secret.

## The Euler-Fermat theorem

Euler generalised Fermat's result to any modulus. If $\gcd(a, n) = 1$, then

$$
a^{\phi(n)} \equiv 1 \pmod{n}
$$

With $a = 3$ and $n = 10$: $\phi(10) = 4$ and $3^4 = 81 \equiv 1$. With $a = 2$ and $n = 11$: $\phi(11) = 10$ and $2^{10} = 1024 \equiv 1$. When $n$ is prime, $\phi(n) = n - 1$, and you get Fermat's theorem back.

<CodeTabs>

```matlab
mod(3^4, 10)      % 1
mod(2^10, 11)     % 1
```

```python
print(pow(3, 4, 10), pow(2, 10, 11))  # 1 1
```

</CodeTabs>
