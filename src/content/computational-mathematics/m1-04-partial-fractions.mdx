# Partial Fractions

A ratio of two polynomials can be hard to work with. Split it into a sum of simple fractions and each piece becomes easy to integrate, to invert, or to read off a system's behaviour.

## The expansion

For polynomials $b$ and $a$ with no repeated roots in $a$:

$$
\frac{b(s)}{a(s)} = \frac{r_1}{s - p_1} + \frac{r_2}{s - p_2} + \cdots + \frac{r_n}{s - p_n} + k(s)
$$

Here $p_i$ are the **poles** (the [roots](/courses/computational-mathematics/polynomials-and-roots#roots) of $a$), $r_i$ are the **residues**, and $k(s)$ holds any direct terms. They're called poles because the fraction shoots up to infinity there: at $s = p_i$ the bottom is zero, like a tent pole pushing the graph up. Each residue says how strongly its pole pulls.

$k$ is empty when $b$ has a lower degree than $a$. Otherwise, $k(s)$ is the polynomial part you'd get from [long division](/courses/computational-mathematics/multiplying-and-dividing#deconvolution) first. For example, $\frac{s^2 + 1}{s + 1} = s - 1 + \frac{2}{s + 1}$, so `residue([1 0 1], [1 1])` gives $r = 2$, $p = -1$ and $k = [1\ \ {-1}]$.

"No repeated roots" matters because the formula needs one simple fraction per pole. If $a$ has a double root, the expansion also needs a term with $(s - p)^2$ underneath. `residue` handles that case too, but this lesson sticks to distinct poles.

Each piece $\dfrac{r}{s - p}$ is the simplest system there is: something that remembers its past and lets it fade at a fixed rate. Machine learning is full of these. An **exponential moving average** updates as

$$
y_t = \alpha x_t + (1 - \alpha)\, y_{t-1}
$$

so every new value is blended with the running average, and older values fade by a factor of $1 - \alpha$ each step. That's a filter with a single pole. **Momentum** and the **Adam** optimizer, which train most neural networks today, keep moving averages like this of the gradient, so one noisy step can't throw training off course. Many models also keep an averaged copy of their own weights to use at the end, because it's steadier than the last step.

<CodeTabs>

```matlab
x = [1 2 3];
alpha = 0.5;

% filter(b, a, x) runs y(t) = alpha*x(t) + (1 - alpha)*y(t-1).
% The last argument starts the average at the first value.
y = filter(alpha, [1 -(1 - alpha)], x, (1 - alpha) * x(1))

y =
    1.0000    1.5000    2.2500
```

```python
import pandas as pd

s = pd.Series([1.0, 2.0, 3.0])

# adjust=False gives exactly the update above, starting from the first value
print(s.ewm(alpha=0.5, adjust=False).mean().tolist())  # [1.0, 1.5, 2.25]
```

</CodeTabs>

Splitting a complicated filter into partial fractions breaks it into pieces of exactly this kind, each with its own pole and its own rate of fading.

## An example

A **transfer function** is a fraction like this one, written in the variable $s$, that describes how a system turns an input signal into an output: a circuit, a motor, a filter. Engineers write systems this way because chaining two systems is then just multiplying their fractions. Take this transfer function:

$$
\frac{-4s + 8}{s^2 + 6s + 8}
$$

The denominator factors as $(s + 4)(s + 2)$. To find the residue at a pole, cover up that pole's factor and substitute the pole into everything left over:

<CoverUpVisualizer />

MATLAB's `residue` returns the same numbers:

<CodeTabs>

```matlab
b = [-4 8];
a = [1 6 8];
[r, p, k] = residue(b, a)

r =
   -12
     8
p =
    -4
    -2
k =
     []
```

```python
import numpy as np

b = [-4, 8]
a = [1, 6, 8]

# For distinct poles the rule fits in one line: the residue at p is b(p) / a'(p),
# where a' is the derivative of a. That's the cover-up method.
p = np.roots(a)
r = np.polyval(b, p) / np.polyval(np.polyder(a), p)

print(np.round(p, 6).tolist())  # [-4.0, -2.0]
print(np.round(r, 6).tolist())  # [-12.0, 8.0]

# SciPy has the full version, which also handles repeated poles.
# It lists the poles in a different order:
from scipy.signal import residue

r2, p2, k2 = residue(b, a)
print(np.round(r2, 6).tolist(), np.round(p2, 6).tolist())  # [8.0, -12.0] [-2.0, -4.0]
```

</CodeTabs>

So the fraction equals $\dfrac{-12}{s + 4} + \dfrac{8}{s + 2}$.

Worked by hand, the cover-up method gives each residue in one line. For the pole $-4$, cover up $(s + 4)$ and put $s = -4$ into the rest:

$$
r_1 = \frac{-4(-4) + 8}{-4 + 2} = \frac{24}{-2} = -12
$$

For the pole $-2$, cover up $(s + 2)$ and put $s = -2$ into the rest:

$$
r_2 = \frac{-4(-2) + 8}{-2 + 4} = \frac{16}{2} = 8
$$

The same numbers come from a formula that doesn't need the factors written out: $r_i = b(p_i) / a'(p_i)$, where $a'$ is the [derivative](/courses/computational-mathematics/derivatives-and-curve-fitting#derivatives) of $a$. Here $a'(s) = 2s + 6$, so $r_1 = 24 / a'(-4) = 24 / (-2) = -12$, and $r_2 = 16 / a'(-2) = 16 / 2 = 8$.

<Callout tone="sky" label="Reading other notes">
Some notes write the expansion with $\frac{a(s)}{b(s)}$ on the left. MATLAB's `residue(b, a)` always expands $b$ over $a$: numerator first, denominator second. The direct term is $k(s)$, a polynomial, sometimes misprinted as $k_s$.
</Callout>

<Callout tone="orange" label="Common mistake">
Getting a pole's sign backwards. The factor $(s + 4)$ comes from the pole $s = -4$, not $+4$, because $s + 4 = s - (-4)$. So the cover-up step puts $s = -4$ into the rest. Putting in $+4$ gives $\frac{-8}{6}$, which is wrong. To check a residue, add the simple fractions back together and compare with the original.
</Callout>

## Going back

Give `residue` three inputs, and it converts back to polynomial form:

<CodeTabs>

```matlab
[b2, a2] = residue(r, p, k)

b2 =
    -4     8
a2 =
     1     6     8
```

```python
import numpy as np
from scipy.signal import invres

b2, a2 = invres([-12, 8], [-4, -2], [])
print(np.round(b2, 6).tolist(), np.round(a2, 6).tolist())  # [-4.0, 8.0] [1.0, 6.0, 8.0]
```

</CodeTabs>

Each term $r/(s - p)$ corresponds to an exponential $re^{pt}$ over time. So once you've split a transfer function, you can read how the system responds term by term.
