# Matrices and MATLAB

A **matrix** is a rectangular grid of numbers. Many programs are built on this simple idea. A photo is a matrix of pixel values. A spreadsheet is a matrix with labels. A neural network layer is mostly a matrix of weights.

This course uses MATLAB because its syntax is close to the maths on paper. Every code block also has a Python version, using NumPy and pandas: switch with the tabs on top, and your choice applies to every block in the course.

## Writing a matrix down

We describe size as **rows by columns**, always in that order. A 2-by-3 matrix has 2 rows and 3 columns. The entry in row $i$, column $j$ of $A$ is written $a_{ij}$. The row always comes first, in the size and in the index. Swapping them is the most common mistake with matrices: $a_{23}$ is row 2, column 3, which is a different entry from $a_{32}$.

<CodeTabs>

```matlab
A = pascal(3);
A(2, 3)        % row 2, column 3; MATLAB counts from 1

ans =
     3
```

```python
import numpy as np

A = np.array([[1, 1, 1], [1, 2, 3], [1, 3, 6]])

# Python counts from 0, so MATLAB's A(2, 3) is A[1, 2]
print(A[1, 2])  # 3
```

</CodeTabs>

Three shapes get their own names:

- A **column vector** is a matrix with a single column: $m$-by-1.
- A **row vector** is a matrix with a single row: 1-by-$n$.
- A **scalar** is 1-by-1, which is a single number.

In MATLAB, a space or comma moves to the next column and a semicolon starts a new row:

<CodeTabs>

```matlab
u = [3; 1; 4]      % column vector
v = [2 0 -1]       % row vector
s = 7              % scalar
```

```python
import numpy as np

u = np.array([[3], [1], [4]])  # column vector, shape (3, 1)
v = np.array([[2, 0, -1]])     # row vector, shape (1, 3)
s = 7                          # scalar

# NumPy also has plain 1-D arrays, np.array([2, 0, -1]), with shape (3,).
# They're neither rows nor columns, and most code uses them for vectors.
print(u.shape, v.shape)  # (3, 1) (1, 3)
```

</CodeTabs>

This is also how machine learning stores data. A training set is one matrix, usually called $X$, with **one row per example and one column per feature**. Three people described by height and weight make a 3-by-2 matrix:

<CodeTabs>

```matlab
X = [170 65; 182 80; 165 54];
size(X)

ans =
     3     2
```

```python
import pandas as pd

# Data usually arrives as a pandas DataFrame, with named columns.
# .to_numpy() drops the labels and leaves the matrix.
df = pd.DataFrame({"height": [170, 182, 165], "weight": [65, 80, 54]})
X = df.to_numpy()

print(X.shape)  # (3, 2)
```

</CodeTabs>

## Two example matrices

MATLAB has dozens of functions that build matrices. We'll keep coming back to two of them because they're small and easy to recognise. The **main diagonal** of a matrix is the line of entries $a_{11}, a_{22}, a_{33}, \dots$ from the top-left corner down to the right. On it, the row number equals the column number. `pascal(3)` is **symmetric**, meaning it looks the same when you mirror it across its main diagonal: $a_{ij} = a_{ji}$ for every $i$ and $j$. Check one pair: row 2, column 3 holds 3, and so does row 3, column 2. `magic(3)` isn't symmetric, but all its rows, columns and both diagonals add up to 15.

<CodeTabs>

```matlab
A = pascal(3)          B = magic(3)

A =                    B =
     1     1     1          8     1     6
     1     2     3          3     5     7
     1     3     6          4     9     2
```

```python
import numpy as np

# NumPy has no pascal or magic, so write them out
# (scipy.linalg.pascal(3) builds the first one).
A = np.array([[1, 1, 1], [1, 2, 3], [1, 3, 6]])
B = np.array([[8, 1, 6], [3, 5, 7], [4, 9, 2]])

print(B.sum(axis=0).tolist())  # [15, 15, 15]
```

</CodeTabs>

When you need test data, `rand` gives numbers between 0 and 1, and `fix` removes the part after the decimal point. This line makes a 3-by-2 matrix of random integers from 0 to 9:

<CodeTabs>

```matlab
C = fix(10 * rand(3, 2))
```

```python
import numpy as np

rng = np.random.default_rng()
C = rng.integers(0, 10, size=(3, 2))  # integers from 0 to 9; the 10 is excluded
```

</CodeTabs>

## Adding and subtracting

If $A$ and $B$ are both $m$-by-$n$, their sum $C = A + B$ is also $m$-by-$n$, with

$$
c_{ij} = a_{ij} + b_{ij}
$$

for every row $i = 1, \dots, m$ and every column $j = 1, \dots, n$. By hand, you add the two entries that sit in the same place:

$$
\begin{aligned}
&\begin{bmatrix} 1 & -2 & 3 \\ 2 & -1 & 4 \end{bmatrix} +
\begin{bmatrix} 0 & 2 & 1 \\ 1 & 3 & -4 \end{bmatrix} \\
&= \begin{bmatrix} 1+0 & -2+2 & 3+1 \\ 2+1 & -1+3 & 4+(-4) \end{bmatrix} \\
&= \begin{bmatrix} 1 & 0 & 4 \\ 3 & 2 & 0 \end{bmatrix}
\end{aligned}
$$

Subtraction works the same way. Adding $A$ to $B$ and then subtracting $A$ brings you back to $B$, just as it does with ordinary numbers.

<CodeTabs>

```matlab
A + B

ans =
     9     2     7
     4     7    10
     5    12     8
```

```python
import numpy as np

A = np.array([[1, 1, 1], [1, 2, 3], [1, 3, 6]])
B = np.array([[8, 1, 6], [3, 5, 7], [4, 9, 2]])

print((A + B).tolist())  # [[9, 2, 7], [4, 7, 10], [5, 12, 8]]

# Plain Python has no matrix type. With nested lists you write the loop:
P, Q = [[1, 2], [3, 4]], [[5, 6], [7, 8]]
print([[a + b for a, b in zip(rp, rq)] for rp, rq in zip(P, Q)])  # [[6, 8], [10, 12]]
```

</CodeTabs>

Machine learning uses this all the time to prepare data. Features are often measured in different units, like centimetres and kilograms. So they are usually **standardised** first: subtract each column's mean, then divide by its **standard deviation**. The standard deviation measures how far values usually are from their mean. Afterwards every feature sits around 0 on a similar scale. Without this step, the feature with the biggest numbers would control the model. A change of 10 in centimetres would count as much as a change of 10 in kilograms.

Two details in the code below need explaining. `mean(X)` returns one mean per column, a 1-by-2 row, so `X - mean(X)` subtracts a row from a 3-by-2 matrix. That works because MATLAB (since 2016) and NumPy **broadcast**: a single row is copied down to fill every row before the subtraction. And `./` is entry-by-entry division. The dot tells MATLAB to work entry by entry rather than use the matrix version of the operation, which you'll meet with [multiplication](/courses/computational-mathematics/multiplying-matrices#the-rule). `std(X, 1)` divides by $n$ rather than $n - 1$, which matches NumPy's default.

<CodeTabs>

```matlab
X = [170 65; 182 80; 165 54];
Z = (X - mean(X)) ./ std(X, 1);
round(mean(Z), 6)

ans =
     0     0
```

```python
import numpy as np

X = np.array([[170, 65], [182, 80], [165, 54]], dtype=float)
Z = (X - X.mean(axis=0)) / X.std(axis=0)  # the 1-row means stretch to fit every row

print(np.allclose(Z.mean(axis=0), 0))  # True
```

</CodeTabs>

## Multiplying by a scalar

The scalar multiple $rA$ multiplies every entry of $A$ by $r$:

$$
c_{ij} = r \cdot a_{ij}
$$

With $r = -2$, every entry changes sign and doubles:

$$
\begin{aligned}
&-2\begin{bmatrix} 4 & -2 & -3 \\ 7 & -3 & 2 \end{bmatrix} \\
&= \begin{bmatrix} -2 \cdot 4 & -2 \cdot (-2) & -2 \cdot (-3) \\ -2 \cdot 7 & -2 \cdot (-3) & -2 \cdot 2 \end{bmatrix} \\
&= \begin{bmatrix} -8 & 4 & 6 \\ -14 & 6 & -4 \end{bmatrix}
\end{aligned}
$$

Pick an operation and step through it. Each entry is only ever combined with the entry in the same position:

<ElementwiseVisualizer />

Training a neural network is mostly this step, repeated millions of times. **Gradient descent** updates the weights with

$$
w \leftarrow w - \eta \nabla L
$$

Here $w$ holds the weights and $L$ is the **loss**, one number that measures how wrong the model's predictions are. The **gradient** $\nabla L$ has one entry per weight, saying how fast the loss rises as that weight grows. Stepping against it (that's why there's a minus sign) moves each weight in the direction that lowers the error. The **learning rate** $\eta$ is a scalar that sets the step size. So one training step is a scalar multiple followed by a subtraction:

<CodeTabs>

```matlab
w = [0.5 -1.2];
grad = [0.2 -0.4];
eta = 0.1;

w = w - eta * grad

w =
    0.4800   -1.1600
```

```python
import numpy as np

w = np.array([0.5, -1.2])
grad = np.array([0.2, -0.4])
eta = 0.1

w = w - eta * grad
print(np.round(w, 4).tolist())  # [0.48, -1.16]
```

</CodeTabs>

<Callout tone="orange" label="Common error">
Addition needs matching sizes. The exceptions are the broadcasting cases above: a scalar is added to every entry, and a single row or column is copied to fill the other matrix. Two full matrices of different shapes never work. Trying `pascal(3) + fix(10*rand(3,2))` stops with a dimensions error, because a 3-by-3 and a 3-by-2 don't match. Older MATLAB versions word it as "Matrix dimensions must agree", and Octave says "nonconformant arguments".
</Callout>

<CodeTabs>

```matlab
pascal(3) + ones(3, 2)

error: operator +: nonconformant arguments (op1 is 3x3, op2 is 3x2)
```

```python
import numpy as np

np.ones((3, 3)) + np.ones((3, 2))
# ValueError: operands could not be broadcast together with shapes (3,3) (3,2)
```

</CodeTabs>
