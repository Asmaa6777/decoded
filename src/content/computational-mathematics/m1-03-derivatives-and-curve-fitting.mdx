# Derivatives and Curve Fitting

Two more jobs that become a single function call: finding how fast a polynomial changes, and finding the polynomial that best describes noisy data. Together, they're a small version of machine learning.

## Derivatives

The **derivative** $p'(x)$ of a polynomial is another polynomial that gives the slope of $p$'s curve at every $x$. It's positive where the curve rises, negative where it falls, and zero at the top of a hill or the bottom of a valley. For a single term, the derivative of $ax^n$ is $nax^{n-1}$: the power comes down as a multiplier and goes down by one. On a coefficient vector, that takes two steps. First multiply each coefficient by its power of $x$. Then delete the constant term, the rightmost number, because a constant has a derivative of zero.

Take $x^3 - 2x - 5$. Its coefficients `[1 0 -2 -5]` go with the powers 3, 2, 1 and 0, so multiplying gives `[3 0 -2 0]`. Deleting the constant term leaves `[3 0 -2]`, which is $3x^2 - 2$. `polyder` does this for you:

<CodeTabs>

```matlab
p = [1 0 -2 -5];      % x³ - 2x - 5
q = polyder(p)

q =
     3     0    -2     % 3x² - 2
```

```python
import numpy as np

print(np.polyder([1, 0, -2, -5]).tolist())  # [3, 0, -2]
```

</CodeTabs>

<Callout tone="orange" label="Common mistake">
Only dropping the last number. `[1 0 -2 -5]` with the constant removed is `[1 0 -2]`, which is $x^2 - 2$, not the derivative. Each coefficient must first be multiplied by its own power, so the $x^3$ coefficient becomes 3. The answer is always one entry shorter than $p$.
</Callout>

`polyder` also accepts two polynomials, and the number of outputs you ask for decides what it computes. Take $a(x) = x^2 + 3x + 5$ and $b(x) = 2x^2 + 4x + 6$.

With one output, `polyder(a, b)` returns the derivative of the product $a(x)\,b(x)$. There's a rule for that, $(ab)' = a'b + ab'$, but the simplest way to check it is to multiply first and then differentiate. The product, worked out by [convolution](/courses/computational-mathematics/multiplying-and-dividing#convolution), is $2x^4 + 10x^3 + 28x^2 + 38x + 30$, so the answer is $8x^3 + 30x^2 + 56x + 38$:

<CodeTabs>

```matlab
a = [1 3 5];  b = [2 4 6];

c = polyder(a, b)        % 8  30  56  38
```

```python
import numpy as np

a, b = [1, 3, 5], [2, 4, 6]

# NumPy's polyder takes one polynomial, so multiply first
print(np.polyder(np.polymul(a, b)).tolist())  # [8, 30, 56, 38]
```

</CodeTabs>

With two outputs, it returns the derivative of the quotient $a(x) / b(x)$. The result is a fraction, so you get its top and bottom separately. By the quotient rule, the derivative of $a/b$ is $(a'b - ab')/b^2$, so `q` is $a'b - ab'$ and `d` is $b^2$. Here $a' = 2x + 3$ and $b' = 4x + 4$, so

$$
\begin{aligned}
a'b &= (2x + 3)(2x^2 + 4x + 6) = 4x^3 + 14x^2 + 24x + 18 \\
ab' &= (x^2 + 3x + 5)(4x + 4) = 4x^3 + 16x^2 + 32x + 20 \\
a'b - ab' &= -2x^2 - 8x - 2
\end{aligned}
$$

The $x^3$ terms cancel, which is why `q` has only three numbers:

<CodeTabs>

```matlab
[q, d] = polyder(a, b)   % q = -2  -8  -2   (Octave divides both by 4)
                         % d =  4  16  40  48  36
```

```python
import numpy as np

a, b = [1, 3, 5], [2, 4, 6]

# The quotient rule, written out: q = a'b - ab', d = b²
q = np.polysub(np.polymul(np.polyder(a), b), np.polymul(a, np.polyder(b)))
q = np.trim_zeros(q, "f")  # the x³ terms cancel; drop the leading zero they leave
d = np.polymul(b, b)

print(q.tolist())  # [-2, -8, -2]
print(d.tolist())  # [4, 16, 40, 48, 36]
```

</CodeTabs>

So the derivative of the quotient is

$$
\frac{-2x^2 - 8x - 2}{4x^4 + 16x^3 + 40x^2 + 48x + 36}
$$

The derivative is how every neural network learns. It says which way is downhill. So training measures the error, takes the derivative of the error with respect to each weight, and moves each weight a little the other way. That's **gradient descent**, and the deep-learning libraries' main job is computing these derivatives for billions of weights at once. For a single weight fitting $y = wx$ to three points, a short loop is enough. The error is the mean of $(wx_i - y_i)^2$. Its derivative with respect to $w$ is the mean of $2(wx_i - y_i)x_i$: the power 2 comes down, and the inner $wx_i$ gives the factor $x_i$. The data lies on $y = 2x$, so $w$ should end up at 2:

<CodeTabs>

```matlab
xs = [1 2 3];  ys = [2 4 6];
w = 0;

for step = 1:100
    grad = mean(2 * (w * xs - ys) .* xs);   % derivative of the mean squared error
    w = w - 0.05 * grad;                    % step downhill
end
w

w =
    2.0000
```

```python
xs, ys = [1.0, 2.0, 3.0], [2.0, 4.0, 6.0]
w = 0.0

for step in range(100):
    grad = sum(2 * (w * x - y) * x for x, y in zip(xs, ys)) / len(xs)
    w -= 0.05 * grad

print(round(w, 4))  # 2.0
```

</CodeTabs>

## Fitting a curve to data

Real measurements rarely lie exactly on a smooth curve. `polyfit(x, y, n)` finds the degree $n$ polynomial (MATLAB's help says "order $n$") with the smallest **sum of squared errors**, which is called a **least-squares** fit. Each error is the gap between the curve and a data point, $p(x_i) - y_i$. Squaring stops positive and negative gaps from cancelling, and makes one big miss cost more than several small ones:

$$
\min_{p} \sum_{i} \bigl(p(x_i) - y_i\bigr)^2
$$

<CodeTabs>

```matlab
x = [1 2 3 4 5];
y = [5.5 43.1 128 290.7 498.4];
p = polyfit(x, y, 3)

p =
   -0.1917   31.5821  -60.3262   35.3400
```

```python
import numpy as np

x = [1, 2, 3, 4, 5]
y = [5.5, 43.1, 128, 290.7, 498.4]

print(np.round(np.polyfit(x, y, 3), 4).tolist())  # [-0.1917, 31.5821, -60.3262, 35.34]
```

</CodeTabs>

So the fitted cubic is $p(x) \approx -0.1917x^3 + 31.5821x^2 - 60.3262x + 35.34$. To draw it, evaluate it at many points between the data, here every 0.1 from 1 to 5, and plot those over the original measurements:

<CodeTabs>

```matlab
x2 = 1:0.1:5;             % 41 points from 1 to 5
y2 = polyval(p, x2);
plot(x, y, 'o', x2, y2)   % data as circles, the fit as a line
grid on

polyval(p, 2.5)
ans =
   78.9181
```

```python
import numpy as np

x = [1, 2, 3, 4, 5]
y = [5.5, 43.1, 128, 290.7, 498.4]
p = np.polyfit(x, y, 3)

x2 = np.arange(1, 5.05, 0.1)  # 41 points from 1 to 5
y2 = np.polyval(p, x2)
# matplotlib: plt.plot(x, y, "o", x2, y2)

print(len(x2), round(float(np.polyval(p, 2.5)), 4))  # 41 78.9181
```

</CodeTabs>

This is the core of machine learning, on a small scale. `polyfit` is [linear regression](/courses/computational-mathematics/determinants-and-inverses#dont-use-inv-to-solve-equations) on [polynomial features](/courses/computational-mathematics/polynomials-and-roots#writing-one-down), the sum of squared errors is the **mean squared error** loss without the division, and the degree is the model's complexity.

Now try it. Change the degree, and drag the points to see the curve respond:

<Callout tone="orange" label="Lower error isn't always better">
Five points can always be matched exactly by a polynomial of degree 4. Zero error looks perfect, but it often means the curve has learned the noise in your data and will predict poorly between and beyond the points. This is called overfitting, and it's one of the main problems in machine learning.
</Callout>

That's why machine learning never judges a model on the data it trained on. Hold some points back as a **test set**: as the degree rises, the error on the training points keeps falling, while the error on the held-out points eventually climbs. The degree where test error is lowest is the one to keep. Here a straight line is trained on the even points and checked on the odd ones, against a degree-4 curve:

<CodeTabs>

```matlab
x = 0:9;
y = 2*x + [0.3 -0.4 0.2 0.5 -0.3 0.1 -0.5 0.4 -0.2 0.3];
train = mod(x, 2) == 0;  test = ~train;
mse = @(p, m) mean((polyval(p, x(m)) - y(m)).^2);

p1 = polyfit(x(train), y(train), 1);
p4 = polyfit(x(train), y(train), 4);

[mse(p4, train) < mse(p1, train), mse(p4, test) > mse(p1, test)]

ans =
  1×2 logical array
   1   1
```

```python
import numpy as np

x = np.arange(10.0)
y = 2 * x + np.array([0.3, -0.4, 0.2, 0.5, -0.3, 0.1, -0.5, 0.4, -0.2, 0.3])
train, test = x % 2 == 0, x % 2 == 1

def errors(degree):
    p = np.polyfit(x[train], y[train], degree)
    return [np.mean((np.polyval(p, x[m]) - y[m]) ** 2) for m in (train, test)]

low, high = errors(1), errors(4)
print(high[0] < low[0])  # True
print(high[1] > low[1])  # True
```

</CodeTabs>

The degree-4 curve wins on the training points and loses on the new ones: it memorised the noise. Large neural networks face the same trade-off with millions of weights instead of five coefficients.

## Where you'll meet this

<ApplicationsGrid>
