# The Kronecker Product

The ordinary matrix product needs sizes that fit together. The **Kronecker product** works with any two matrices and always grows the result, so it's the standard way to build a big structured matrix out of small ones.

## The definition

If $A$ is $m$-by-$n$ and $B$ is $p$-by-$q$, then $A \otimes B$ is $mp$-by-$nq$. Each entry of $A$ scales one whole copy of $B$:

$$
A \otimes B =
\begin{bmatrix}
a_{11}B & a_{12}B & \cdots & a_{1n}B \\
a_{21}B & a_{22}B & \cdots & a_{2n}B \\
\vdots & \vdots & & \vdots \\
a_{m1}B & a_{m2}B & \cdots & a_{mn}B
\end{bmatrix}
$$

Watch the blocks appear one at a time:

<CodeTabs>

```matlab
A = [1 -2; -1 0];
B = [4 -3; 2 3];
kron(A, B)

ans =
     4    -3    -8     6
     2     3    -4    -6

    -2    -3     0     0
```

```python
import numpy as np

A = np.array([[1, -2], [-1, 0]])
B = np.array([[4, -3], [2, 3]])
print(np.kron(A, B).tolist())  # [[4, -3, -8, 6], [2, 3, -4, -6], [-4, 3, 0, 0], [-2, -3, 0, 0]]

# Plain Python spells out all four loops: rows of A, rows of B, then their entries
P, Q = [[1, 2]], [[0, 5], [6, 7]]
print([[a * b for a in rp for b in rq] for rp in P for rq in Q])  # [[0, 5, 0, 10], [6, 7, 12, 14]]
```

</CodeTabs>

The size grows fast, and machine learning puts that to work in reverse. Some optimizers need the curvature of the loss for every pair of weights, a matrix far too large to store, let alone invert. **K-FAC** approximates each layer's block of it as a Kronecker product of two small matrices. That helps because

$$
(A \otimes B)^{-1} = A^{-1} \otimes B^{-1}
$$

so [inverting](/courses/computational-mathematics/determinants-and-inverses#the-inverse) two small matrices replaces inverting a huge one. **Gaussian processes**, which predict with an honest error bar around each prediction, use the same shortcut on grid-shaped data such as images or measurements over space and time, because their covariance matrix often factors this way.

## Order changes the pattern

`kron(X, Y)` and `kron(Y, X)` have the same size and the same entries in a different arrangement. Using the [identity matrix](/courses/computational-mathematics/multiplying-matrices#the-identity-matrix) makes this easy to see. With $X = \begin{bmatrix}1 & 2\\3 & 4\end{bmatrix}$ and `I = eye(2)`:

<CodeTabs>

```matlab
X = [1 2; 3 4];
I = eye(2);
kron(X, I)             kron(I, X)

  1  0  2  0             1  2  0  0
  0  1  0  2             3  4  0  0
  3  0  4  0             0  0  1  2
  0  3  0  4             0  0  3  4
```

```python
import numpy as np

X = np.array([[1, 2], [3, 4]])
I = np.eye(2, dtype=int)

print(np.kron(X, I).tolist())  # [[1, 0, 2, 0], [0, 1, 0, 2], [3, 0, 4, 0], [0, 3, 0, 4]]
print(np.kron(I, X).tolist())  # [[1, 2, 0, 0], [3, 4, 0, 0], [0, 0, 1, 2], [0, 0, 3, 4]]
```

</CodeTabs>

`kron(I, X)` repeats $X$ down the diagonal. `kron(X, I)` spreads the entries of $X$ apart. Matrices made of zeros and ones are the usual way to stamp out repeated copies like this.

## Where you'll meet this

<ApplicationsGrid>
<PracticalApplication title="Simulating quantum computers" tool="Qiskit">
The combined state of several qubits is the Kronecker product of their individual states. Each added qubit doubles the size, which is why simulating many qubits gets expensive so quickly.
</PracticalApplication>
<PracticalApplication title="Solving equations on a grid" tool="Scientific computing">
The matrix for a 2D heat or Laplace problem can be assembled from 1D matrices using `kron`, which saves writing out a huge sparse matrix by hand.
</PracticalApplication>
