# What Is Cryptography?

Everything from the [last module](/courses/computational-mathematics/divisibility-and-euclid) was preparation for this one. Number theory gives us operations that are [easy to do and hard to undo](/courses/computational-mathematics/discrete-logarithms#a-one-way-street) without a secret, and cryptography puts them to work.

## The vocabulary

- **Cryptography** (from the Greek *kryptos*, "hidden", and *graphein*, "to write") is the study of how to conceal information in a ciphertext, so that only the legitimate users holding the key can recover it, while making it impossible or computationally infeasible for an unauthorized person to do so.
- **Cryptanalysis** (from *kryptos* and *analyein*, "to loosen") is the science and art of recovering information from ciphertext without knowing the key.
- **Cryptology** (from *kryptos* and *logos*, "word") is the broader field that covers both. Within cryptography sit symmetric ciphers, asymmetric ciphers and cryptographic **protocols** (multi-step exchanges such as key agreement and authentication handshakes).

Modern cryptography solves two main security problems:

1. **Privacy** stops unauthorised parties from reading messages sent over a public channel. The sender can be sure that only the intended receiver can read it. Every question you type to a hosted AI model travels this way, encrypted with TLS, and medical or financial training data is kept encrypted when it's stored and when it moves.
2. **Authentication** stops unauthorised parties from injecting messages. The receiver can be sure who sent it. A signed model file, for example, shows that the weights you downloaded really came from the lab that published them.

Cryptanalysis also helped create the modern computer. At Bletchley Park in the Second World War, Alan Turing helped design the Bombe, an electromechanical machine for breaking Enigma, and Tommy Flowers built Colossus, one of the first programmable electronic computers, to attack another German cipher.

Machine learning has been pointed at the problem too. In 2016, researchers at Google trained one neural network to encrypt messages for a second while a third tried to eavesdrop, and the first two learned a scheme the third couldn't read. It's a striking result, but nobody protects real data with learned ciphers, because they come with no proof of security. Real systems use ciphers whose strength rests on mathematics like the number theory in this course.

## Two kinds of system

Cryptographic systems (also called **cryptosystems**, **cryptographic schemes** or **ciphers**) split into two families:

- **Secret-key** (or **symmetric**, or **conventional**) systems use the same key to encrypt and decrypt.
- **Public-key** (or **asymmetric**) systems use a public key to encrypt and a different private key to decrypt.

## The notation

A cryptosystem has these parts:

- $M$, the **message space**: a set of plaintext strings over some alphabet to be encrypted.
- $C$, the **ciphertext space**: a set of encrypted strings over some alphabet.
- $K$, the **key space**: a set of possible keys, including an encryption key $e_k$ and a decryption key $d_k$.
- $E$, the encryption process (algorithm): $E_{e_k}(m) = c$.
- $D$, the decryption process (algorithm): $D_{d_k}(c) = m$.

The two algorithms have to undo each other, for every message:

$$
D_{d_k}(c) = D_{d_k}(E_{e_k}(m)) = m
$$

In code, that's two functions that undo each other. Here $E$ shifts each letter $k$ places along the alphabet and $D$ shifts it back, a cipher you'll take apart in [Caesar and Shift Ciphers](/courses/computational-mathematics/caesar-and-shift-ciphers):

<CodeTabs>

```matlab
E = @(k, m) char(mod(double(m) - 65 + k, 26) + 65);   % 'A' is character 65
D = @(k, c) E(-k, c);

E(3, 'HELLO')          % KHOOR
D(3, E(3, 'HELLO'))    % HELLO
```

```python
def E(k, m):
    return "".join(chr((ord(ch) - 65 + k) % 26 + 65) for ch in m)  # "A" is character 65

def D(k, c):
    return E(-k, c)

print(E(3, "HELLO"))  # KHOOR
print(D(3, E(3, "HELLO")))  # HELLO
```

</CodeTabs>

## Secret-key systems

In a conventional secret-key system, $e_k = d_k = k \in K$, called the **secret key**. Anyone who has enough information to encrypt messages automatically has enough information to decrypt them as well, so the key must travel to the legitimate receiver over a separate secure channel.

Written as a mapping, the sender applies an invertible transformation $f$ determined by $k$,

$$
f \colon M \xrightarrow{k} C, \qquad c = E_k(m), \quad m \in M,\ c \in C
$$

and sends $c$ over the public insecure channel. The receiver applies the inverse transformation $f^{-1}$,

$$
f^{-1} \colon C \xrightarrow{k} M, \qquad D_k(c) = D_k(E_k(m)) = m
$$

to recover the original plaintext. Follow one message through:

The ciphertext crosses the insecure channel in full view, so all the security rests on the key.

So the key has to be truly unpredictable, and that rules out the random numbers you use for everything else. The generators in MATLAB and NumPy are built to be **reproducible**: give them the same seed and they replay the same numbers, which is exactly what you want when you shuffle training data and exactly what a key must never do.

<CodeTabs>

```matlab
% rand and randi are reproducible on purpose: rng(42) replays them exactly.
% MATLAB has no secure generator built in, so real keys come from the
% operating system or a cryptography library, never from rand.
rng(42);  a = randi(255, 1, 4);
rng(42);  b = randi(255, 1, 4);
isequal(a, b)          % true: fine for experiments, fatal for keys
```

```python
import secrets

# The secrets module draws from the operating system's secure generator.
# Never make keys with the random module: like MATLAB's rand, it's
# designed to be reproducible.
key = secrets.token_bytes(16)  # a 128-bit key
print(len(key))  # 16
```
