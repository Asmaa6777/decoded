# Fast Exponentiation

RSA has to compute things like $a^m \bmod n$ where $m$ has hundreds of digits. Multiplying $m - 1$ times would take longer than the age of the universe, and yet your browser does it in milliseconds. The trick is a tiny algorithm that reads $m$ in [binary](/courses/logic-design/number-systems).

## Why the naive way fails

The obvious method is to multiply by $a$ over and over, [reducing modulo $n$](/courses/computational-mathematics/modular-arithmetic#you-can-reduce-at-any-time) after each step. Reducing keeps the numbers small, but it still takes $m - 1$ multiplications.

## Square and multiply

Write $m$ in binary and read it from left to right. Start with $a$ for the first bit. For each bit after that:

- **Always** square the running value.
- If the bit is **1**, also multiply by $a$.

Why does binary representation make this work? Any exponent $m$ decomposes into powers of 2: $m = \sum_{i=0}^k b_i 2^i$, with bits $b_i \in \{0, 1\}$. Reading from left to right, squaring the accumulator doubles its exponent ($(a^k)^2 = a^{2k}$), which shifts the binary exponent left by one bit. If the next bit is 1, multiplying by $a$ adds 1 ($a^{2k} \cdot a = a^{2k+1}$). When the bit is 0, no multiplication is performed. Reducing modulo $n$ after each step keeps intermediate values below $n^2$.

For $a^{100}$, we have $100 = (1100100)_2$, so the bits build the exponent like this:

| Bit | Operation | Power so far |
| --- | --- | --- |
| 1 | start | $a^1$ |
| 1 | square, multiply | $a^3$ |
| 0 | square | $a^6$ |
| 0 | square | $a^{12}$ |
| 1 | square, multiply | $a^{25}$ |
| 0 | square | $a^{50}$ |
| 0 | square | $a^{100}$ |

Squaring doubles the exponent, which shifts its binary form left, and multiplying by $a$ sets the new last bit to 1.

For $25^{193} \bmod 469$, the binary form of the exponent is $193 = (11000001)_2 = e_7 e_6 e_5 e_4 e_3 e_2 e_1 e_0$. The eight bit steps evaluate as follows:

| Bit | Value | Operation | Computation modulo 469 | Reduced |
| --- | --- | --- | --- | --- |
| $e_7$ | 1 | start | $25 \bmod 469$ | 25 |
| $e_6$ | 1 | square, multiply | $25^2 = 625 \equiv 156$; $156 \cdot 25 = 3900 \equiv 148$ | 148 |
| $e_5$ | 0 | square | $148^2 = 21904 = 46 \cdot 469 + 330$ | 330 |
| $e_4$ | 0 | square | $330^2 = 108900 = 232 \cdot 469 + 92$ | 92 |
| $e_3$ | 0 | square | $92^2 = 8464 = 18 \cdot 469 + 22$ | 22 |
| $e_2$ | 0 | square | $22^2 = 484 = 1 \cdot 469 + 15$ | 15 |
| $e_1$ | 0 | square | $15^2 = 225 < 469$ | 225 |
| $e_0$ | 1 | square, multiply | $225^2 \equiv 442 \equiv -27$; $(-27) \cdot 25 = -675 \equiv 263$ | 263 |

Therefore $25^{193} \equiv 263 \pmod{469}$. Reducing between the square and the multiplication keeps numbers small: instead of computing $225^2 \cdot 25 = 1265625$, reducing $225^2 \equiv 442 \equiv -27$ allows computing $(-27) \cdot 25 = -675 \equiv 263 \pmod{469}$ by hand.

<CodeTabs>

```matlab
a = 25;  m = 193;  n = 469;
bits = dec2bin(m);                % '11000001'
r = mod(a, n);                    % the first bit: start with a
for i = 2:length(bits)
    r = mod(r * r, n);            % always square
    if bits(i) == '1'
        r = mod(r * a, n);        % multiply on a 1
    end
end
r                                 % powermod(25, 193, 469) gives the same

r =
   263
```

```python
def fast_pow(a, m, n):
    r = a % n                      # the first bit: start with a
    for bit in bin(m)[3:]:         # bin(193) is '0b11000001'; [3:] skips '0b' and the first 1
        r = r * r % n              # always square
        if bit == "1":
            r = r * a % n          # multiply on a 1
    return r

print(fast_pow(25, 193, 469))  # 263
# Python's built-in three-argument pow does the same
print(pow(25, 193, 469))  # 263
```

</CodeTabs>

## How much it saves

The number of multiplications scales with the binary length of $m$, roughly $\log_2 m$, instead of $m$ itself. A 2048-bit exponent takes at most about 4,096 multiplications, avoiding a 600-digit number of operations. Advanced Algorithms analyses this strategy as [divide and conquer](/courses/advanced-algorithms/divide-and-conquer), applying it to matrices to compute Fibonacci numbers.

Repeated squaring applies to any associative multiplication, including square matrices in machine learning. A **Markov chain** transitions between discrete states with specified probabilities recorded in a **transition matrix** $P$. The power $P^k$ gives the state distribution after $k$ steps, and high powers reveal the stationary distribution. Google's original **PageRank** algorithm used this stationary share. Computing 64 steps requires only 6 squarings:

<CodeTabs>

```matlab
P = [0.9 0.1; 0.5 0.5];    % from state 1: stay 90%, move 10%
P^64                       % ^ on a matrix squares repeatedly (matrix power, not P.^64)

ans =
    0.8333    0.1667
    0.8333    0.1667
```

```python
import numpy as np

P = np.array([[0.9, 0.1], [0.5, 0.5]])

# matrix_power squares repeatedly; P ** 64 would raise each entry instead
print(np.round(np.linalg.matrix_power(P, 64)[0], 4).tolist())  # [0.8333, 0.1667]
```

</CodeTabs>

Both rows converge to identical distributions: regardless of starting state, the chain spends five-sixths of its time in state 1. **Diffusion models** use an analogous shortcut. Image generation trains across hundreds of noise steps. Instead of simulating each noise step sequentially, a closed-form equation evaluates any arbitrary timestep directly.

<Callout tone="orange" label="Common errors">
- **Forgetting to square on bit 1:** A common mistake assumes bit 0 means square and bit 1 means multiply. Every bit after the first requires squaring. A bit value of 1 adds a multiplication by $a$ right after the squaring step.
- **Processing bits in the wrong direction:** Left-to-right square-and-multiply begins at the most significant bit and multiplies into the squared total. Right-to-left begins at the least significant bit and squares the base into an accumulator. Mixing the two produces incorrect results.
- **Reducing exponents modulo $n$:** Exponents do not reduce modulo $n$ ($a^m \bmod n \ne a^{m \bmod n} \bmod n$).
- **Writing `mod(a^m, n)` in code:** In MATLAB, `mod(25^193, 469)` is incorrect. The value `25^193` overflows double-precision floats, discarding lower digits before `mod` executes. Use `powermod(25, 193, 469)` or reduce at each step. In Python, prefer `pow(a, m, n)` over `a**m % n`.
</Callout>
