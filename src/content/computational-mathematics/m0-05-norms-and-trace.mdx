# Matrix Norms and the Trace

How big is a matrix? Its number of rows doesn't answer that, because a 3-by-3 matrix of tiny values and one of huge values are the same size. A **norm** reduces a matrix to one non-negative number that measures the magnitude of its entries.

## What every norm promises

There are several norms, but all the ones here share these properties, for any scalar $k$:

1. $\|A\| \ge 0$
2. $\|A\| = 0$ only when $A$ is the zero matrix
3. $\|kA\| = |k|\,\|A\|$
4. $\|A + B\| \le \|A\| + \|B\|$, the triangle inequality
5. $\|AB\| \le \|A\|\,\|B\|$

## Three norms to know

The **1-norm** is the largest absolute column sum:

$$
\|A\|_1 = \max_{j} \sum_{i=1}^{n} |a_{ij}|
$$

The **infinity-norm** is the largest absolute row sum:

$$
\|A\|_\infty = \max_{i} \sum_{j=1}^{n} |a_{ij}|
$$

A handy way to remember them: "1" is tall and thin like a column, and "∞" is short and wide like a row.

The **Euclidean norm** is the square root of the sum of every entry squared. It's Pythagoras applied to the whole matrix:

$$
\|A\|_E = \sqrt{\sum_{i=1}^{n} \sum_{j=1}^{n} a_{ij}^2}
$$

All three use the same matrix below, and they don't agree. There's no single true size, so you pick the norm that suits the problem:

B = [5 -4 2; -1 2 3; -2 1 0];

```python
import numpy as np

B = np.array([[5, -4, 2], [-1, 2, 3], [-2, 1, 0]])

print(np.linalg.norm(B, 1))  # 8.0
print(np.linalg.norm(B, np.inf))  # 11.0
print(np.linalg.norm(B, "fro"))  # 8.0

# The defaults differ: with no second argument, np.linalg.norm(B) is the
# Euclidean (Frobenius) norm, while MATLAB's norm(B) is the 2-norm.

# In pandas each definition reads as a sum and a max:
import pandas as pd

df = pd.DataFrame(B)
print(df.abs().sum(axis=0).max())  # 8
print(df.abs().sum(axis=1).max())  # 11
```

</CodeTabs>

<Callout tone="orange" label="Watch the name in MATLAB">
Many books call this the Frobenius norm, and MATLAB does too: use `norm(A, 'fro')`. Plain `norm(A)` computes something else, the 2-norm, which is the largest singular value of $A$.
</Callout>

Norms are how machine learning keeps a model under control while it trains:

- **Regularization.** A model with huge weights tends to memorise its training data instead of learning the pattern. **Weight decay** adds the squared Euclidean norm of the weights to the loss, so training pays a price for large weights. **Lasso** adds the sum of absolute values instead, which tends to push unhelpful weights to exactly zero. Note that this "L1 penalty" sums all the entries, so it isn't the matrix 1-norm above.
- **Gradient clipping.** Now and then a gradient comes out enormous, and one step that size would wreck the weights learned so far. So if the gradient's norm passes a limit, the gradient is scaled back down to that length, keeping its direction. Large language models are trained with this switched on.

<CodeTabs>

```matlab
g = [30 40];
limit = 5;

clipped = g * min(1, limit / norm(g))

clipped =
     3     4
```

```python
import numpy as np

g = np.array([30.0, 40.0])
limit = 5.0

clipped = g * min(1.0, limit / np.linalg.norm(g))
print(clipped.tolist())  # [3.0, 4.0]
```

</CodeTabs>

## The trace

The **trace** of a square matrix is the sum of its main diagonal:

$$
\operatorname{tr}(A) = \sum_{i=1}^{n} a_{ii} = a_{11} + a_{22} + \cdots + a_{nn}
$$

For `magic(4)`, `trace` returns $16 + 11 + 6 + 1 = 34$, which is also what every row and column of that matrix adds up to.

<CodeTabs>

```matlab
trace(magic(4))

ans =
    34
```

```python
import numpy as np

M = np.array([[16, 2, 3, 13], [5, 11, 10, 8], [9, 7, 6, 12], [4, 14, 15, 1]])
print(np.trace(M))  # 34
```

</CodeTabs>

The trace has a job in data science too. The diagonal of a covariance matrix holds the variance of each feature, so its trace is the **total variance** of the data. PCA divides that total up when it reports how much of the variation each of its components explains, and that's how you decide how many dimensions you can safely throw away.
