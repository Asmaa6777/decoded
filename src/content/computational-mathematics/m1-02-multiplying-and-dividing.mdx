# Multiplying and Dividing Polynomials

Multiply two polynomials by hand and you collect like terms. Do that on coefficient vectors and you've performed a **convolution**, an operation that also runs image filters, audio effects and the networks that recognise faces.

## Convolution

Take $a(s) = s^2 + 2s + 3$ and $b(s) = 4s^2 + 5s + 6$. The coefficient of $s^n$ in the product comes from every pair of powers adding up to $n$:

$$
c_n = \sum_{i} a_i \, b_{n-i}
$$

Picture $b$ flipped and sliding past $a$. Wherever they overlap, multiply the pairs and add. That's a [dot product](/courses/computational-mathematics/transpose-and-products#the-dot-product) of the overlapping parts, so each coefficient of the answer is one dot product:

<ConvolutionVisualizer />

<CodeTabs>

```matlab
a = [1 2 3];  b = [4 5 6];
c = conv(a, b)

c =
     4    13    28    27    18
```

```python
import numpy as np

print(np.convolve([1, 2, 3], [4, 5, 6]).tolist())  # [4, 13, 28, 27, 18]

# Without NumPy it's the definition: every pair of positions adds into c[i + j]
a, b = [1, 2, 3], [4, 5, 6]
c = [0] * (len(a) + len(b) - 1)
for i, x in enumerate(a):
    for j, y in enumerate(b):
        c[i + j] += x * y
print(c)  # [4, 13, 28, 27, 18]
```

</CodeTabs>

So the product is $4s^4 + 13s^3 + 28s^2 + 27s + 18$. If $a$ has degree $m$ and $b$ has degree $n$, the result has degree $m + n$.

The same slide-multiply-add runs through machine learning. A **moving average**, the most common way to smooth a noisy series before forecasting, is a convolution with equal weights. Averaging each pair of neighbours means sliding $[0.5,\ 0.5]$ along the data:

<CodeTabs>

```matlab
s = [2 4 6 8];
conv(s, [0.5 0.5], 'valid')   % 'valid' keeps only full overlaps

ans =
     3     5     7
```

```python
import numpy as np
import pandas as pd

s = pd.Series([2.0, 4.0, 6.0, 8.0])

print(np.convolve(s, [0.5, 0.5], mode="valid").tolist())  # [3.0, 5.0, 7.0]
# pandas calls it a rolling mean; the first value has no full window yet
print(s.rolling(2).mean().dropna().tolist())  # [3.0, 5.0, 7.0]
```

</CodeTabs>

When averages like these feed a forecasting model, each one must use only past values. A window that reaches forward lets the model peek at the future during training, and it then looks far better in testing than it will ever be in real use.

Slide a small grid of weights across an image instead of a list, and you get **convolution in two dimensions**: the blur in a photo editor, and the core of a **convolutional neural network**. A CNN learns its own grids of weights, called filters. Early ones end up detecting edges and textures, later ones eyes and wheels, and a pattern counts the same wherever it appears in the picture because the same filter slides over every position. Frameworks usually skip the flip, so strictly they compute a correlation, but everyone still calls it convolution. The flip makes no practical difference when the weights are learned.

## Deconvolution

`deconv` runs this backwards, which is polynomial long division. It returns the quotient and the remainder:

<CodeTabs>

```matlab
a = [1 2 3];
c = [4 13 28 27 18];
[q, r] = deconv(c, a)

q =
     4     5     6
r =
     0     0     0     0     0
```

```python
import numpy as np

q, r = np.polydiv([4, 13, 28, 27, 18], [1, 2, 3])

print(np.round(q).astype(int).tolist())  # [4, 5, 6]
print(np.allclose(r, 0))  # True
```

</CodeTabs>

A remainder of all zeros tells you that $a$ divides $c$ exactly. This also gives a quick test for a [root](/courses/computational-mathematics/polynomials-and-roots#roots): $r$ is a root of $p$ exactly when `deconv(p, [1 -r])` leaves no remainder.
