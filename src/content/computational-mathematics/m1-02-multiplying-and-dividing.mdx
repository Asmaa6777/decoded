# Multiplying and Dividing Polynomials

Multiply two polynomials by hand and you collect like terms. Do that on coefficient vectors and you've performed a **convolution**, an operation that also runs image filters, audio effects and the networks that recognise faces.

## Convolution

Take $a(s) = s^2 + 2s + 3$ and $b(s) = 4s^2 + 5s + 6$. The coefficient of $s^n$ in the product comes from every pair of powers adding up to $n$:

$$
c_n = \sum_{i} a_i \, b_{n-i}
$$

Here $a_i$ means the coefficient of $s^i$, so $a_0 = 3$, $a_1 = 2$, $a_2 = 1$ and $b_0 = 6$, $b_1 = 5$, $b_2 = 4$. The coefficient of $s^2$ in the product collects every way to make $s^2$: a constant times an $s^2$, an $s$ times an $s$, and an $s^2$ times a constant:

$$
\begin{aligned} c_2 &= a_0 b_2 + a_1 b_1 + a_2 b_0 \\ &= (3)(4) + (2)(5) + (1)(6) = 28 \end{aligned}
$$

As $a$'s power goes up, $b$'s goes down. That's why convolution is often pictured with $b$ flipped. Picture $b$ flipped and sliding past $a$. Wherever they overlap, multiply the pairs and add. That's a [dot product](/courses/computational-mathematics/transpose-and-products#the-dot-product) of the overlapping parts, so each coefficient of the answer is one dot product:

<ConvolutionVisualizer />

<CodeTabs>

```matlab
a = [1 2 3];  b = [4 5 6];
c = conv(a, b)

c =
     4    13    28    27    18
```

```python
import numpy as np

print(np.convolve([1, 2, 3], [4, 5, 6]).tolist())  # [4, 13, 28, 27, 18]

# Without NumPy it's the definition: every pair of positions adds into c[i + j]
a, b = [1, 2, 3], [4, 5, 6]
c = [0] * (len(a) + len(b) - 1)
for i, x in enumerate(a):
    for j, y in enumerate(b):
        c[i + j] += x * y
print(c)  # [4, 13, 28, 27, 18]
```

</CodeTabs>

So the product is $4s^4 + 13s^3 + 28s^2 + 27s + 18$. If $a$ has degree $m$ and $b$ has degree $n$, the result has degree $m + n$. The highest power comes from multiplying the two highest powers: $s^m \cdot s^n = s^{m+n}$.

<Callout tone="orange" label="Common mistake">
Multiplying the coefficient vectors entry by entry. `[1 2 3] .* [4 5 6]` gives `[4 10 18]`, which is not the product. Every term of one polynomial multiplies every term of the other, so the answer is longer than either input: two vectors of length 3 give a vector of length 5.
</Callout>

The same slide, multiply and add appears all over machine learning. A **moving average**, the most common way to smooth a noisy series before forecasting, is a convolution with equal weights. Averaging each pair of neighbours means sliding $[0.5,\ 0.5]$ along the data:

<CodeTabs>

```matlab
s = [2 4 6 8];
conv(s, [0.5 0.5], 'valid')   % 'valid' keeps only full overlaps

ans =
     3     5     7
```

```python
import numpy as np
import pandas as pd

s = pd.Series([2.0, 4.0, 6.0, 8.0])

print(np.convolve(s, [0.5, 0.5], mode="valid").tolist())  # [3.0, 5.0, 7.0]
# pandas calls it a rolling mean; the first value has no full window yet
print(s.rolling(2).mean().dropna().tolist())  # [3.0, 5.0, 7.0]
```

</CodeTabs>

When averages like these feed a forecasting model, each one must use only past values. A window that reaches forward lets the model see the future during training. It then scores much better in testing than it ever will in real use.

Slide a small grid of weights across an image instead of a list, and you get **convolution in two dimensions**. It's the blur in a photo editor, and the core of a **convolutional neural network** (CNN). A CNN learns its own grids of weights, called filters. Early filters learn to detect edges and textures, later ones eyes and wheels. Because the same filter slides over every position, a pattern counts the same wherever it appears in the picture. Frameworks usually skip the flip, so strictly they compute a correlation, but everyone still calls it convolution. The flip makes no practical difference when the weights are learned.

## Deconvolution

`deconv` runs this backwards, which is polynomial long division. It works like long division of numbers: divide the leading terms, multiply back, subtract, and repeat. Dividing $x^2 + 3x + 5$ by $x + 1$:

1. $x^2 \div x = x$, the first term of the quotient. Multiply back: $x(x + 1) = x^2 + x$. Subtract: $(x^2 + 3x + 5) - (x^2 + x) = 2x + 5$.
2. $2x \div x = 2$, the next term. Multiply back: $2(x + 1) = 2x + 2$. Subtract: $(2x + 5) - (2x + 2) = 3$.
3. $3$ has a lower degree than $x + 1$, so it's the remainder.

Step through the same division. Each column holds one power of $x$, so subtracting is just subtracting column by column:

<LongDivisionVisualizer />

So $x^2 + 3x + 5 = (x + 2)(x + 1) + 3$. MATLAB returns the remainder padded with zeros to the length of the original vector:

<CodeTabs>

```matlab
[q, r] = deconv([1 3 5], [1 1])

q =
     1     2
r =
     0     0     3
```

```python
import numpy as np

q, r = np.polydiv([1, 3, 5], [1, 1])
print(q.tolist(), r.tolist())  # [1.0, 2.0] [3.0]
```

</CodeTabs>

NumPy's `polydiv` drops the leading zeros of the remainder, which MATLAB keeps. Dividing the product from before by $a$ gives back $b$ with nothing left over:

<CodeTabs>

```matlab
a = [1 2 3];
c = [4 13 28 27 18];
[q, r] = deconv(c, a)

q =
     4     5     6
r =
     0     0     0     0     0
```

```python
import numpy as np

q, r = np.polydiv([4, 13, 28, 27, 18], [1, 2, 3])

print(np.round(q).astype(int).tolist())  # [4, 5, 6]
print(np.allclose(r, 0))  # True
```

</CodeTabs>

A remainder of all zeros tells you that $a$ divides $c$ exactly. This also gives a quick test for a [root](/courses/computational-mathematics/polynomials-and-roots#roots): $r$ is a root of $p$ exactly when `deconv(p, [1 -r])` leaves no remainder. The reason is that dividing by $x - r$ always leaves a remainder equal to $p(r)$. In the division above, $x + 1$ is $x - (-1)$, and the remainder 3 is exactly $p(-1) = 1 - 3 + 5$. So the remainder is zero exactly when $p(r) = 0$.
