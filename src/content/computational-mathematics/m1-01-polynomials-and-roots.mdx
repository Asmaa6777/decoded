# Polynomials and Their Roots

MATLAB has no special polynomial type. A polynomial is just a [row vector](/courses/computational-mathematics/matrices-and-matlab#writing-a-matrix-down) of its coefficients, in descending powers. So everything from the [matrix module](/courses/computational-mathematics/matrices-and-matlab) applies: a polynomial is data you can store, pass around and do arithmetic on.

## Writing one down

The polynomial

$$
p(x) = x^3 - 2x^2 - x + 2
$$

is entered as:

<CodeTabs>

```matlab
p = [1 -2 -1 2];
```

```python
# NumPy kept MATLAB's convention: coefficients in descending powers
p = [1, -2, -1, 2]

# (The newer numpy.polynomial.Polynomial class stores them the other way
# round, lowest power first. Check which one a library expects.)
```

</CodeTabs>

Missing powers still need a place. $x^3 - 2x - 5$ has no $x^2$ term, so its vector is `[1 0 -2 -5]`, with an explicit zero.

Polynomials are also the oldest trick for making a straight-line model bend. A linear model can only fit $y = w_0 + w_1 x$, but add $x^2$ and $x^3$ as extra input columns and it fits a cubic. These **polynomial features** keep the model linear in its weights, so the same solver still works, and it's often the first thing to try when a straight line underfits.

## Roots

A **root** is a value of $x$ where $p(x) = 0$, which is where the curve crosses the x-axis. `roots` returns them as a [column vector](/courses/computational-mathematics/matrices-and-matlab#writing-a-matrix-down), and `poly` goes the other way:

<CodeTabs>

```matlab
p = [1 -2 -1 2];
r = roots(p)      % -1, 2 and 1

p2 = poly(r)      % 1  -2  -1  2
```

```python
import numpy as np

p = [1, -2, -1, 2]

print(np.round(np.sort(np.roots(p)), 6).tolist())  # [-1.0, 1.0, 2.0]
print(np.round(np.poly([-1, 2, 1]), 6).tolist())  # [1.0, -2.0, -1.0, 2.0]
```

</CodeTabs>

These two are inverse functions, up to ordering, scaling and rounding error.

Root finding is quietly at the centre of training a model. A loss is lowest where its slope is flat, at a point where the [derivative](/courses/computational-mathematics/derivatives-and-curve-fitting#derivatives) is zero. So **minimising a loss means finding a root of its derivative**, and every optimizer, from gradient descent to the ones that train large language models, is in effect hunting for a root of the gradient.

## Evaluating

`polyval(p, 3)` works out $p(3) = 27 - 18 - 3 + 2 = 8$. Drag the sliders and see the roots move. When the curve lifts off the axis, the real roots disappear, and they turn up again as a complex pair:

<PolynomialExplorer />

<CodeTabs>

```matlab
polyval([1 -2 -1 2], 3)

ans =
     8
```

```python
import numpy as np

print(np.polyval([1, -2, -1, 2], 3))  # 8

# polyval uses Horner's method: one multiplication per coefficient.
# It's short enough to write in plain Python:
def polyval(p, x):
    result = 0
    for c in p:
        result = result * x + c
    return result

print(polyval([1, -2, -1, 2], 3))  # 8
```

</CodeTabs>

<Callout tone="sky" label="Why roots returns complex numbers">
A polynomial of degree $n$ always has exactly $n$ roots if you count repeats and allow complex values. $x^2 + 1$ never touches the x-axis, yet it still has two roots, $i$ and $-i$.
</Callout>

## Evaluating at a matrix

`polyvalm` puts a square matrix where $x$ was. Its powers are [matrix products](/courses/computational-mathematics/multiplying-matrices#the-rule), so $X^3$ means $X \cdot X \cdot X$, not each entry cubed. The constant term has to become a matrix as well, so it's multiplied by the [identity](/courses/computational-mathematics/multiplying-matrices#the-identity-matrix):

$$
p(x) = x^3 - 2x - 5 \quad\text{becomes}\quad p(X) = X^3 - 2X - 5I
$$

<CodeTabs>

```matlab
p = [1 0 -2 -5];
X = [2 4 5; -1 0 3; 7 1 5];
Y = polyvalm(p, X)

Y =
   377   179   439
   111    81   136
   490   253   639
```

```python
import numpy as np

X = np.array([[2, 4, 5], [-1, 0, 3], [7, 1, 5]])

# NumPy has no polyvalm, so write the matrix polynomial out.
# matrix_power(X, 3) is X @ X @ X; X**3 would cube each entry instead.
Y = np.linalg.matrix_power(X, 3) - 2 * X - 5 * np.eye(3, dtype=int)
print(Y.tolist())  # [[377, 179, 439], [111, 81, 136], [490, 253, 639]]
```

</CodeTabs>

Note that this differs from `polyval(p, X)`, which evaluates the polynomial separately on each entry.

Matrices and polynomials meet again in **eigenvalues**. Some directions are only stretched by a matrix, never turned, and the stretch factors along them are its eigenvalues. They're the roots of a polynomial built from the matrix, its **characteristic polynomial**, which `poly` returns when you give it a square matrix. PCA ranks the directions in a dataset by exactly these numbers:

<CodeTabs>

```matlab
A = [2 1; 1 2];
c = poly(A)       % characteristic polynomial: x^2 - 4x + 3
roots(c)          % its roots, the eigenvalues: 3 and 1
```

```python
import numpy as np

A = np.array([[2.0, 1.0], [1.0, 2.0]])
c = np.poly(A)

print(np.round(c, 6).tolist())  # [1.0, -4.0, 3.0]
print(np.round(np.sort(np.roots(c)), 6).tolist())  # [1.0, 3.0]
```

</CodeTabs>

Real libraries don't compute eigenvalues this way, because polynomial roots are numerically touchy. In fact `roots` works the other way round: it builds a matrix whose characteristic polynomial is $p$, and computes that matrix's eigenvalues with `eig`.

## Where you'll meet this

<ApplicationsGrid>
<PracticalApplication title="Checking if a system is stable" tool="Control engineering">
A linear system's behaviour depends on the roots of its characteristic polynomial. If any root has a positive real part, its output grows without limit.
</PracticalApplication>
<PracticalApplication title="Finding where curves meet" tool="Font and vector rendering">
Bézier curves are polynomials. Finding where a ray or line crosses one, as renderers do to fill glyphs and shapes, comes down to finding roots.
</PracticalApplication>
