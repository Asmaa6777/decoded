# Greedy Algorithms: Prim and Kruskal

Earlier lessons focused on specific algorithms. This module looks at general strategies for designing algorithms. The first strategy is one people often use by instinct: **always grab the best option available right now.**

## The greedy approach

A greedy algorithm constructs a solution **one step at a time**. At each step, it extends the partial solution built so far by making a choice that satisfies three properties:

1. **Feasible:** it satisfies all the constraints of the problem.
2. **Locally optimal:** it is the best choice available *at this step*.
3. **Irrevocable:** once made, the choice is never undone or reconsidered.

The third rule keeps greedy algorithms fast and simple, because they never backtrack or explore alternative branches. However, this same rule explains why greedy algorithms can fail. A greedy algorithm picks the **local optimum** (the best immediate choice) in the hope that these choices combine to produce the **global optimum** (the best overall solution).

## When greedy fails

Consider making change for an amount of 6 using the smallest number of coins possible, when coins are available in values 1, 3, and 4.

A greedy cashier always picks the largest coin that does not exceed the remaining total: first **4**, leaving 2. Then **1**, and then another **1**, giving three coins: 4 + 1 + 1.

Using **3 + 3** requires only two coins. Grabbing 4 looked best at the initial step, but it forced an inferior total. Because greedy algorithms never backtrack, they cannot correct that early mistake.

<CoinChangeGreedy system="small" />

Try other target amounts with coins 1, 3, and 4 (totals of 10 and 14 fail too), then switch to standard US currency, where greedy change-making never fails.

Real-world currency systems like 1, 5, 10, and 25 cents were chosen specifically so greedy change-making always yields the minimum number of coins.

Greedy algorithms offer clear benefits: they are simple to describe, easy to implement, and often run faster than algorithms that search multiple alternatives. Their main limitation is that they **do not always produce the optimal solution**. For each problem, you must mathematically prove that local choices guarantee a globally optimal outcome, or decide to accept an approximate answer.

For certain fundamental problems, greedy choices are provably guaranteed to find the true minimum. Minimum spanning trees are a classic example.

## Minimum spanning trees

Imagine laying cable to connect six buildings. Specific pairs of buildings can be linked, each at a known installation cost. Every building must connect to the network, directly or indirectly, and your goal is to minimize total cable cost.

In graph theory, this network forms a connected, weighted, undirected graph. A [spanning tree](/courses/discrete-mathematics/trees#spanning-trees) is a subset of edges that connects **every** vertex with **no cycles** (a cycle would mean paying for redundant cable). For a graph with $n$ vertices, every spanning tree contains exactly $n - 1$ edges.

*(Notation note):* In textbooks and exam papers, $n$, $|V|$, and $V$ interchangeably denote the number of vertices in a graph, while $m$, $|E|$, and $E$ denote the number of edges. A spanning tree across $V$ vertices always contains exactly $V - 1$ edges.

To see why, construct the tree one edge at a time. Begin with $n$ isolated vertices, representing $n$ separate components. Each edge that does not form a cycle connects two separate components into one, reducing the component count by exactly 1. Reducing $n$ components to 1 single connected component takes exactly $n - 1$ edges. Adding any further edge would connect two vertices that are already linked, creating a cycle.

The **minimum spanning tree (MST)** is the spanning tree that has the smallest total edge weight.

Two classic greedy algorithms find minimum spanning trees: Prim's algorithm and Kruskal's algorithm. Both algorithms are guaranteed to find an optimal minimum spanning tree every time.

The examples below trace both algorithms on a graph with six vertices, a to f, and ten weighted edges: ab = 3, bc = 1, bf = 4, cf = 4, af = 5, df = 5, ae = 6, cd = 6, ef = 2, and de = 8.

## Prim's algorithm: grow one tree

Prim's algorithm builds a single tree outward from an initial vertex:

1. Start the tree with any single vertex. Any starting vertex produces a valid minimum spanning tree.
2. Examine every edge that connects a vertex **in** the tree to a vertex **not yet** in the tree.
3. Select the **cheapest** of those crossing edges, and add it along with its endpoint vertex to the tree.
4. Repeat this process until every vertex belongs to the tree.

In the visualizer, dotted neon edges indicate candidate crossing edges at each step. Prim always selects the lowest-weight crossing edge, expanding the tree by one vertex each turn.

You can trace the algorithm step by step using a priority table. Each vertex outside the tree keeps a label $(p, w)$ recording its closest parent $p$ currently in the tree and the weight $w$ of that connecting edge. If no edge connects that vertex to the current tree yet, its label is $(-, \infty)$.

**The relaxation rule:** Whenever a newly selected vertex $u$ enters the tree, inspect every neighbor $v$ of $u$ still outside the tree. If edge $(u, v)$ has weight $w(u, v) < \text{label}[v].w$, update $v$'s label to $(u, w(u, v))$. Then, pick the external vertex with the smallest weight label to join the tree next:

| Tree vertex added | Remaining vertices |
| --- | --- |
| a(−, −) | **b(a, 3)**, c(−, ∞), d(−, ∞), e(a, 6), f(a, 5) |
| b(a, 3) | **c(b, 1)**, d(−, ∞), e(a, 6), f(b, 4) |
| c(b, 1) | d(c, 6), e(a, 6), **f(b, 4)** |
| f(b, 4) | d(f, 5), **e(f, 2)** |
| e(f, 2) | **d(f, 5)** |
| d(f, 5) | |

Tracing the label updates:
- When vertex **a** starts the tree, its incident edges set labels for $b(a, 3)$, $e(a, 6)$, and $f(a, 5)$, while $c$ and $d$ remain $(-, \infty)$. The minimum is $b(a, 3)$.
- When vertex **b** joins, edge $bc(1)$ updates $c$ from $(-, \infty)$ to $c(b, 1)$, and edge $bf(4)$ improves $f$'s label from $(a, 5)$ to $(b, 4)$ because $4 < 5$. The minimum is $c(b, 1)$.
- When vertex **c** joins, edge $cd(6)$ updates $d$ from $(-, \infty)$ to $d(c, 6)$. Edge $cf(4)$ matches $f$'s current weight 4, so $f$ remains $(b, 4)$. The minimum among remaining vertices is $f(b, 4)$.
- When vertex **f** joins, edge $fe(2)$ improves $e$ from $(a, 6)$ to $(f, 2)$, and edge $fd(5)$ improves $d$ from $(c, 6)$ to $(f, 5)$. The minimum is $e(f, 2)$.
- When vertex **e** joins, edge $ed(8)$ is examined, but $8 > 5$, so $d$'s label stays $(f, 5)$. The final vertex added is $d(f, 5)$.

The resulting tree consists of edges ab, bc, bf, fe, and fd, with total weight $3 + 1 + 4 + 2 + 5 = 15$.

Here is the pseudocode for Prim's algorithm, where $V_T$ is the set of tree vertices and $E_T$ is the set of tree edges:

```text
ALGORITHM Prim(G)
V_T ← {v0}          // any vertex can start the tree
E_T ← ∅
for i ← 1 to |V| − 1 do
    find a minimum-weight edge e* = (v*, u*) among all edges (v, u)
        such that v is in V_T and u is in V − V_T
    V_T ← V_T ∪ {u*}
    E_T ← E_T ∪ {e*}
return E_T
```

The main loop runs $|V| - 1$ times, adding one tree edge in each iteration.

## Kruskal's algorithm: join the forest

Kruskal's algorithm takes a different approach. Rather than growing a single tree from a starting vertex, it treats every vertex as its own one-node tree (a [forest](/courses/discrete-mathematics/trees#what-a-tree-is)) and joins them together:

1. **[Sort](/courses/algorithm-design-and-analysis/quick-sort#the-idea)** all edges in non-decreasing order of weight.
2. Pick the cheapest remaining edge. If its endpoints belong to two **different** trees, add it to the forest to connect them. If both endpoints are **already in the same tree**, adding it would form a cycle, so **reject** it.
3. Repeat until you have collected $n - 1$ edges.

In the visualizer, orange dashed edges have low weights, but their endpoints were already connected through earlier edges. Adding them would merely create a cycle, so Kruskal discards them.

On the six-vertex example graph, the sorted edges are bc (1), ef (2), ab (3), bf (4), cf (4), af (5), df (5), ae (6), cd (6), and de (8):

| Edge | Weight | Result |
| --- | --- | --- |
| bc | 1 | accept |
| ef | 2 | accept |
| ab | 3 | accept |
| bf | 4 | accept: joins the component containing a, b, c to the component containing e, f |
| cf | 4 | reject: c and f are already connected |
| af | 5 | reject: a and f are already connected |
| df | 5 | accept: fifth edge added, completing the tree |

Kruskal halts as soon as it accepts $|V| - 1 = 5$ edges, without needing to inspect edges ae, cd, or de. In this example, it finds the same tree as Prim, with a total weight of **15**. When edge weights tie, the two algorithms may choose different individual edges, but the total minimum weight remains identical.

Here is the pseudocode for Kruskal's algorithm, tracking edge count with `ecounter` and indexing edges with `k`:

```text
ALGORITHM Kruskal(G)
sort E so that w(e_i1) ≤ … ≤ w(e_i|E|)
E_T ← ∅; ecounter ← 0
k ← 0
while ecounter < |V| − 1 do
    k ← k + 1
    if E_T ∪ {e_ik} is acyclic
        E_T ← E_T ∪ {e_ik}; ecounter ← ecounter + 1
return E_T
```

The condition `is acyclic` checks whether the candidate edge connects two previously disjoint components. In practical implementations, we never run an expensive full graph search (such as BFS or DFS, which would cost $O(V)$ per edge) to test for cycles. Instead, we use the **Disjoint Set Union (Union-Find)** data structure: calling `find(u) != find(v)` verifies that $u$ and $v$ belong to different trees in near $O(1)$ amortized time.

## Worked examples with ties

**Prim, starting from vertex C.** Given edges AB = 4, AC = 4, BC = 2, CD = 3, CE = 2, CF = 4, DF = 3, EF = 3:

| Tree so far | Cheapest edge leaving it | Adds |
| --- | --- | --- |
| C | CB = 2 (tied with CE = 2) | B |
| C, B | CE = 2 | E |
| C, B, E | CD = 3 (tied with EF = 3) | D |
| C, B, E, D | DF = 3 (tied with EF = 3) | F |
| C, B, E, D, F | AB = 4 (tied with AC = 4) | A |

Notice what happens after vertex F joins at step 4: edge EF has weight 3, which is lower than AB (4). However, because both endpoints E and F already belong to the tree ($E, F \in V_T$), edge EF has become an **internal edge**. It no longer crosses the cut to any vertex outside the tree, so it cannot be selected. The cheapest remaining crossing edge connecting the tree to vertex A is AB = 4 (tied with AC = 4).

Total weight is $2 + 2 + 3 + 3 + 4 = 14$. Different tie-breaking decisions may yield different valid trees, but every valid minimum spanning tree has a total weight of 14. In coursework or exam settings, state your tie-breaking rule clearly (here, alphabetical order).

**Kruskal on a separate graph.** Given edges AB = 1, DE = 2, BC = 3, CD = 4, AE = 5, AC = 7, AD = 10:

Sorting the edges gives AB (1), DE (2), BC (3), CD (4), AE (5), AC (7), and AD (10). Kruskal accepts AB (1), DE (2), BC (3), and CD (4). That reaches $5 - 1 = 4$ edges, completing the spanning tree across vertices A, B, C, D, and E with total weight $1 + 2 + 3 + 4 = 10$. The remaining edges AE, AC, and AD are never added because each would close a cycle.

## Why does greedy work here?

The correctness of both algorithms rests on two dual geometric principles:

1. **The Cut Property:** In graph theory, a **cut** partitions the vertices of a graph into two disjoint sets. The cheapest edge crossing between these two sets is always safe to include in a minimum spanning tree. Suppose an optimal spanning tree connects the two sets using a more expensive crossing edge instead. Swapping that expensive edge for the cheapest crossing edge maintains full connectivity across the cut without increasing total weight. Therefore, at least one optimal spanning tree must contain the cheapest crossing edge.
2. **The Cycle Property:** In any cycle of a connected graph, the edge with the strictly largest weight cannot belong to any minimum spanning tree. Kruskal's algorithm leverages this property directly: whenever an edge forms a cycle with previously accepted edges, it is guaranteed to have the highest weight in that cycle (since edges are processed cheapest-first), so discarding it is provably safe.

Prim's algorithm applies the cut property by defining the cut between vertices in the growing tree and vertices outside it. Kruskal's algorithm applies it by defining the cut between a candidate edge's component and the rest of the graph. Because every choice selects an edge that belongs to at least one valid optimal tree, neither algorithm makes an irreversible mistake.

## Analysis

- **Prim's algorithm:** with an adjacency matrix and a simple linear scan for the cheapest crossing edge, the running time is $\Theta(V^2)$. When implemented with an adjacency list and a binary [priority queue](/courses/data-structures/heaps#the-interface), the running time drops to $O(E \log V)$.
- **Kruskal's algorithm:** sorting $|E|$ edges takes $O(E \log E)$. Because a simple graph without multi-edges has at most $E \le V^2$ edges, $\log E \le \log(V^2) = 2 \log V$, meaning $O(E \log E) = O(E \log V)$. Checking whether two vertices share the same component uses a [union-find](/courses/data-structures/union-find#the-interface) disjoint-set data structure: each vertex points to a parent representative, `find` traverses pointers to identify the root, and two vertices share a component when their roots match. Adding an edge links one root to the other, merging their trees. Using path compression and union by rank keeps each operation nearly $O(1)$ amortized time ($O(\alpha(V))$, where the inverse Ackermann function $\alpha(V) \le 4$ for all physical graph sizes). The entire edge-inspection loop runs in $O(E \alpha(V))$ time, which is strictly dominated by the $O(E \log V)$ sorting step.

As a general guideline, choose Prim's algorithm for **dense** graphs, where the edge count approaches the maximum $V(V-1)/2$. Choose Kruskal's algorithm for **sparse** graphs, where the edge count is closer to $V$, because having fewer edges minimizes sorting time.

**Disconnected graphs and spanning forests:** If a graph is disconnected with $k > 1$ components, Prim's algorithm only spans the component containing its initial vertex. Kruskal's algorithm, however, processes all edges globally and naturally constructs a **Minimum Spanning Forest (MSF)** consisting of $V - k$ edges spanning each component independently.

<Callout tone="orange" label="Common mistakes with Prim and Kruskal">
**Confusing candidate edges in Prim:** In Prim's algorithm, every candidate edge must directly attach to the tree constructed so far. Selecting the cheapest edge anywhere in the entire graph is Kruskal's strategy, not Prim's. In the six-vertex example, after selecting edge ab (weight 3), Prim chooses bc (weight 1), and only considers ef (weight 2) once vertex f has joined the tree.

**Omitting the cycle check in Kruskal:** In Kruskal's algorithm, you must confirm that both endpoints belong to different components before accepting an edge. In the six-vertex graph, edge cf (weight 4) arrives right after bf (weight 4). Accepting cf would close the cycle b-c-f because b, c, and f are already linked. Always verify that an edge joins two separate components before adding it.
</Callout>

## The Java

Here are complete, runnable Java implementations of both Prim's algorithm (using an adjacency matrix in $\Theta(V^2)$ time) and Kruskal's algorithm (using Disjoint Sets with path compression in $O(E \log V)$ time):

```java
import java.util.Arrays;

public class SpanningTreeAlgorithms {

    // --- 1. Prim's Algorithm (Adjacency Matrix, Theta(V^2)) ---
    static int prim(int n, int[][] adj) {
        boolean[] inTree = new boolean[n];
        int[] key = new int[n];       // smallest edge weight connecting to tree
        int[] parent = new int[n];    // parent vertex in tree
        Arrays.fill(key, Integer.MAX_VALUE);
        Arrays.fill(parent, -1);

        key[0] = 0;                   // start tree at vertex 0 (vertex 'a')
        int totalWeight = 0;

        for (int step = 0; step < n; step++) {
            // Find unvisited vertex with smallest key
            int u = -1;
            for (int i = 0; i < n; i++) {
                if (!inTree[i] && (u == -1 || key[i] < key[u])) {
                    u = i;
                }
            }

            inTree[u] = true;
            totalWeight += key[u];

            // Relax edges leaving u to unvisited neighbors
            for (int v = 0; v < n; v++) {
                if (adj[u][v] > 0 && !inTree[v] && adj[u][v] < key[v]) {
                    key[v] = adj[u][v];
                    parent[v] = u;
                }
            }
        }
        return totalWeight;
    }

    // --- 2. Kruskal's Algorithm (Union-Find with Path Compression) ---
    static int find(int[] parent, int x) {
        if (parent[x] != x) parent[x] = find(parent, parent[x]); // path compression
        return parent[x];
    }

    static int kruskal(int n, int[][] edges) {        // each edge: {u, v, weight}
        // Use Integer.compare to prevent arithmetic overflow on negative weights
        Arrays.sort(edges, (a, b) -> Integer.compare(a[2], b[2]));
        int[] parent = new int[n];
        for (int i = 0; i < n; i++) parent[i] = i;

        int totalWeight = 0, used = 0;
        for (int[] e : edges) {
            int ru = find(parent, e[0]), rv = find(parent, e[1]);
            if (ru == rv) continue;                   // same tree: would form a cycle
            parent[ru] = rv;                          // union the two trees
            totalWeight += e[2];
            if (++used == n - 1) break;               // tree complete
        }
        return totalWeight;
    }

    public static void main(String[] args) {
        // Six vertices: a = 0, b = 1, c = 2, d = 3, e = 4, f = 5
        int[][] edges = {
            {0, 1, 3}, {1, 2, 1}, {1, 5, 4}, {2, 5, 4}, {0, 5, 5},
            {5, 3, 5}, {0, 4, 6}, {2, 3, 6}, {5, 4, 2}, {4, 3, 8}
        };

        // Build adjacency matrix for Prim
        int n = 6;
        int[][] adj = new int[n][n];
        for (int[] e : edges) {
            adj[e[0]][e[1]] = e[2];
            adj[e[1]][e[0]] = e[2];
        }

        System.out.println("Prim MST weight:    " + prim(n, adj));     // 15
        System.out.println("Kruskal MST weight: " + kruskal(n, edges)); // 15
    }
}
```

**(c) Stopping condition and cycle detection with Union-Find:**
- A spanning tree on $V$ vertices strictly requires $V - 1$ edges. Tracking `usedEdges` and halting when `usedEdges == V - 1` prevents examining the remaining edges in the sorted list.
- **Cycle detection via Union-Find:**
  - Each vertex maintains a parent pointer `parent[v]`.
  - To test edge $(u, v)$, call `find(u)` and `find(v)` to locate the root representatives of their respective trees.
  - If `find(u) == find(v)`, both vertices share the same root, meaning a path already connects them; adding $(u, v)$ would complete a cycle, so the edge is rejected in $O(1)$ amortized time.
  - If `find(u) != find(v)`, the edge connects two disjoint trees; `parent[rootU] = rootV` unions the two sets. With union by rank and path compression, each check takes $O(\alpha(V))$ time, where $\alpha$ is the nearly constant inverse Ackermann function.

**3.** *(Counterexamples to greedy heuristics: coin change and MST edge weights)* Greedy algorithms rely on the heuristic that picking the best immediate option leads to an optimal overall outcome.

1. Prove why the greedy coin change heuristic fails on the coin denomination set $C = \{1, 3, 4\}$:
   - Trace the greedy choice versus the optimal choice for target amounts $6$, $10$, and $14$.
   - Identify the exact reason why the irrevocable property causes the greedy approach to fail here.
2. Contrast this with the Minimum Spanning Tree problem: explain why the greedy choice in Prim's and Kruskal's algorithms is provably guaranteed never to make an irrevocable mistake.
3. Suppose a connected undirected graph has negative edge weights (for example, edges with weights $-5, -2, 3$). Can Prim's and Kruskal's algorithms still be used to find a minimum spanning tree, or will they fail like Dijkstra's shortest path algorithm? Justify your answer.

<ModelAnswer>
**(a) Coin change counterexamples for $C = \{1, 3, 4\}$:**
- **Target amount 6:**
  - *Greedy approach:* Selects the largest coin $\le 6$, which is $4$ (remaining: $2$). Next selects $1$ (remaining: $1$), and finally $1$. Result: **3 coins** ($4 + 1 + 1$).
  - *Optimal approach:* Two coins of 3: **2 coins** ($3 + 3$).
- **Target amount 10:**
  - *Greedy approach:* Takes $4$ (remaining 6), takes $4$ (remaining 2), takes $1$ (remaining 1), takes $1$. Result: **4 coins** ($4 + 4 + 1 + 1$).
  - *Optimal approach:* **3 coins** ($4 + 3 + 3$).
- **Target amount 14:**
  - *Greedy approach:* Takes $4, 4, 4$ (remaining 2), takes $1$, takes $1$. Result: **5 coins** ($4 + 4 + 4 + 1 + 1$).
  - *Optimal approach:* **4 coins** ($4 + 4 + 3 + 3$).
- **Why greedy fails:** Greedy choices are **irrevocable**. Grabbing the largest coin (4) consumes too much capacity, leaving a remainder (2) that cannot be formed by the medium coin (3). Because greedy algorithms cannot backtrack or look ahead to evaluate combinations of smaller coins, the irrevocable local choice permanently eliminates the globally optimal solution.

**(b) Why greedy works for MST (The Cut Property):**
- In MST construction, the **Cut Property** guarantees safety: for *any* partition (cut) of vertices into two sets $S$ and $V \setminus S$, the lightest edge crossing the cut *must* belong to an optimal minimum spanning tree.
- Prim's algorithm maintains a cut between the tree vertices $V_T$ and the non-tree vertices $V \setminus V_T$. Because it strictly chooses the lightest crossing edge, that edge is mathematically proven to be part of an optimal MST.
- Kruskal's algorithm maintains a cut between a candidate edge's component and the rest of the graph.
- Unlike coin change, where choosing a 4 can permanently block the optimal pair $(3, 3)$, choosing the minimum crossing edge in a graph can never prevent connecting the remaining vertices at minimal cost.

**(c) Negative edge weights in MST:**
- **Both Prim's and Kruskal's algorithms work completely correctly on graphs with negative edge weights.**
- *Proof by constant shifting:* Let $w_{min} < 0$ be the minimum edge weight in graph $G$. Add a positive constant $C = |w_{min}| + 1$ to every edge weight in the graph, creating graph $G'$. Because *every* spanning tree on $V$ vertices contains exactly $V - 1$ edges, the weight of every spanning tree in $G'$ increases by exactly $(V - 1) \times C$:
  $$
  W_{G'}(T) = W_G(T) + (V - 1)C
  $$
  Because every spanning tree is shifted by the exact same constant, the tree that minimizes $W_{G'}(T)$ is identical to the tree that minimizes $W_G(T)$.
- *Contrast with Dijkstra's algorithm:* Dijkstra fails with negative weights because path lengths vary in edge counts: a path with 2 edges is shifted by $2C$ while a path with 5 edges is shifted by $5C$, destroying relative path optimality. In MSTs, all spanning trees have identical edge counts ($V - 1$), so negative weights cause no distortion.
</ModelAnswer>

**4.** *(MST uniqueness theorem and edge density trade-offs)*
1. State the condition under which a connected weighted graph is guaranteed to have a **unique** minimum spanning tree.
2. Suppose all edge weights in a connected graph with $V = 6$ and $E = 10$ are identical (for example, every edge has weight $2$). How many different minimum spanning trees exist, and what is the total weight of each?
3. In a university exam, a student is asked whether to choose Prim's or Kruskal's algorithm to compute the MST of a dense road network with $V = 5{,}000$ intersections and $E = 10{,}000{,}000$ road segments ($E \approx \frac{1}{2} V^2$). Analyze the asymptotic time complexity of both algorithms on this graph and provide a recommendation.

<ModelAnswer>
**(a) MST uniqueness condition:**
- **Theorem:** If all edge weights in a connected graph are **distinct** (no two edges share the same weight), then the graph has **exactly one unique minimum spanning tree**.
- *Proof sketch:* Suppose two distinct MSTs $T_1$ and $T_2$ exist. Let $e$ be the minimum-weight edge that belongs to one tree but not the other (say $e \in T_1 \setminus T_2$). Adding $e$ to $T_2$ creates a cycle. At least one edge $e'$ in this cycle crosses the cut defined by $e$. Since all weights are distinct and $e$ was the minimum difference edge, $w(e') > w(e)$. Replacing $e'$ with $e$ in $T_2$ yields a spanning tree with strictly lower total weight than $T_2$, contradicting the assumption that $T_2$ was a minimum spanning tree.

**(b) Graph with identical edge weights:**
- If every edge has weight $2$, then *any* spanning tree has total weight:
  $$
  (V - 1) \times 2 = (6 - 1) \times 2 = 10
  $$
- Every possible spanning tree is a minimum spanning tree.
- By Cayley's formula, for a complete graph $K_n$, there are $n^{n-2}$ spanning trees. For $n = 6$, $6^{6-2} = 6^4 = 1{,}296$ different spanning trees. For an arbitrary graph with 10 edges, the count equals the number of cycle-free subgraphs of size 5 connecting all 6 vertices (determinable via Kirchhoff's Matrix Tree Theorem). All of them have total weight 10.

**(c) Algorithm selection for dense graphs ($V = 5{,}000$, $E = 10{,}000{,}000$):**
- **Prim with adjacency matrix:** Time complexity is $\Theta(V^2)$.
  $$
  V^2 = (5{,}000)^2 = 25{,}000{,}000\text{ operations}
  $$
  Finding the minimum crossing edge scans an array of size $V$ in each of the $V$ steps, completely independent of edge count $E$.
- **Kruskal with Union-Find:** Requires sorting all $E$ edges:
  $$
  E \log_2 E = 10^7 \times \log_2(10^7) \approx 10^7 \times 23.25 \approx 232{,}500{,}000\text{ operations}
  $$
  Sorting alone requires roughly 10 times more operations than Prim's entire execution.
- **Recommendation:** **Prim's algorithm (using an adjacency matrix or simple distance array)** is substantially faster on dense graphs ($E = \Theta(V^2)$) because it avoids sorting the massive edge list. Kruskal's algorithm is preferred only for **sparse graphs** ($E \ll V^2$, such as $E = O(V)$), where sorting takes only $O(V \log V)$ time.
</ModelAnswer>
