# Graphs: BFS and DFS

So far everything has lived in an array: a straight line of values with a first and a last. A lot of data isn't shaped like that, such as cities connected by roads, people connected by friendships, web pages connected by links, or courses connected by prerequisites. All of these are **graphs**.

## What a graph is

A [graph](/courses/discrete-mathematics/graphs#what-a-graph-is) $G = (V, E)$ is two sets:

- $V$, the **vertices** (also called nodes): the things. Usually $n = |V|$.
- $E$, the **edges** (also called arcs): the connections between pairs of vertices. Usually $m = |E|$.

Edges come in a few kinds:

- **Undirected:** the connection goes both ways, like a friendship or a two-way street.
- **Directed:** one way only, like a follow on social media or a one-way street. Drawn with an arrow.
- **Weighted:** each edge carries a number, such as a distance, a cost or a time. A weighted graph is also called a **network**.

Some vocabulary you'll need:

An edge is written as a pair, (starting vertex, ending vertex). For an undirected edge, (A, B) and (B, A) are the same edge. For a directed edge they're two different edges.

Some vocabulary you'll need:

- Two vertices are **adjacent** if an edge connects them. Two edges are **adjacent edges** if they share a vertex.
- The **degree** of a vertex is the number of edges that touch it (the notes say edges **incident** with it). In the graph A–B–C, B has degree 2 and A has degree 1.
- A **path** is a sequence of vertices where each one is adjacent to the next. Its **length** is the number of edges in it, so the path A, B, C, D has length 3. A path that never repeats a vertex is a **simple path**.
- A **cycle** is a path that starts and ends at the same vertex: a closed simple path. A graph with no cycles is **acyclic**.

The notes sort graphs into five types: **undirected** (only undirected edges), **directed** (only directed edges), **cycle graph** (has a cycle), **acyclic** (has none) and **weighted**. Two of their definitions need care:

- What the notes call a "cycle graph" (any graph with a cycle) is usually called a **cyclic graph**. In most textbooks, a *cycle graph* is a graph that is nothing but one ring, like A–B–C–A.
- The notes say a weighted graph's values are non-negative and equal the length between the vertices. Distances are the usual example, but weights can be any number, including negative ones (a profit and loss, for instance). Some algorithms, such as Dijkstra's shortest paths, only work when weights are non-negative, which is why it matters.

## Storing a graph in Java

The most common way is an **adjacency list**: for every vertex, a list of its neighbours. With vertices numbered `0` to `n - 1`:

```java
int n = 7;
List<List<Integer>> adj = new ArrayList<>();
for (int i = 0; i < n; i++) adj.add(new ArrayList<>());

// undirected edge between u and v: add it in both directions
static void addEdge(List<List<Integer>> adj, int u, int v) {
    adj.get(u).add(v);
    adj.get(v).add(u);
}
```

The alternative is an **adjacency matrix**: an `n × n` grid of booleans where `matrix[u][v]` says whether the edge exists. It answers "are u and v connected?" in $O(1)$, but it uses $O(n^2)$ memory even when the graph has hardly any edges. Adjacency lists use $O(n + m)$.

## Traversal: visit everything, once

**Traversing** a graph means visiting every vertex reachable from a starting point, **each exactly once**. The "once" is the hard part. Unlike an array, a graph can have cycles, and a naive walk would go round and round forever. The fix is always to keep a `visited` array and never enter a vertex twice.

The notes put it as: mark each vertex as visited while avoiding cycles. A vertex is either **visited** or **not visited**.

There are two basic orders to visit vertices in, and they differ only in the data structure that holds the vertices waiting to be explored.

## Breadth-first search: ripples in a pond

**BFS** explores in **layers**: first the start vertex, then everything one edge away, then everything two edges away, like a ripple spreading out from a stone dropped in water.

It uses a **[queue](/courses/data-structures/queues-and-deques#the-interface)**, which is first in, first out. When you visit a vertex, every unvisited neighbour joins the *back* of the line, so vertices are explored in exactly the order they were discovered.

<GraphTraversal algorithm="bfs" />

Watch the queue at the bottom. Vertex 0's neighbours (1 and 2) are all handled before any of *their* neighbours. The mint edges form the **BFS tree**, the route by which each vertex was first reached.

### The notes' BFS example

The notes' version, step by step:

1. Put the start vertex at the back of a queue.
2. Take the front vertex of the queue and add it to the visited list.
3. Add each of its neighbours that hasn't been visited (or queued) to the back of the queue.
4. Repeat steps 2 and 3 until the queue is empty.

Their example graph has vertices 1 to 10 and edges 1–2, 1–4, 2–3, 2–5, 2–7, 2–8, 3–4, 3–9, 3–10, 5–6, 5–7, 5–8 and 7–8. Starting from 1, their answer is **1 4 2 3 5 8 7 10 9 6**:

| Take from the queue | New neighbours added | Queue after |
| --- | --- | --- |
| 1 | 4, 2 | 4 2 |
| 4 | 3 | 2 3 |
| 2 | 5, 8, 7 (3 is already queued) | 3 5 8 7 |
| 3 | 10, 9 | 5 8 7 10 9 |
| 5 | 6 (7 and 8 are already queued) | 8 7 10 9 6 |
| 8, 7, 10, 9, 6 | nothing new | empty |

Notice the notes take 4 before 2, and 8 before 7: they add neighbours in the order they appear in the drawing. With neighbours in numerical order, as in the Java below, the same graph gives 1 2 4 3 5 7 8 9 10 6. **Both are correct BFS orders.** BFS fixes the layers (1; then 2 and 4; then 3, 5, 7, 8; then 9, 10, 6), but the order within a layer depends on the order you list neighbours in. On an exam, say which order you use, usually alphabetical or numerical, and stick to it.

In an unweighted graph, the path BFS finds to each vertex is a **shortest path** (fewest edges), because the ripple reaches each vertex as early as it possibly can.

## Depth-first search: the maze explorer

**DFS** picks a direction and goes as **deep** as it can. When it hits a dead end (a vertex with no unvisited neighbours), it **backtracks** to the last vertex that still has an unexplored path, and goes deep again from there. It's how you'd explore a maze with a piece of chalk.

It uses a **stack**, which is last in, first out. The most recently discovered vertex is explored first. The simplest way to write DFS uses recursion, and then the stack is Java's own **call stack**: each recursive call is pushed when you go deeper, and popped when you backtrack.

<GraphTraversal algorithm="dfs" />

With the same graph and start, the order is very different. DFS dives 0 → 1 → 3 → 6 → 4 → 2 → 5, one long path, before it ever comes back. Use the toggle under the controls to switch between BFS and DFS on the same picture.

### The notes' DFS: an explicit stack

The notes write DFS without recursion, with a stack whose size is the number of vertices:

1. Pick a start vertex, visit it, and push it on the stack.
2. Look at the vertex on **top** of the stack. Visit any one of its neighbours that hasn't been visited, and push it.
3. Repeat step 2 until the top vertex has no unvisited neighbours.
4. Then **backtrack**: pop the top vertex. A popped vertex is a **dead end**.
5. Repeat steps 2 to 4 until the stack is empty.

Their example graph has vertices A to G and edges A–B, A–D, A–E, B–C, B–E, C–E, C–F, C–G, D–E, E–F and F–G. Taking neighbours alphabetically and starting at A:

| Step | Top of stack | Action | Stack (bottom → top) |
| --- | --- | --- | --- |
| 1 | | visit A, push | A |
| 2 | A | B is unvisited: visit, push | A B |
| 3 | B | C is unvisited: visit, push | A B C |
| 4 | C | E is unvisited: visit, push | A B C E |
| 5 | E | D is unvisited: visit, push | A B C E D |
| 6 | D | A and E are visited: pop D | A B C E |
| 7 | E | F is unvisited: visit, push | A B C E F |
| 8 | F | G is unvisited: visit, push | A B C E F G |
| 9 to 14 | | nothing new anywhere: pop G, F, E, C, B, A | empty |

The visit order is **A B C E D F G**. The edges used to reach each new vertex, A–B, B–C, C–E, E–D, E–F and F–G, form the **DFS spanning tree**: it connects all 7 vertices with 6 edges and no cycle. The other five edges, which led to vertices already visited, are what the notes label **back edges**.

The recursive Java below does exactly this. Each recursive call is a push, and each `return` is a pop.

## Analysis

Both algorithms do the same amount of work, just in a different order:

- Every vertex is marked visited and processed **once**: $O(V)$.
- Every edge is looked at a constant number of times when scanning neighbour lists (once from each end in an undirected graph): $O(E)$.

Total: **$O(V + E)$** for both (the notes give this for each algorithm), with an adjacency list. Space is $O(V)$ for the `visited` array plus the queue or stack.

(With an adjacency matrix, finding a vertex's neighbours means scanning a whole row, so both become $O(V^2)$.)

| | BFS | DFS |
| --- | --- | --- |
| Data structure | Queue (FIFO) | Stack (LIFO) / recursion |
| Explores | Level by level | One path as deep as possible, then backtracks |
| Shortest paths (unweighted) | Yes | No |
| Time | $O(V + E)$ | $O(V + E)$ |

<Callout tone="orange" label="Mark when you add, not when you leave">
In BFS, mark a vertex visited the moment you **add it to the queue**, not when you take it out. Otherwise different neighbours can add the same vertex several times before it's processed. The result is still correct, but the wasted work is a common cause of "time limit exceeded."
</Callout>

<Callout tone="orange" label="BFS is not recursive">
The notes call breadth-first search "a recursive algorithm". It isn't: BFS is a loop around a queue, as in their own four steps above. DFS is the one that's naturally recursive, because its stack can be the call stack.
</Callout>

### Homework: spanning trees of the A to S graph

The notes' homework asks for the "minimum spanning tree" of this graph by DFS and by BFS, starting from A. Its edges are A–B, A–S, S–C, S–G, C–D, C–E, C–F, F–G, G–H and E–H: nine vertices, ten edges.

Taking neighbours alphabetically:

- **DFS** visits A B S C D E H G F. From C it goes to D (a dead end, so it pops back to C), then E, H, G and F. Tree edges: A–B, A–S, S–C, C–D, C–E, E–H, H–G, G–F.
- **BFS** visits A B S C G D E F H. Layers: A; then B and S; then C and G; then D, E, F and H. Tree edges: A–B, A–S, S–C, S–G, C–D, C–E, C–F, G–H.

Both trees have 8 edges, because a spanning tree of 9 vertices always has $9 - 1 = 8$. The edges have no weights, so every spanning tree is equally "minimum", and the word adds nothing here. With weighted edges, DFS and BFS would **not** find the minimum one; that takes [Prim's or Kruskal's algorithm](/courses/algorithm-design-and-analysis/greedy-and-mst#minimum-spanning-trees).

Advanced Algorithms takes this further, from BFS on unweighted graphs to weighted ones, in [shortest paths](/courses/advanced-algorithms/shortest-paths#unweighted-graphs).

## The full Java

```java
import java.util.*;

public class GraphTraversal {

    static void bfs(List<List<Integer>> adj, int start) {
        boolean[] visited = new boolean[adj.size()];
        Queue<Integer> queue = new ArrayDeque<>();
        visited[start] = true;
        queue.add(start);
        while (!queue.isEmpty()) {
            int v = queue.poll();
            System.out.print(v + " ");
            for (int w : adj.get(v)) {
                if (!visited[w]) {
                    visited[w] = true;
                    queue.add(w);
                }
            }
        }
        System.out.println();
    }

    static void dfs(List<List<Integer>> adj, int v, boolean[] visited) {
        visited[v] = true;
        System.out.print(v + " ");
        for (int w : adj.get(v))
            if (!visited[w])
                dfs(adj, w, visited);
    }

    public static void main(String[] args) {
        int n = 7;
        List<List<Integer>> adj = new ArrayList<>();
        for (int i = 0; i < n; i++) adj.add(new ArrayList<>());
        int[][] edges = { {0,1}, {0,2}, {1,3}, {1,4}, {2,4}, {2,5}, {3,6}, {4,6} };
        for (int[] e : edges) {
            adj.get(e[0]).add(e[1]);
            adj.get(e[1]).add(e[0]);
        }
        for (List<Integer> list : adj) Collections.sort(list);

        bfs(adj, 0);                          // 0 1 2 3 4 5 6
        dfs(adj, 0, new boolean[n]);          // 0 1 3 6 4 2 5
    }
}
```
