# Graphs: BFS and DFS

Earlier lessons stored data in arrays, where elements sit in a sequence with a fixed start and end. Many collections of information do not fit a linear sequence. Road maps connect cities, social networks connect friends, the web connects pages through hyperlinks, and academic curricula connect courses through prerequisites. In computer science, these interconnected networks are **graphs**.

## What a graph is

A [graph](/courses/discrete-mathematics/graphs#what-a-graph-is) $G = (V, E)$ consists of two sets:

- $V$, the set of **vertices** (also called nodes), representing individual entities or locations. The number of vertices is denoted $n = |V|$.
- $E$, the set of **edges** (also called arcs), representing links between pairs of vertices. The number of edges is denoted $m = |E|$.

An edge is written as a pair $(u, v)$, naming the two endpoints. Edges fall into three main categories:

- **Undirected:** the connection works in both directions, like a two-way street or a mutual friendship. The pairs $(u, v)$ and $(v, u)$ refer to the same edge.
- **Directed:** the connection runs in one specified direction, like a one-way street or a web hyperlink. The edge points from $u$ to $v$, drawn with an arrow, so $(u, v)$ is distinct from $(v, u)$.
- **Weighted:** each edge carries a numerical value representing cost, distance, latency, or capacity. A graph with weighted edges is called a **weighted graph** or **network**.

Standard graph terminology:

- Two vertices are **adjacent** (or neighbors) if an edge connects them directly. Two edges are **adjacent edges** if they share a common vertex.
- The **degree** of a vertex is the count of edges connected to it, also described as edges **incident** with that vertex. In an undirected line graph A-B-C, vertex B has degree 2, while A and C each have degree 1.
- A **path** is an ordered sequence of vertices where each consecutive pair is adjacent. The **length** of a path is the number of edges it traverses. For example, the path A, B, C, D contains three edges and has length 3. A path that visits no vertex more than once is a **simple path**.
- A **cycle** is a path of length at least 1 that starts and finishes at the same vertex without repeating any other vertices. A graph containing no cycles is **[acyclic](/courses/discrete-mathematics/paths-and-dags#directed-acyclic-graphs)**.

Course materials often categorize graphs into five structural forms: **undirected** (containing only undirected edges), **directed** (containing only directed edges), **cyclic graph** (containing at least one cycle), **acyclic** (containing no cycles), and **weighted**. Two details deserve attention:

- The lecture notes refer to any graph containing a cycle as a "cycle graph." Standard textbook terminology refers to such a structure as a **cyclic graph**, reserving the term *cycle graph* ($C_n$) specifically for a single circular polygon of $n$ vertices, such as A-B-C-A.
- The lecture notes assume edge weights are always non-negative distances. In broader computer science, edge weights can represent arbitrary values, including negative numbers such as financial transactions or net energy changes. Certain algorithms, such as [Dijkstra's shortest-path algorithm](/courses/advanced-algorithms/shortest-paths#dijkstras-algorithm), require non-negative weights to guarantee correctness, while other algorithms, such as Bellman–Ford, accommodate negative values.

## Storing a graph in Java

The primary representation in algorithms is an **adjacency list**, which stores an explicit list of neighbors for every vertex. Numbering vertices from `0` to `n - 1`:

```java
int n = 7;
List<List<Integer>> adj = new ArrayList<>();
for (int i = 0; i < n; i++) adj.add(new ArrayList<>());

// Undirected edge between u and v: record the connection in both directions
static void addEdge(List<List<Integer>> adj, int u, int v) {
    adj.get(u).add(v);
    adj.get(v).add(u);
}
```

The type `List<List<Integer>>` nests lists: an inner `List<Integer>` stores the neighbors of one vertex, while the outer list indexes each vertex by its integer identifier. Calling `adj.get(3)` yields the list of neighbors for vertex 3. For a triangle with edges 0-1, 1-2, and 2-0, `adj` contains `[[1, 2], [0, 2], [1, 0]]`. Each undirected edge appears twice, once in the neighbor list of each endpoint.

An alternative representation is an **adjacency matrix**, a two-dimensional `n × n` boolean array (stored as a [matrix](/courses/computational-mathematics/matrices-and-matlab#writing-a-matrix-down)) where `matrix[u][v]` indicates whether an edge connects vertex $u$ to vertex $v$. Checking whether an edge exists between two specific vertices takes $O(1)$ time in an adjacency matrix. However, the matrix allocates $\Theta(n^2)$ memory regardless of edge density.

An adjacency list requires $O(n + m)$ space, allocating one list header per vertex and one element per edge endpoint ($2m$ entries total for undirected graphs). In sparse graphs where $m \ll n^2$, the difference in memory is substantial. A road network with 10,000 towns and an average of 4 roads per town requires 100,000,000 entries in an adjacency matrix, but only 40,000 entries in an adjacency list.

## Traversal: visit everything, once

**Graph traversal** (or **traversing** a graph) is the process of visiting every vertex reachable from a selected start vertex, visiting each vertex exactly once. Because graphs can contain cycles, an unconstrained search can revisit vertices indefinitely. Graph traversal algorithms maintain a `visited` array to guarantee that no vertex is processed more than once.

Consider a triangle graph with edges A-B, B-C, and C-A. Starting a search at vertex A without tracking visited vertices causes an infinite loop: A explores neighbor B, B immediately explores neighbor A, and the search oscillates between them until the program exhausts memory. Marking vertices as **visited** allows vertex B to recognize that vertex A has already been handled, directing exploration forward to vertex C.

Standard graph traversals place vertices into two operational states: **visited** and **not visited**. The two foundational graph traversal algorithms, breadth-first search and depth-first search, differ primarily in the underlying data structure used to manage discovered vertices awaiting exploration.

## Breadth-first search: ripples in a pond

**Breadth-first search** (**BFS**) explores a graph level by level, radiating outward from a start vertex. The algorithm visits the start vertex first, then all vertices one edge away, followed by all vertices two edges away, expanding through successive concentric layers.

BFS manages vertices waiting for exploration with a **[queue](/courses/data-structures/queues-and-deques#the-interface)**, following a first-in, first-out (FIFO) discipline. When a vertex is explored, all of its unvisited neighbors are enqueued at the back. This ensures that vertices discovered earlier are evaluated before vertices discovered later.

### Tracing the lecture BFS example

The standard BFS algorithm executes four main steps:

1. Insert the start vertex into the back of a queue and mark it as visited.
2. Remove the vertex at the front of the queue.
3. For each unvisited neighbor of this vertex, mark it as visited and enqueue it at the back.
4. Repeat steps 2 and 3 until the queue is empty.

The lecture example examines a 10-vertex graph with vertices 1 through 10 and edges 1-2, 1-4, 2-3, 2-5, 2-7, 2-8, 3-4, 3-9, 3-10, 5-6, 5-7, 5-8, and 7-8. Starting at vertex 1, the lecture trace produces the visit sequence **1 4 2 3 5 8 7 10 9 6**:

| Dequeued vertex | Discovered neighbors added | Queue state |
| --- | --- | --- |
| 1 | 4, 2 | 4, 2 |
| 4 | 3 | 2, 3 |
| 2 | 5, 8, 7 (vertex 3 is already queued) | 3, 5, 8, 7 |
| 3 | 10, 9 | 5, 8, 7, 10, 9 |
| 5 | 6 (vertices 7 and 8 are already queued) | 8, 7, 10, 9, 6 |
| 8, 7, 10, 9, 6 | None | Empty |

In this trace, vertex 4 is dequeued before vertex 2, and vertex 8 is queued before vertex 7, reflecting the counter-clockwise layout order in the lecture diagram. Sorting neighbor lists numerically produces the sequence 1, 2, 4, 3, 5, 7, 8, 9, 10, 6. Both visit sequences represent valid BFS orderings. BFS determines the sequence of layers: layer 0 contains vertex 1; layer 1 contains vertices 2 and 4; layer 2 contains vertices 3, 5, 7, and 8; and layer 3 contains vertices 9, 10, and 6. Within any individual layer, the specific visit order depends on how the adjacency lists sort neighbors. In academic exercises, explicitly declare whether neighbor traversal follows numerical, alphabetical, or diagram order.

On unweighted graphs, BFS identifies a **shortest path** (a path with the minimum number of edges) from the start vertex to every reachable vertex, because it discovers all vertices at distance $k$ before any vertex at distance $k + 1$.

## Depth-first search: the maze explorer

**Depth-first search** (**DFS**) explores a graph along a single path as deeply as possible before retreating. When the search reaches a vertex with no remaining unvisited neighbors, it **backtracks** to the most recently visited vertex that still has unexplored outgoing edges, continuing forward exploration from that point.

DFS manages pending vertices using a **[stack](/courses/data-structures/stacks#the-interface)**, which operates on a last-in, first-out (LIFO) basis. The most recently discovered vertex is explored first. When implemented recursively, DFS uses the program's runtime **call stack**, pushing a frame for each deeper recursive call and popping the frame upon backtracking.

<GraphTraversal algorithm="dfs" />

On the same graph, DFS produces a substantially different exploration path than BFS, traversing sequentially 0 to 1, 3, 6, 4, 2, and 5 along a single deep branch before returning.

### Tracing the lecture DFS example

An explicit, iterative DFS implementation uses a stack sized up to the total number of vertices:

1. Select a start vertex, mark it as visited, and push it onto the stack.
2. Examine the vertex on the top of the stack. If it has an unvisited neighbor, mark that neighbor as visited and push it onto the stack.
3. Repeat step 2 until the vertex on top of the stack has no remaining unvisited neighbors.
4. Backtrack by popping that top vertex off the stack.
5. Repeat steps 2 through 4 until the stack is empty.

The lecture example analyzes a 7-vertex graph with vertices A through G and edges A-B, A-D, A-E, B-C, B-E, C-E, C-F, C-G, D-E, E-F, and F-G. Selecting neighbors alphabetically and starting at vertex A yields this trace:

| Step | Top of stack | Evaluation | Stack contents (bottom to top) |
| --- | --- | --- | --- |
| 1 | None | Visit vertex A, push onto stack | A |
| 2 | A | B is unvisited: visit B, push onto stack | A, B |
| 3 | B | C is unvisited: visit C, push onto stack | A, B, C |
| 4 | C | E is unvisited: visit E, push onto stack | A, B, C, E |
| 5 | E | D is unvisited: visit D, push onto stack | A, B, C, E, D |
| 6 | D | Neighbors A and E are already visited: pop D | A, B, C, E |
| 7 | E | F is unvisited: visit F, push onto stack | A, B, C, E, F |
| 8 | F | G is unvisited: visit G, push onto stack | A, B, C, E, F, G |
| 9 to 14 | Various | No unvisited neighbors remain: pop G, F, E, C, B, A | Empty |

The resulting traversal order is **A B C E D F G**. The tree edges traversed to discover new vertices (A-B, B-C, C-E, E-D, E-F, and F-G) form a **DFS spanning tree**, connecting all 7 vertices using 6 edges with no cycles (a [tree](/courses/discrete-mathematics/trees#what-a-tree-is) on $V$ vertices). The remaining five edges connect vertices to ancestors already present in the search tree, categorized in graph theory as **back edges**.

A recursive implementation mirrors this behavior directly: each recursive invocation pushes a stack frame, and each method return pops that frame upon reaching a dead end.

## Analysis

Using an adjacency list, both BFS and DFS exhibit identical asymptotic performance:

- Each vertex is marked visited and processed once: $\Theta(V)$.
- Each edge is inspected a constant number of times when scanning adjacency lists (twice in an undirected graph, once from each endpoint): $\Theta(E)$.

The overall time complexity is **$\Theta(V + E)$**. Space complexity is $O(V)$, requiring an array of size $V$ for tracking visited states and either a queue (BFS) or a recursion stack (DFS) holding at most $V$ vertices.

<Callout tone="orange" label="Common mistake: O(V × E)">
Because the code contains a loop over vertices enclosing a loop over neighbors, students often mistakenly conclude that the running time is $O(V \times E)$. The inner loop does not iterate over all $E$ edges for every vertex; it scans only the edges incident to the current vertex. Summing vertex degrees over the entire graph evaluates each edge exactly twice, contributing $2E$ total operations. The loops distribute the edges across all vertices rather than multiplying them.
</Callout>

When using an adjacency matrix, identifying the neighbors of any vertex requires scanning a row of length $V$. Across all $V$ vertices, this inspection requires $\Theta(V^2)$ time, reducing traversal efficiency on sparse graphs.

| Property | Breadth-First Search (BFS) | Depth-First Search (DFS) |
| --- | --- | --- |
| Underlying structure | Queue (FIFO) | Stack (LIFO) or recursive call stack |
| Exploration strategy | Level by level across concentric layers | Deeply along a single path, then backtracks |
| Shortest path on unweighted graphs | Guaranteed (minimum edge count) | Not guaranteed |
| Time complexity (adjacency list) | $O(V + E)$ | $O(V + E)$ |
| Space complexity | $O(V)$ | $O(V)$ |

<Callout tone="orange" label="Mark vertices upon enqueue">
In BFS, mark a vertex as visited the moment it enters the queue, rather than waiting until it is removed. If the visited flag is set only upon dequeuing, several adjacent vertices can discover and enqueue the same vertex multiple times before it is processed. This redundant queue allocation wastes memory and computation, often causing timeout errors on automated grading platforms.
</Callout>

The lecture slides describe breadth-first search as a recursive algorithm. In practice, standard BFS is an iterative algorithm structured around a queue. DFS maps directly to recursion because the runtime call stack provides the necessary LIFO discipline.

### Spanning trees of the A to S graph

The lecture problem set requests the spanning tree of a 9-vertex graph produced by DFS and BFS, starting from vertex A. The graph has vertices A, B, C, D, E, F, G, H, and S, connected by 10 edges: A-B, A-S, S-C, S-G, C-D, C-E, C-F, F-G, G-H, and E-H.

Breaking ties alphabetically:

- **DFS** produces the visit order A B S C D E H G F. From vertex C, the search visits D, hits a dead end, backtracks to C, and advances through E, H, G, and F. The resulting tree edges are A-B, A-S, S-C, C-D, C-E, E-H, H-G, and G-F.
- **BFS** produces the visit order A B S C G D E F H. The layers unfold as follows: layer 0 contains A; layer 1 contains B and S; layer 2 contains C and G; and layer 3 contains D, E, F, and H. The resulting tree edges are A-B, A-S, S-C, S-G, C-D, C-E, C-F, and G-H.

Both resulting spanning trees contain exactly 8 edges, adhering to the mathematical property that any spanning tree of $n$ vertices contains exactly $n - 1$ edges. Because the graph edges are unweighted, every valid spanning tree has identical uniform weight. In graphs with weighted edges, finding an actual minimum weight spanning tree requires specialized greedy methods such as [Prim's or Kruskal's algorithm](/courses/algorithm-design-and-analysis/greedy-and-mst#minimum-spanning-trees).

## The full Java

```java
import java.util.*;

public class GraphTraversal {

    static void bfs(List<List<Integer>> adj, int start) {
        boolean[] visited = new boolean[adj.size()];
        Queue<Integer> queue = new ArrayDeque<>();
        visited[start] = true;
        queue.add(start);
        while (!queue.isEmpty()) {
            int v = queue.poll();
            System.out.print(v + " ");
            for (int w : adj.get(v)) {
                if (!visited[w]) {
                    visited[w] = true;
                    queue.add(w);
                }
            }
        }
        System.out.println();
    }

    static void dfs(List<List<Integer>> adj, int v, boolean[] visited) {
        visited[v] = true;
        System.out.print(v + " ");
        for (int w : adj.get(v))
            if (!visited[w])
                dfs(adj, w, visited);
    }

    public static void main(String[] args) {
        int n = 7;
        List<List<Integer>> adj = new ArrayList<>();
        for (int i = 0; i < n; i++) adj.add(new ArrayList<>());
        int[][] edges = { {0,1}, {0,2}, {1,3}, {1,4}, {2,4}, {2,5}, {3,6}, {4,6} };
        for (int[] e : edges) {
            adj.get(e[0]).add(e[1]);
            adj.get(e[1]).add(e[0]);
        }
        for (List<Integer> list : adj) Collections.sort(list);

        bfs(adj, 0);                          // 0 1 2 3 4 5 6
        dfs(adj, 0, new boolean[n]);          // 0 1 3 6 4 2 5
    }
}
```

**(c) Mathematical proof of spanning tree edge counts:**

Exactly $E - (V - 1) = 10 - 8 = \mathbf{2\text{ edges}}$ are discarded as non-tree edges in both cases.

**3.** *(Adjacency matrix vs adjacency list: memory calculation and Handshaking Lemma)* A university department analyzes a campus network graph with $V = 10{,}000$ computer hosts and $E = 50{,}000$ undirected communication links (average degree $2E/V = 10$).
1. Suppose the graph is stored as an adjacency matrix of 8-bit bytes (`byte[][]`, 1 byte per cell). Calculate the exact memory required for the matrix in megabytes ($1\text{ MB} = 10^6\text{ bytes}$).
2. Suppose the graph is stored as an adjacency list in Java. Each vertex has a 4-byte reference list header, and each directed endpoint of an edge is stored as a 4-byte primitive integer (`int`). For an undirected graph, calculate the exact number of integer elements stored across all lists, the total memory consumed, and the ratio of memory saved by using the adjacency list.
3. State the **Handshaking Lemma** and prove why the inner loop of BFS and DFS over all vertices runs in aggregate $\Theta(E)$ time rather than $O(V \times E)$ time.

<ModelAnswer>
**(a) Adjacency matrix memory:**
- An adjacency matrix for $V$ vertices allocates a $V \times V$ grid.
- Total cell count:
  $$
  V^2 = 10{,}000 \times 10{,}000 = 100{,}000{,}000\text{ cells}
  $$
- At 1 byte per cell:
  $$
  100{,}000{,}000\text{ bytes} = \mathbf{100\text{ MB}} \quad (\text{or } 100 \times 10^6 / 2^{20} \approx 95.37\text{ MiB})
  $$
- In this matrix, only $2E = 100{,}000$ entries contain `1` (a matrix density of $0.1\%$). Over $99.9\%$ of the allocated memory stores `0`s.

**(b) Adjacency list memory and savings ratio:**
- In an undirected graph, each edge $(u, v)$ connects two endpoints, so it is recorded twice: vertex $u$'s list contains $v$, and vertex $v$'s list contains $u$.
- Total edge entries stored across all lists:
  $$
  2E = 2 \times 50{,}000 = \mathbf{100{,}000\text{ integer entries}}
  $$
- Together with the $V = 10{,}000$ list header references, the structure stores:
  $$
  V + 2E = 10{,}000 + 100{,}000 = \mathbf{110{,}000\text{ entries}}
  $$
- At 4 bytes per entry:
  $$
  110{,}000 \times 4\text{ bytes} = 440{,}000\text{ bytes} = \mathbf{0.44\text{ MB}} \quad (\approx 430\text{ KiB})
  $$
- **Space savings ratio:**
  $$
  \frac{\text{Matrix memory}}{\text{List memory}} = \frac{100{,}000{,}000\text{ bytes}}{440{,}000\text{ bytes}} \approx \mathbf{227.27\times}
  $$
  The adjacency list requires less than half a megabyte, achieving over a **$227\times$ reduction in memory** compared to the adjacency matrix.

**(c) Handshaking Lemma and aggregate traversal time:**
- **The Handshaking Lemma:** In any undirected graph $G = (V, E)$, the sum of the degrees of all vertices equals twice the number of edges:
  $$
  \sum_{v \in V} \operatorname{deg}(v) = 2E
  $$
  This identity holds because every edge $(u, v)$ connects exactly two vertices, contributing 1 to $\operatorname{deg}(u)$ and 1 to $\operatorname{deg}(v)$.
- **Why BFS and DFS run in $\Theta(V + E)$ and not $O(V \times E)$:**
  - The outer loop/recursion processes each vertex $v$ exactly once, doing $O(1)$ work per vertex: $\sum_{v \in V} 1 = V = \Theta(V)$.
  - When vertex $v$ is visited, the inner loop `for (int w : adj.get(v))` runs for each neighbor of $v$, executing exactly $\operatorname{deg}(v)$ times.
  - Summing the inner loop iterations over all vertices throughout the entire traversal:
    $$
    \sum_{v \in V} \operatorname{deg}(v) = 2E = \Theta(E)
    $$
  - The inner loop does not inspect all $E$ edges for each of the $V$ vertices; it inspects only the incident edges. Across the entire execution, each edge is examined exactly twice (once from each endpoint).
  - Combining the two components gives total running time:
    $$
    \Theta(V) + \Theta(2E) = \mathbf{\Theta(V + E)}
    $$
  - Conversely, with an adjacency matrix, checking neighbors for vertex $v$ requires reading all $V$ entries in row $v$ (even if empty). Summing across all $V$ rows yields $\sum_{v \in V} V = V^2 = \mathbf{\Theta(V^2)}$, making it drastically slower on sparse graphs.
</ModelAnswer>

**4.** *(Traversal bugs: BFS queue explosion and disconnected components)*
1. In BFS, a student writes the visited check inside the while loop as follows:
   ```java
   while (!queue.isEmpty()) {
       int v = queue.poll();
       visited[v] = true; // BUG: marked on dequeue instead of enqueue
       for (int w : adj.get(v)) {
           if (!visited[w]) {
               queue.add(w);
           }
       }
   }
   ```
   Consider a 4-vertex diamond graph with vertices $\{0, 1, 2, 3\}$ and edges $0-1, 0-2, 1-3, 2-3$, starting traversal at vertex 0.
   - Trace the queue contents step by step and demonstrate which vertex is enqueued multiple times.
   - Contrast this with the correct implementation.
   - Explain why on dense or bipartite graphs, this bug causes queue memory to explode from $O(V)$ to $O(E)$, leading to runtime memory crashes or timeouts.
2. An undirected graph has $V = 8$ vertices with edges defining two separate components: Component 1 with vertices $\{0, 1, 2\}$ and Component 2 with vertices $\{3, 4, 5, 6, 7\}$. If a programmer calls `bfs(adj, 0)`, which vertices will be visited? Provide the complete Java code required to traverse all vertices across any disconnected graph, and state its overall time complexity.

<ModelAnswer>
**(a) The BFS queue explosion trace:**
- Trace on 4-vertex diamond graph ($0-1, 0-2, 1-3, 2-3$) starting at 0:
  - **Start:** Add 0 to queue. `queue = [0]`. `visited = [F, F, F, F]`.
  - **Iteration 1:** Poll 0. Mark `visited[0] = true`. Neighbors of 0 are 1 and 2. Neither is visited. Add 1 and 2 to queue.
    `queue = [1, 2]`. `visited = [T, F, F, F]`.
  - **Iteration 2:** Poll 1. Mark `visited[1] = true`. Neighbors of 1 are 0 (visited) and 3 (unvisited). Add 3 to queue.
    `queue = [2, 3]`. `visited = [T, T, F, F]`.
    *Critical moment:* Vertex 3 is currently in the queue, but `visited[3]` remains `false`!
  - **Iteration 3:** Poll 2. Mark `visited[2] = true`. Neighbors of 2 are 0 (visited) and 3. Because `visited[3]` is still `false`, vertex 2 ALSO adds 3 to the queue!
    `queue = [3, 3]`. `visited = [T, T, T, F]`.
  - **The bug:** Vertex 3 is now present in the queue **twice**.
  - **Iterations 4 & 5:** Poll the first 3, setting `visited[3] = true`. Then poll the duplicate 3, which redundantly inspects its incident edges again.
  - Total enqueue operations: **5** (instead of the correct 4).
- **The correct implementation:** Mark `visited[w] = true` immediately before or at the moment of calling `queue.add(w)`. When vertex 2 evaluates neighbor 3, `visited[3]` is already `true`, so the duplicate enqueue is skipped.
- **Why this explodes on larger graphs:** On a complete bipartite graph $K_{2, n}$ or a dense grid, every node in layer $k$ discovers every neighbor in layer $k + 1$. If nodes are marked only on dequeue, every vertex in layer $k + 1$ gets enqueued once by *every single neighbor* in layer $k$. For $m$ edges, the queue stores $O(E)$ redundant elements rather than at most $V$. On large test cases, this causes immediate `OutOfMemoryError` or `TimeLimitExceeded`.

**(b) Disconnected graphs and the full traversal wrapper:**
- When `bfs(adj, 0)` is called, traversal explores only vertices reachable along paths originating from vertex 0. It visits vertices $\{0, 1, 2\}$ in Component 1. Because no edge connects Component 1 to Component 2, vertices $\{3, 4, 5, 6, 7\}$ are never discovered and remain unvisited.
- **Complete traversal wrapper:** To guarantee every vertex is visited regardless of connectivity, wrap the traversal in an outer loop over all vertex indices from $0$ to $V - 1$:
  ```java
  public static void traverseAll(List<List<Integer>> adj) {
      int n = adj.size();
      boolean[] visited = new boolean[n];
      int componentCount = 0;
      for (int i = 0; i < n; i++) {
          if (!visited[i]) {
              componentCount++;
              bfsComponent(adj, i, visited);
          }
      }
      System.out.println("Total connected components: " + componentCount);
  }

  private static void bfsComponent(List<List<Integer>> adj, int start, boolean[] visited) {
      Queue<Integer> queue = new ArrayDeque<>();
      visited[start] = true;
      queue.add(start);
      while (!queue.isEmpty()) {
          int v = queue.poll();
          System.out.print(v + " ");
          for (int w : adj.get(v)) {
              if (!visited[w]) {
                  visited[w] = true;
                  queue.add(w);
              }
          }
      }
  }
  ```
- **Time complexity:** **$\Theta(V + E)$**. The outer loop checks each vertex index once in $\Theta(V)$. Each vertex is enqueued and polled in `bfsComponent` exactly once, and each edge is scanned twice in total across all components.
</ModelAnswer>
