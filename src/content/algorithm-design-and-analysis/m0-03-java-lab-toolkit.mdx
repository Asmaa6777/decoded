# Practical: Arrays, Swaps and a Stopwatch

Almost every algorithms lab follows the same shape: make an array of random numbers, print it, run an algorithm on it, print it again, and time how long it took. The algorithm changes every week. The scaffolding around it doesn't.

So let's build that scaffolding once, properly, and understand every line of it. You'll reuse it in every sorting and searching lesson after this one.

## Arrays in Java, quickly

Java gives you three ways to write the same one-dimensional array declaration:

```java
int[] a;              // preferred style: the type is "array of int"
int b[];              // C-style, also legal
int[] c = new int[10]; // declare and allocate 10 slots, all 0
```

A few facts that matter for algorithms:

- An array has a **fixed size**, set when you create it. `c.length` gives it (no parentheses — it's a field, not a method).
- Indexes go from `0` to `length - 1`. Reading `c[10]` above throws `ArrayIndexOutOfBoundsException`.
- Reading or writing `a[i]` is **$O(1)$** — instant, no matter how big the array is. That's what makes arrays the natural home for sorting algorithms.

Two-dimensional arrays work the same way — an array of arrays:

```java
int[][] grid = new int[3][4];   // 3 rows, 4 columns
grid[1][2] = 7;
int rows = grid.length, cols = grid[0].length;
```

Printing in reverse is just a loop that counts down:

```java
for (int i = a.length - 1; i >= 0; i--)
    System.out.print(a[i] + " ");
```

## The toolkit

Here are the three helper methods every lab uses. Put them in one class and keep it.

```java
public class AlgoLab {

    // Fill the array with random ints in [0, dataRange)
    public static void generateRandomArray(int[] array, int dataRange) {
        for (int i = 0; i < array.length; i++)
            array[i] = (int) (Math.random() * dataRange);
    }

    public static void printArray(int[] array) {
        for (int i = 0; i < array.length; i++)
            System.out.print(array[i] + ", ");
        System.out.println();
    }

    // Exchange the values at positions x and y
    public static void swap(int[] array, int x, int y) {
        int temp = array[x];
        array[x] = array[y];
        array[y] = temp;
    }
}
```

`Math.random()` returns a `double` in $[0, 1)$. Multiply by `dataRange` and cast to `int` and you get a whole number from `0` up to `dataRange - 1`.

<Callout tone="violet" label="Why swap needs the array">
A beginner's version is `swap(int x, int y)` that swaps two ints. It compiles, runs, and does nothing — Java passes primitive values by **copy**, so the method swaps its own private copies. Passing the array works because the method receives a reference to the *same* array, and changes it in place.
</Callout>

You'll see some labs write the parameters in a different order, like `swap(x, y, array)`. That's fine — it's the same three lines inside. Pick one order and stick to it.

## The trap: copying an array

This is the bug that ruins more sorting experiments than anything else:

```java
int[] original = new int[10];
generateRandomArray(original, 100);

int[] copy = original;        // NOT a copy!
selectionSort(copy);
printArray(original);         // ...it's sorted too.
```

`copy = original` copies the **reference**, not the data. Both names now point at the same array. To make a real, independent copy:

```java
int[] copy = original.clone();          // or: Arrays.copyOf(original, original.length)
```

You need this whenever you want to run two algorithms on *the same* random input for a fair race.

## The stopwatch

```java
long start = System.currentTimeMillis();
selectionSort(array);
long end = System.currentTimeMillis();
System.out.println("Took " + (end - start) + " ms");
```

`currentTimeMillis()` counts milliseconds. For small arrays, everything takes "0 ms" — the work finishes before the clock ticks. Two fixes:

- Use `System.nanoTime()` instead, which counts nanoseconds and is meant for measuring durations.
- Make the array bigger. That's the honest fix: analysis is about *large* $n$ anyway.

## Putting it together

```java
public static void main(String[] args) {
    int arraySize = 10, dataRange = 100;
    int[] array = new int[arraySize];
    generateRandomArray(array, dataRange);

    System.out.println("Before:");
    printArray(array);

    long start = System.nanoTime();
    // ... the algorithm of the week goes here ...
    long end = System.nanoTime();

    System.out.println("After:");
    printArray(array);
    System.out.println("Time: " + (end - start) / 1_000_000.0 + " ms");
}
```

## Your turn: two warm-up exercises

These are the classic first-lab exercises. Write them yourself before peeking.

**1. Print the largest number in a random array.** (You already saw the idea in lesson 1.)

**2. Print the sum of all the items in a random array.**

```java
static long sum(int[] a) {
    long total = 0;                 // long, so big arrays don't overflow
    for (int i = 0; i < a.length; i++)
        total += a[i];
    return total;
}
```

Both are $O(n)$: one pass, constant work per element.

## The real experiment

Here's where the stopwatch becomes useful. Once you have selection sort (next lesson), run it at sizes 1,000, 2,000, 4,000 and 8,000 and write the times down.

If an algorithm is $O(n^2)$, doubling $n$ should roughly **quadruple** the time. If it's $O(n)$, doubling $n$ should roughly double it. Watching your own measurements line up with the math is the moment Big-O stops being notation and starts being a prediction.

<Callout tone="sky" label="Make it fair">
Use `.clone()` so every algorithm sorts the same input. Run each size a few times and take the middle value — the first run is often slow while the JVM warms up.
</Callout>
