# Practical: Arrays, Swaps and a Stopwatch

Almost every algorithms lab has the same shape: make an array of random numbers, print it, run an algorithm on it, print it again, and time how long it took. The algorithm changes every week, but the code around it stays the same.

So we'll write that code once and go through every line. You'll reuse it in every sorting and searching lesson after this one.

## Arrays in Java, quickly

Java gives you three ways to write the same one-dimensional array declaration:

```java
int[] a;              // preferred style: the type is "array of int"
int b[];              // C-style, also legal
int[] c = new int[10]; // declare and allocate 10 slots, all 0
```

A few facts that matter for algorithms:

- An array has a **fixed size**, set when you create it. `c.length` gives it, with no parentheses, because it's a field and not a method.
- Indexes go from `0` to `length - 1`. Reading `c[10]` above throws `ArrayIndexOutOfBoundsException`.
- Reading or writing `a[i]` is **$O(1)$**: instant, however big the array is. That's why sorting algorithms work on arrays.

Two-dimensional arrays work the same way, as an array of arrays:

```java
int[][] grid = new int[3][4];   // 3 rows, 4 columns
grid[1][2] = 7;
int rows = grid.length, cols = grid[0].length;
```

Printing in reverse is a loop that counts down:

```java
for (int i = a.length - 1; i >= 0; i--)
    System.out.print(a[i] + " ");
```

## The toolkit

These are the three helper methods every lab uses. Put them in one class and keep it.

```java
public class AlgoLab {

    // Fill the array with random ints in [0, dataRange)
    public static void generateRandomArray(int[] array, int dataRange) {
        for (int i = 0; i < array.length; i++)
            array[i] = (int) (Math.random() * dataRange);
    }

    public static void printArray(int[] array) {
        for (int i = 0; i < array.length; i++)
            System.out.print(array[i] + ", ");
        System.out.println();
    }

    // Exchange the values at positions x and y
    public static void swap(int[] array, int x, int y) {
        int temp = array[x];
        array[x] = array[y];
        array[y] = temp;
    }
}
```

`Math.random()` returns a `double` in $[0, 1)$. Multiply by `dataRange`, cast to `int`, and you get a whole number from `0` up to `dataRange - 1`.

<Callout tone="violet" label="Why swap needs the array">
A beginner's version is `swap(int x, int y)`, which swaps two ints. It compiles and runs, and does nothing, because Java passes primitive values by **copy** and the method swaps its own private copies. Passing the array works because the method gets a reference to the *same* array and changes it in place.
</Callout>

Some labs put the parameters in a different order, like `swap(x, y, array)`. The three lines inside are the same. Pick one order and stick to it.

## The trap: copying an array

This bug ruins more sorting experiments than anything else:

```java
int[] original = new int[10];
generateRandomArray(original, 100);

int[] copy = original;        // NOT a copy!
selectionSort(copy);
printArray(original);         // ...it's sorted too.
```

`copy = original` copies the **reference**, so both names point at the same array. To make a real, independent copy:

```java
int[] copy = original.clone();          // or: Arrays.copyOf(original, original.length)
```

You need this whenever you want a fair race between two algorithms on *the same* random input.

## The stopwatch

```java
long start = System.currentTimeMillis();
selectionSort(array);
long end = System.currentTimeMillis();
System.out.println("Took " + (end - start) + " ms");
```

`currentTimeMillis()` counts milliseconds. For small arrays everything takes "0 ms" because the work finishes before the clock ticks. There are two fixes:

- Use `System.nanoTime()` instead. It counts nanoseconds and is meant for measuring durations.
- Make the array bigger. Analysis is about *large* $n$ anyway.

## Putting it together

```java
public static void main(String[] args) {
    int arraySize = 10, dataRange = 100;
    int[] array = new int[arraySize];
    generateRandomArray(array, dataRange);

    System.out.println("Before:");
    printArray(array);

    long start = System.nanoTime();
    // ... the algorithm of the week goes here ...
    long end = System.nanoTime();

    System.out.println("After:");
    printArray(array);
    System.out.println("Time: " + (end - start) / 1_000_000.0 + " ms");
}
```

## Your turn: two warm-up exercises

These are the usual first-lab exercises. Write them yourself before peeking.

**1. Print the largest number in a random array.** (You saw the idea in lesson 1.)

**2. Print the sum of all the items in a random array.**

```java
static long sum(int[] a) {
    long total = 0;                 // long, so big arrays don't overflow
    for (int i = 0; i < a.length; i++)
        total += a[i];
    return total;
}
```

Both are $O(n)$: one pass, constant work per element.

## The real experiment

This is where the stopwatch earns its place. Once you have selection sort (next lesson), run it at sizes 1,000, 2,000, 4,000 and 8,000 and write the times down.

If an algorithm is $O(n^2)$, doubling $n$ should roughly **quadruple** the time. If it's $O(n)$, doubling $n$ should roughly double it. When your own measurements match the math, Big-O becomes a prediction you can check.

<Callout tone="sky" label="Make it fair">
Use `.clone()` so every algorithm sorts the same input. Run each size a few times and take the middle value, since the first run is often slow while the JVM warms up.
</Callout>
