# Practical: Arrays, Swaps and a Stopwatch

Most algorithms labs share the same structure: generate an array of random numbers, print the initial array, execute an algorithm, print the result, and measure elapsed time. While the algorithm changes each week, the surrounding scaffolding remains identical.

Writing this harness once provides a reusable foundation for every subsequent sorting and searching lab.

## Arrays in Java, quickly

Java gives you three ways to write the same one-dimensional array declaration:

```java
int[] a;              // preferred style: the type is "array of int"
int b[];              // C-style, also legal
int[] c = new int[10]; // declare and allocate 10 slots, all 0
```

The third line demonstrates **instantiation**: `new` allocates array storage in memory. When the elements are already known, you can declare and populate the array immediately using an **initializer list**:

```java
int[] a2 = {12, 24, 16};          // length 3, decided by the list
a = new int[] {10, 20, 30, 40};   // give an existing variable a new array
System.out.println(a[0]);         // 10
System.out.println(a2[2]);        // 16, the third element
System.out.println(a.length);     // 4
```

The compact syntax `{12, 24, 16}` is valid only at declaration time. For subsequent assignments, you must write `new int[] {...}`.

A few facts that matter for algorithms:

- An array has a **fixed size** determined at creation. The property `c.length` returns its capacity without parentheses because length is a field rather than a method.
- Valid indices range from `0` to `length - 1`. Attempting to read index `c[10]` on a 10-element array throws an `ArrayIndexOutOfBoundsException`.
- Reading or writing `a[i]` runs in **$O(1)$** [constant time](/courses/data-structures/arrays-and-memory#memory-is-one-long-array), regardless of array size. Constant-time index access makes arrays the standard structure for in-place sorting algorithms.

Two-dimensional arrays work the same way, as an array of arrays:

```java
int[][] grid = new int[3][4];   // 3 rows, 4 columns
grid[1][2] = 7;
int rows = grid.length, cols = grid[0].length;

int[][] small = {{1, 2}, {4, 5}};   // initializer list: two rows of two
```

To print a 2D array, loop over the rows, and inside that over the columns of each row:

```java
for (int i = 0; i < small.length; i++) {
    System.out.print("row " + i + ": ");
    for (int j = 0; j < small[i].length; j++)
        System.out.print(small[i][j] + " ");
    System.out.println();
}
// row 0: 1 2
// row 1: 4 5
```

Use `small[i].length` when iterating over row elements, rather than assuming every row has length `small[0].length`. In Java, a multidimensional array is an array of arrays, meaning individual rows can have different lengths.

Printing in reverse is a loop that counts down:

```java
for (int i = a.length - 1; i >= 0; i--)
    System.out.print(a[i] + " ");
```

## The toolkit

These are the three helper methods every lab uses. Put them in one class and keep it.

```java
public class AlgoLab {

    // Fill the array with random ints in [0, dataRange)
    public static void generateRandomArray(int[] array, int dataRange) {
        for (int i = 0; i < array.length; i++)
            array[i] = (int) (Math.random() * dataRange);
    }

    public static void printArray(int[] array) {
        for (int i = 0; i < array.length; i++)
            System.out.print(array[i] + ", ");
        System.out.println();
    }

    // Exchange the values at positions x and y
    public static void swap(int[] array, int x, int y) {
        int temp = array[x];
        array[x] = array[y];
        array[y] = temp;
    }
}
```

`Math.random()` returns a `double` in the [half-open interval](/courses/discrete-mathematics/sets#what-a-set-is) $[0, 1)$, meaning values at least 0 and strictly less than 1. Multiplying by `dataRange` scales the interval, and prefixing `(int)` performs a type **cast** that truncates the fractional portion. For example, with `dataRange = 100`, a generated value of $0.734$ scales to $73.4$ and truncates to $73$. Because the maximum random return is strictly below $1.0$, multiplying by 100 never reaches 100, yielding integers from `0` through `dataRange - 1`.

Operator precedence requires parentheses: writing `(int) Math.random() * dataRange` evaluates the cast before the multiplication. Because `Math.random()` is always less than 1, truncating it immediately yields 0, producing an array filled entirely with zeros.

The `swap` method requires a temporary variable `temp` to avoid overwriting data. Tracing `swap(array, 0, 1)` on `[5, 9]` shows the sequence: `temp` stores 5, `array[0]` receives 9, and `array[1]` retrieves `temp` (5), resulting in `[9, 5]`. Omitting `temp` by writing `array[x] = array[y]; array[y] = array[x];` overwrites the original value at index `x` before it can be copied, leaving both slots holding 9.

<ArraySwapVisualizer />

<Callout tone="violet" label="Why swap requires the array reference">
A common pitfall is writing `swap(int x, int y)` to swap two integer variables. That method compiles and runs without error, but has no effect on the caller's variables. Java passes **primitive** arguments (`int`, `long`, `double`, `boolean`) by **value**, meaning the method operates only on local copies. In contrast, an array variable of type `int[]` stores an object **reference** (the memory address of the array). Passing an array copies the reference, allowing the method to modify the original array in place.
</Callout>

Some labs put the parameters in a different order, like `swap(x, y, array)`. The three lines inside are the same. Pick one order and stick to it.

## The trap: copying an array

This bug ruins more sorting experiments than anything else:

```java
int[] original = new int[10];
generateRandomArray(original, 100);

int[] copy = original;        // NOT a copy!
selectionSort(copy);
printArray(original);         // ...it's sorted too.
```

The assignment `copy = original` copies the object reference rather than the underlying array data. Both variables reference the identical array in memory. To create a separate, independent duplicate, clone the array:

```java
int[] copy = original.clone();          // or: Arrays.copyOf(original, original.length)
```

You need this whenever you want a fair race between two algorithms on *the same* random input.

## The stopwatch

```java
long start = System.currentTimeMillis();
selectionSort(array);
long end = System.currentTimeMillis();
System.out.println("Took " + (end - start) + " ms");
```

`System.currentTimeMillis()` measures wall-clock time in milliseconds. For small inputs, fast algorithms complete in less than one millisecond, reporting 0 ms. To measure accurately:

- Use `System.nanoTime()`, which measures elapsed time in nanoseconds and is designed for performance benchmarks.
- Increase the array size $n$ so execution takes measurable time, aligning with asymptotic analysis.

Place **only** the algorithm under test between the timing calls. Handouts that include array initialization or console output inside the timed block inadvertently measure I/O overhead rather than algorithm complexity, because terminal printing is much slower than memory operations.

## Putting it together

```java
public static void main(String[] args) {
    int arraySize = 10, dataRange = 100;
    int[] array = new int[arraySize];
    generateRandomArray(array, dataRange);

    System.out.println("Before:");
    printArray(array);

    long start = System.nanoTime();
    // ... the algorithm of the week goes here ...
    long end = System.nanoTime();

    System.out.println("After:");
    printArray(array);
    System.out.println("Time: " + (end - start) / 1_000_000.0 + " ms");
}
```

`System.nanoTime()` measures in nanoseconds, so dividing by $1{,}000{,}000$ converts the duration to milliseconds. In Java numeric literals, underscores (as in `1_000_000.0`) improve readability and do not affect the value. Appending `.0` produces a floating-point `double` division, preserving fractional milliseconds. Dividing by an integer `1_000_000` would perform integer division, truncating a 0.8 ms elapsed duration down to 0.

## Your turn: three warm-up exercises

These are the usual first-lab exercises. Write them yourself before peeking.

**1. Print the largest number in a random array.** (You saw the idea in [the first lesson](/courses/algorithm-design-and-analysis/what-is-an-algorithm#a-first-algorithm-three-ways).)

**2. Print the sum of all the items in a random array.**

```java
static long sum(int[] a) {
    long total = 0;                 // long, so big arrays don't overflow
    for (int i = 0; i < a.length; i++)
        total += a[i];
    return total;
}
```

**3. Print every position where a value `x` appears.** Unlike a normal search, don't stop at the first match: the array is random, so `x` may appear several times, or not at all.

```java
static void printPositions(int[] a, int x) {
    boolean found = false;
    for (int i = 0; i < a.length; i++) {
        if (a[i] == x) {
            System.out.println(x + " is at index " + i);
            found = true;
        }
    }
    if (!found) System.out.println(x + " is not in the array");
}
```

Using `long` prevents integer overflow. In Java, a 32-bit signed `int` has a maximum value of $2^{31} - 1 \approx 2.14 \times 10^9$. Summing one million integers of up to 10,000 can reach 10 billion, exceeding this bound. When an arithmetic operation exceeds the range of an `int`, Java wraps around to negative values without throwing an exception, leading to silent calculation errors.

All three exercises run in $O(n)$ linear time with one pass and constant work per element. The third exercise always checks every slot, so its best case requires $n$ comparisons as well, unlike [linear search](/courses/algorithm-design-and-analysis/counting-steps#best-worst-and-average-case) which halts upon encountering the first matching element.

## The real experiment

Benchmark measurements allow you to verify theoretical complexity. After implementing [selection sort](/courses/algorithm-design-and-analysis/selection-and-bubble-sort#selection-sort-find-the-smallest-put-it-first) in the next lesson, record execution times across input sizes of 1,000, 2,000, 4,000, and 8,000 elements.

For an $O(n^2)$ algorithm, doubling the input size quadruples execution time because $(2n)^2 = 4n^2$. For an $O(n)$ algorithm, doubling $n$ roughly doubles the duration. Comparing empirical timing against theoretical growth confirms [Big-O](/courses/algorithm-design-and-analysis/counting-steps#the-three-notations) as a predictive tool.

<Callout tone="sky" label="Benchmarking best practices">
Use `.clone()` so every test run sorts identical data. Run multiple trials at each input size and take the median time. Repeating trials mitigates JVM warm-up distortion, where just-in-time (JIT) compilation initially interprets bytecode before compiling frequently executed paths into optimized native machine code.
</Callout>

### Part 1: Lab and written exam questions

**1.** *(Lab 1 & 2)* A student writes the following method to compute the total sum of an integer array:

```java
static int sum(int[] a) {
    int total = 0;
    for (int i = 0; i < a.length; i++) {
        total += a[i];
    }
    return total;
}
```

If the array contains $1{,}000{,}000$ elements, each holding the value $5{,}000$, what happens when this method runs? Calculate the expected mathematical sum and the exact value Java returns, explaining why.

<ModelAnswer>
**Mathematical sum:**
$$
1{,}000{,}000 \times 5{,}000 = \mathbf{5{,}000{,}000{,}000} \quad (5 \times 10^9)
$$

**What happens in Java:**
In Java, a signed 32-bit `int` stores values from $-2^{31}$ to $2^{31} - 1$, where:
$$
2^{31} - 1 = 2{,}147{,}483{,}647
$$

Because $5{,}000{,}000{,}000 > 2{,}147{,}483{,}647$, the sum overflows the 32-bit integer range. In Java, integer arithmetic wraps around modulo $2^{32}$ without throwing an exception or warning.

In two's complement arithmetic, adding values past $2^{31} - 1$ flips into negative values and wraps around by subtracting $2^{32} = 4{,}294{,}967{,}296$:
$$
5{,}000{,}000{,}000 - 4{,}294{,}967{,}296 = \mathbf{705{,}032{,}704}
$$

The method completes silently and returns **$705{,}032{,}704$**, an incorrect positive number.

**Correction:**
Declare the accumulator as a 64-bit `long`:
```java
static long sum(int[] a) {
    long total = 0;
    for (int i = 0; i < a.length; i++) total += a[i];
    return total;
}
```
A signed 64-bit `long` accommodates values up to $2^{63} - 1 \approx 9.22 \times 10^{18}$, comfortably holding the 5 billion total.
</ModelAnswer>

**2.** *(Lab 2 exam problem)* Consider the two swap methods below:

```java
// Method A
public static void swap(int x, int y) {
    int temp = x;
    x = y;
    y = temp;
}

// Method B
public static void swap(int[] a, int i, int j) {
    int temp = a[i];
    a[i] = a[j];
    a[j] = temp;
}
```

What does the following test code output to the console? Explain the difference in behavior.

```java
int[] arr = {10, 20};
swap(arr[0], arr[1]);
System.out.println(arr[0] + ", " + arr[1]);
swap(arr, 0, 1);
System.out.println(arr[0] + ", " + arr[1]);
```

<ModelAnswer>
**Console output:**
```text
10, 20
20, 10
```

**Explanation:**
- **First call `swap(arr[0], arr[1])`:** Method A takes two primitive `int` arguments. Java passes primitive arguments strictly **by value**. The values 10 and 20 are copied into local parameter variables `x` and `y`. Exchanging `x` and `y` modifies only Method A's local stack frame. When Method A returns, that stack frame is discarded, leaving the original array `arr` completely unchanged (`10, 20`).
- **Second call `swap(arr, 0, 1)`:** Method B receives the object reference to `arr` in heap memory. Accessing `a[i]` and `a[j]` modifies the elements stored at those heap locations directly. The values at indices 0 and 1 are exchanged, updating `arr` to `[20, 10]`.
</ModelAnswer>

**3.** *(Lab 1 & 2)* Predict the exact output of this code snippet, and explain the memory difference between reference assignment and `.clone()`:

```java
int[] a = {1, 2, 3};
int[] b = a;
int[] c = a.clone();
b[0] = 99;
c[1] = 88;
System.out.println(a[0] + " " + a[1] + " " + b[0] + " " + c[0] + " " + c[1]);
```

<ModelAnswer>
**Output:**
```text
99 2 99 1 88
```

**Memory explanation:**
- `int[] b = a` performs a **reference copy**. No new array is created. Variables `a` and `b` point to the identical array object in heap memory. When `b[0] = 99` is executed, it modifies the memory slot shared by both variables, so `a[0]` and `b[0]` both evaluate to 99.
- `int[] c = a.clone()` allocates a **new, independent array** in heap memory and copies the values `{1, 2, 3}` into it. Variable `c` references this distinct memory object. When `c[1] = 88` executes, only `c[1]` changes; `a[1]` remains 2. When printed, `c[0]` retains its initial copied value of 1.
</ModelAnswer>

**4.** *(Benchmarking analysis)* During an empirical lab experiment, selection sort ($O(n^2)$) took $15.0\text{ ms}$ to sort a random array of $n = 2{,}000$ integers. Assuming execution time strictly follows $T(n) = c \cdot n^2$:

1. Predict the running time for $n = 4{,}000$.
2. Predict the running time for $n = 8{,}000$.
3. What would the predicted running time for $n = 4{,}000$ be if the algorithm instead had linear time complexity $O(n)$?

<ModelAnswer>
1. **For $n = 4{,}000$:**
   Doubling the input size from $2{,}000$ to $4{,}000$ represents a factor of $k = 2$. For an $O(n^2)$ algorithm, doubling $n$ quadruples the duration ($k^2 = 2^2 = 4$):
   $$
   T(4{,}000) = 15.0\text{ ms} \times 4 = \mathbf{60.0\text{ ms}}
   $$

2. **For $n = 8{,}000$:**
   Doubling $n$ again from $4{,}000$ to $8{,}000$ quadruples the time once more:
   $$
   T(8{,}000) = 60.0\text{ ms} \times 4 = \mathbf{240.0\text{ ms}}
   $$
   (Equivalently, increasing $n$ by $4\times$ from $2{,}000$ scales runtime by $4^2 = 16$: $15.0\text{ ms} \times 16 = 240.0\text{ ms}$.)

3. **If the algorithm were linear $O(n)$:**
   For a linear algorithm, doubling the input size doubles the running time:
   $$
   T(4{,}000) = 15.0\text{ ms} \times 2 = \mathbf{30.0\text{ ms}}
   $$
</ModelAnswer>
