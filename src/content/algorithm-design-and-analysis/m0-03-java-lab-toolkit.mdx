# Practical: Arrays, Swaps and a Stopwatch

Most algorithm labs follow the same pattern: generate an array of random numbers, print it, run an algorithm, print the result, and measure elapsed time. The algorithm changes each week, but the code around it stays the same.

We will write that helper code once and examine each line. You can reuse it across every sorting and searching lesson that follows.

## Arrays in Java, quickly

Java gives you three ways to write the same one-dimensional array declaration:

```java
int[] a;              // preferred style: the type is "array of int"
int b[];              // C-style, also legal
int[] c = new int[10]; // declare and allocate 10 slots, all 0
```

The third line is called **instantiation**: `new` creates the array in memory. If you already know the values, you can declare and fill the array in one go with an **initializer list**:

```java
int[] a2 = {12, 24, 16};          // length 3, decided by the list
a = new int[] {10, 20, 30, 40};   // give an existing variable a new array
System.out.println(a[0]);         // 10
System.out.println(a2[2]);        // 16, the third element
System.out.println(a.length);     // 4
```

The short form `{12, 24, 16}` only works on the line where the array is declared. Anywhere else you need `new int[] {...}`.

A few facts that matter for algorithms:

- An array has a **fixed size**, set when you create it. `c.length` gives it, with no parentheses, because it's a field and not a method.
- Indexes go from `0` to `length - 1`. Reading `c[10]` above throws `ArrayIndexOutOfBoundsException`.
- Reading or writing `a[i]` is **$O(1)$**: it takes constant time regardless of array size. That makes arrays the standard structure for sorting algorithms.

Two-dimensional arrays work the same way, as an array of arrays:

```java
int[][] grid = new int[3][4];   // 3 rows, 4 columns
grid[1][2] = 7;
int rows = grid.length, cols = grid[0].length;

int[][] small = {{1, 2}, {4, 5}};   // initializer list: two rows of two
```

To print a 2D array, loop over the rows, and inside that over the columns of each row:

```java
for (int i = 0; i < small.length; i++) {
    System.out.print("row " + i + ": ");
    for (int j = 0; j < small[i].length; j++)
        System.out.print(small[i][j] + " ");
    System.out.println();
}
// row 0: 1 2
// row 1: 4 5
```

Use `small[i].length` for the inner loop, not `small[0].length`. In Java each row is its own array, and rows are allowed to have different lengths.

Printing in reverse is a loop that counts down:

```java
for (int i = a.length - 1; i >= 0; i--)
    System.out.print(a[i] + " ");
```

## The toolkit

These are the three helper methods every lab uses. Put them in one class and keep it.

```java
public class AlgoLab {

    // Fill the array with random ints in [0, dataRange)
    public static void generateRandomArray(int[] array, int dataRange) {
        for (int i = 0; i < array.length; i++)
            array[i] = (int) (Math.random() * dataRange);
    }

    public static void printArray(int[] array) {
        for (int i = 0; i < array.length; i++)
            System.out.print(array[i] + ", ");
        System.out.println();
    }

    // Exchange the values at positions x and y
    public static void swap(int[] array, int x, int y) {
        int temp = array[x];
        array[x] = array[y];
        array[y] = temp;
    }
}
```

`Math.random()` returns a `double` (a number with a decimal part) in $[0, 1)$: at least 0 and less than 1. Multiply by `dataRange` and **cast** to `int`. A cast, written `(int)`, converts the value to an `int` by cutting off the decimal part. With `dataRange = 100`, a random 0.734 becomes 73.4 and then 73. The largest possible result is just under 100, which cuts to 99, so you get a whole number from `0` up to `dataRange - 1`.

Parentheses matter: `(int) Math.random() * dataRange` applies the cast first. Because `Math.random()` is always less than 1, `(int)` truncates it to 0 before the multiplication, leaving every element as 0.

The `swap` method requires a temporary variable `temp`. Tracing `swap(array, 0, 1)` on `[5, 9]` shows why: `temp` stores 5, `array[0]` becomes 9, and `array[1]` receives `temp` (5), producing `[9, 5]`. A common mistake is omitting `temp` and writing `array[x] = array[y]; array[y] = array[x];`. The first assignment overwrites the 5 before it can be copied to the second slot, leaving `[9, 9]`.

<Callout tone="violet" label="Why swap needs the array">
A beginner's version is `swap(int x, int y)`, which swaps two ints. It compiles and runs, and does nothing. Java passes **primitive** values (the basic types `int`, `long`, `double`, `boolean` and so on) by **copy**, so the method swaps its own private copies and the caller never sees it. An array isn't a primitive. A variable of type `int[]` holds a **reference**, which is the address of where the array lives in memory. Passing the array copies the address, so the method reaches the *same* array and changes it in place.
</Callout>

Some labs put the parameters in a different order, like `swap(x, y, array)`. The three lines inside are the same. Pick one order and stick to it.

## The trap: copying an array

A common trap occurs when trying to duplicate an array for testing:

```java
int[] original = new int[10];
generateRandomArray(original, 100);

int[] copy = original;        // NOT a copy!
selectionSort(copy);
printArray(original);         // ...it's sorted too.
```

`copy = original` copies the **reference** (the address, as in the swap box above), not the elements, so both names point at the same array. To make a real, independent copy:

```java
int[] copy = original.clone();          // or: Arrays.copyOf(original, original.length)
```

You need this whenever you want a fair race between two algorithms on *the same* random input.

## The stopwatch

```java
long start = System.currentTimeMillis();
selectionSort(array);
long end = System.currentTimeMillis();
System.out.println("Took " + (end - start) + " ms");
```

Because `currentTimeMillis()` measures in milliseconds, small arrays often register as 0 ms when execution finishes between clock updates. Two adjustments solve this:

- Use `System.nanoTime()` instead. It counts nanoseconds and is meant for measuring durations.
- Increase array size $n$ so the operation takes measurable time.

Time **only** the algorithm itself. Avoid placing array generation or printing inside the timed block. Console output is much slower than in-memory operations, so including it measures `System.out.print` rather than the algorithm.

## Putting it together

```java
public static void main(String[] args) {
    int arraySize = 10, dataRange = 100;
    int[] array = new int[arraySize];
    generateRandomArray(array, dataRange);

    System.out.println("Before:");
    printArray(array);

    long start = System.nanoTime();
    // ... the algorithm of the week goes here ...
    long end = System.nanoTime();

    System.out.println("After:");
    printArray(array);
    System.out.println("Time: " + (end - start) / 1_000_000.0 + " ms");
}
```

`nanoTime` counts nanoseconds, and a million nanoseconds make a millisecond, so the last line divides by a million. The underscores in `1_000_000.0` are only there to make it readable; Java ignores them. The `.0` makes it a `double`, so the division keeps the decimals. Dividing by the `int` `1_000_000` would cut 0.8 ms down to 0.

## Your turn: three warm-up exercises

These are standard introductory lab exercises. Try solving them before reading the solutions.

**1. Print the largest number in a random array.** (You saw the idea in [the first lesson](/courses/algorithm-design-and-analysis/what-is-an-algorithm#a-first-algorithm-three-ways).)

**2. Print the sum of all the items in a random array.**

```java
static long sum(int[] a) {
    long total = 0;                 // long, so big arrays don't overflow
    for (int i = 0; i < a.length; i++)
        total += a[i];
    return total;
}
```

**3. Print every position where a value `x` appears.** Unlike a normal search, don't stop at the first match: the array is random, so `x` may appear several times, or not at all.

```java
static void printPositions(int[] a, int x) {
    boolean found = false;
    for (int i = 0; i < a.length; i++) {
        if (a[i] == x) {
            System.out.println(x + " is at index " + i);
            found = true;
        }
    }
    if (!found) System.out.println(x + " is not in the array");
}
```

The `sum` method uses `long` for the accumulator because a standard 32-bit `int` cannot exceed approximately 2.1 billion ($2^{31} - 1$). An array of one million values up to 10,000 can sum to 10 billion. When exceeding the integer limit, Java does not throw an error; instead, the value **overflows**, wrapping into a negative number while execution continues with corrupted data.

All three are $O(n)$: one pass, constant work per element. The third always looks at every element, so its best case is $n$ comparisons as well. That's different from the [linear search](/courses/algorithm-design-and-analysis/counting-steps#best-worst-and-average-case) that stops at the first match.

## The real experiment

Timing code allows you to verify theoretical growth rates empirically. Once you implement [selection sort](/courses/algorithm-design-and-analysis/selection-and-bubble-sort#selection-sort-find-the-smallest-put-it-first) in the next lesson, test it with arrays of 1,000, 2,000, 4,000, and 8,000 elements.

If an algorithm is $O(n^2)$, doubling $n$ should roughly **quadruple** the time, because $(2n)^2 = 4n^2$. If it's $O(n)$, doubling $n$ should roughly double it. When your own measurements match the math, [Big-O](/courses/algorithm-design-and-analysis/counting-steps#the-three-notations) becomes a prediction you can check.

</Callout>
