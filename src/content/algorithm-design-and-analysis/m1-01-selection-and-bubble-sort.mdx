# Selection Sort and Bubble Sort

A **sorting algorithm** arranges elements in a specific order: numerical order for numbers, alphabetical order for strings, either ascending or descending. Sorting makes fast searching possible, forms the initial step in many data processing pipelines, and serves as the standard introduction to algorithm analysis.

We begin with two simple algorithms: selection sort and bubble sort. Both require quadratic time, but their operations are easy to trace and count step by step.

## Selection sort: find the smallest, put it first

In **selection sort**, the algorithm finds the smallest element and swaps it into index 0, finds the smallest remaining element and swaps it into index 1, and repeats until the array is ordered.

The array is split in two: a sorted part on the left that grows by one each pass, and an unsorted part on the right that shrinks. Press **Play**, or **Step** through it one comparison at a time and watch the highlighted line of Java underneath move with you.

Exams often ask students to trace sorting pass by pass. The trace below shows each pass for this input:

| Pass | Smallest of the rest | Array after the swap |
| --- | --- | --- |
| start | | 3 7 8 5 2 1 9 5 4 |
| 1 | 1 | **1** 7 8 5 2 3 9 5 4 |
| 2 | 2 | **1 2** 8 5 7 3 9 5 4 |
| 3 | 3 | **1 2 3** 5 7 8 9 5 4 |
| 4 | 4 | **1 2 3 4** 7 8 9 5 5 |
| 5 | 5 | **1 2 3 4 5** 8 9 7 5 |
| 6 | 5 | **1 2 3 4 5 5** 9 7 8 |
| 7 | 7 | **1 2 3 4 5 5 7** 9 8 |
| 8 | 8 | **1 2 3 4 5 5 7 8 9** |

Sorting nine elements takes eight passes. After pass 8, the single remaining element is already in its correct final position.

The notes use a smaller example: 6, 2, 11, 7, 5. Pass 1 finds 2 and swaps it with 6, producing 2, 6, 11, 7, 5. Pass 2 finds 5 and swaps it with 6, producing 2, 5, 11, 7, 6. Pass 3 swaps 6 with 11, producing 2, 5, 6, 7, 11. Pass 4 finds that 7 is already the smaller of 7 and 11, leaving the array unchanged.

The notes write the algorithm in the textbook's pseudocode, where `←` means "gets" (assignment) and `A[0..n − 1]` is an array of $n$ elements:

```text
ALGORITHM SelectionSort(A[0..n − 1])
for i ← 0 to n − 2 do
    min ← i
    for j ← i + 1 to n − 1 do
        if A[j] < A[min]  min ← j
    swap A[i] and A[min]
```

The outer loop stops at index $n - 2$, the second-to-last position. By that point, the final element is already in place.

### Analysis

The input size is $n$, the number of elements. The basic operation is the **key comparison** `A[j] < A[min]`. How often it runs depends only on $n$, not on the values. On pass 1 it runs $n - 1$ times, on pass 2 it runs $n - 2$ times, and so on down to 1:

$$
(n-1) + (n-2) + \dots + 1 = \frac{n(n-1)}{2}
$$

The comparison count is $\Theta(n^2)$, and it remains identical regardless of input order. Even an already sorted array requires $n(n-1)/2$ comparisons, because basic selection sort never checks whether the array is already ordered. Best, average, and worst cases are all $O(n^2)$. (Step through the visualizer with `1, 2, 3, 4, 5` to observe this redundant work.)

<Callout tone="orange" label="Common mistake: swapping too early">
Students often swap every time they find a value smaller than `A[min]`, rather than recording its index in `min` and swapping once at the end of the pass. Swapping repeatedly still sorts the array, but it alters the algorithm: it performs multiple swaps per pass instead of one, and exam trace answers will not match the expected state. Each pass of selection sort must end with **exactly one** swap (which may swap an element with itself).
</Callout>

Selection sort minimizes write operations, performing at most $n - 1$ **swaps**, or at most one swap per pass. When write operations to physical storage are costly or cause hardware wear, this low write count is useful.

Selection sort is also **in place**, meaning it reorganizes elements within the original array rather than allocating auxiliary memory. It requires only a few index variables, so its [space complexity](/courses/algorithm-design-and-analysis/counting-steps#space-is-a-cost-too) is $O(1)$.

## Bubble sort: fix the neighbours

**Bubble sort** repeatedly inspects two adjacent elements at a time. If they are in the wrong order, it swaps them. One complete traversal across the array, called a **pass** (or **scan**), moves the largest remaining element to the end of the unsorted segment. In literature this is described as "bubbling up" or "bubbling down" to its correct position. Subsequent passes repeat this process for the remaining elements.

Here is the notes' example, 6, 2, 11, 7, 5. On each pass `i`, the index `j` walks from 0 and compares `A[j]` with `A[j + 1]`:

| Pass | j | Compare | Array after |
| --- | --- | --- | --- |
| i = 0 | 0 | 6 > 2, swap | 2 6 11 7 5 |
| | 1 | 6 < 11, no swap | 2 6 11 7 5 |
| | 2 | 11 > 7, swap | 2 6 7 11 5 |
| | 3 | 11 > 5, swap | 2 6 7 5 **11** |
| i = 1 | 0, 1 | 2 < 6, 6 < 7 | 2 6 7 5 **11** |
| | 2 | 7 > 5, swap | 2 6 5 **7 11** |
| i = 2 | 0 | 2 < 6 | 2 6 5 **7 11** |
| | 1 | 6 > 5, swap | 2 5 **6 7 11** |
| i = 3 | 0 | 2 < 5, no swap | **2 5 6 7 11** |

Each pass makes one fewer comparison because the suffix of the array is already sorted: 4 + 3 + 2 + 1 = 10 comparisons and 4 swaps. Pass `i = 3` makes zero swaps because 2 and 5 are already in order.

The notes' pseudocode:

```text
ALGORITHM BubbleSort(A[0..n − 1])
for i ← 0 to n − 2 do
    for j ← 0 to n − 2 − i do
        if A[j + 1] < A[j]  swap A[j] and A[j + 1]
```

<SortVisualizer algorithm="bubble" initial={[5, 1, 4, 2, 8, 3]} />

This basic pseudocode always executes all $n - 1$ passes, even if the array becomes sorted early. An optimized variant adds a boolean `swapped` flag. If a complete pass finishes with **zero swaps**, all adjacent elements are in order, meaning the entire array is sorted and the algorithm can terminate immediately. Test this behavior in the visualizer with `1, 2, 3, 4, 5, 6` to observe it finish after one pass.

### Analysis

- **Worst case** (reverse-sorted input): every adjacent pair is inverted, so every comparison triggers a swap. This requires $n(n-1)/2$ comparisons and $n(n-1)/2$ swaps, giving $O(n^2)$.
- **Best case** (already sorted, using the `swapped` flag): one pass of $n - 1$ comparisons makes zero swaps, triggering an early exit in **$O(n)$** time.
- **Average case:** the algorithm performs approximately $n/2$ passes of $O(n)$ comparisons each, yielding $O(n^2)$ total comparisons.

<Callout tone="orange" label="Common mistake: the inner loop's last index">
Because the inner loop accesses both `A[j]` and `A[j + 1]`, `j` must stop before reaching the final index. In Java, the loop bound is `j < array.length - 1 - i`. Setting `j < array.length - i` causes `j + 1` to evaluate to `array.length` on the first pass, throwing an `ArrayIndexOutOfBoundsException`.
</Callout>

Without the flag, bubble sort requires $O(n^2)$ time even on sorted inputs, because the nested loops always run to completion. The $O(n)$ best-case bound applies strictly to the version with early termination. When answering questions regarding the best case of bubble sort, explicitly mention the early termination flag to justify the $O(n)$ running time.

<Callout tone="orange" label="Which one is better?">
Neither algorithm is suitable for large datasets, as both run in $O(n^2)$ on random input. Selection sort performs significantly fewer swaps, whereas bubble sort with an early exit flag can detect sorted data in linear time. Production systems rely on faster algorithms like `Arrays.sort`. These two sorts are studied primarily because their operation counts and nested loop structures illustrate algorithmic analysis clearly.
</Callout>

## Stability

A sorting algorithm is **stable** if elements with equal keys preserve their original relative order after sorting. Bubble sort is stable: it only swaps adjacent elements when they are strictly out of order, so equal values never cross each other. Selection sort is **not stable** because its long-range swaps can displace an earlier duplicate past a later one.

Stability is important during multi-criteria sorting. For example, sorting records by student name and then re-sorting by grade using a stable sort keeps students with equal grades in alphabetical order. An unstable sort can disrupt that initial ordering.

## Side by side

| | Selection sort | Bubble sort (with flag) |
| --- | --- | --- |
| Best case | $O(n^2)$ | $O(n)$ |
| Average case | $O(n^2)$ | $O(n^2)$ |
| Worst case | $O(n^2)$ | $O(n^2)$ |
| Swaps (worst) | $n - 1$ | $n(n-1)/2$ |
| Extra space | $O(1)$ | $O(1)$ |
| Stable? | No | Yes |

## The lab version

Add these to your `AlgoLab` class from the previous lesson, then sort a random array of 1,000 numbers and time it.

```java
public static void selectionSort(int[] array) {
    for (int i = 0; i < array.length - 1; i++) {
        int currentMin = i;
        for (int j = i + 1; j < array.length; j++)
            if (array[j] < array[currentMin])
                currentMin = j;
        swap(array, i, currentMin);
    }
}

public static void bubbleSort(int[] array) {
    for (int i = 0; i < array.length - 1; i++) {
        boolean swapped = false;
        for (int j = 0; j < array.length - 1 - i; j++)
            if (array[j + 1] < array[j]) {
                swap(array, j, j + 1);
                swapped = true;
            }
        if (!swapped) break;
    }
}
```

The lab benchmarks both algorithms on identical datasets: it populates `array_1`, clones it into `array_2 = array_1.clone()`, and measures execution times using `System.currentTimeMillis()`. Without creating an independent copy, the second algorithm would receive an already sorted array, distorting the timing comparison.

Measure execution times at input sizes of 2,000 and 4,000 elements. Because both algorithms have quadratic complexity, doubling $n$ approximately quadruples execution time.

<Callout tone="orange" label="Errors in the lab sheet">
The original lab handout calls `Selection_Sort(array_1)`, whereas the method definition is named `SelectionSort`; matching the identifiers resolves the compilation error. Additionally, its `BubbleSort` loop uses `i <= array.length - 1`, executing one redundant pass where no comparisons occur. Its helper method signature places the array parameter last as `(x, y, array)`, while the code above uses the standardized toolkit method `swap(array, i, j)`.
</Callout>
