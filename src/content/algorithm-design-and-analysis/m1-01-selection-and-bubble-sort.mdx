# Selection Sort and Bubble Sort

A **sorting algorithm** puts the elements of a list in order — numerical order for numbers, lexical (dictionary) order for strings, ascending or descending. It sounds like a small problem. It isn't. Sorted data is what makes fast searching possible (module 2), it's the first step of countless data-analysis and machine-learning pipelines, and it's been studied so thoroughly that it's become the standard way to *teach* algorithm analysis.

We start with the two simplest sorts. Both are slow. That's the point: they're slow in a way you can see and count, which makes them the perfect place to practise analysis.

## Selection sort: find the smallest, put it first

The idea fits in one sentence: **find the smallest element, swap it into position 0; find the smallest of what's left, swap it into position 1; repeat.**

The array is split in two: a sorted part on the left that grows by one each pass, and an unsorted part on the right that shrinks. Press **Play** — or **Step** through it one comparison at a time and watch the highlighted line of Java underneath move with you.

That input isn't random — it's the kind of list exam questions ask you to sort "in steps." Here's what the answer looks like, one line per pass:

| Pass | Smallest of the rest | Array after the swap |
| --- | --- | --- |
| start | | 3 7 8 5 2 1 9 5 4 |
| 1 | 1 | **1** 7 8 5 2 3 9 5 4 |
| 2 | 2 | **1 2** 8 5 7 3 9 5 4 |
| 3 | 3 | **1 2 3** 5 7 8 9 5 4 |
| 4 | 4 | **1 2 3 4** 7 8 9 5 5 |
| 5 | 5 | **1 2 3 4 5** 8 9 7 5 |
| 6 | 5 | **1 2 3 4 5 5** 9 7 8 |
| 7 | 7 | **1 2 3 4 5 5 7** 9 8 |
| 8 | 8 | **1 2 3 4 5 5 7 8 9** |

Nine elements, eight passes. After pass 8 the last element is automatically in place — there's nothing left to compare it with.

### Analysis

The basic operation is the comparison `a[j] < a[min]`. On pass 1 it runs $n - 1$ times, on pass 2 it runs $n - 2$ times, and so on down to 1:

$$
(n-1) + (n-2) + \dots + 1 = \frac{n(n-1)}{2}
$$

That's $\Theta(n^2)$ — and notice it's the same number **no matter what the input looks like**. Already sorted? Still $n(n-1)/2$ comparisons, because selection sort never checks whether it could stop early. Best, average and worst case are all $O(n^2)$. (Step through the visualizer with the array `1, 2, 3, 4, 5` to see it doing all that useless work.)

What selection sort *is* good at is **swaps**: at most $n - 1$ of them, one per pass. If writing to memory is expensive — think flash storage that wears out — that's a real advantage.

It's also **in place**: it needs no extra array, just a couple of index variables. Space complexity $O(1)$.

## Bubble sort: fix the neighbours

Bubble sort only ever looks at **two neighbours at a time**. If they're in the wrong order, swap them. Walk across the whole array doing that, and the biggest element gets carried all the way to the end — it "bubbles up." Then do it again for the next biggest, and so on.

<SortVisualizer algorithm="bubble" initial={[5, 1, 4, 2, 8, 3]} />

The version above has one important improvement: a `swapped` flag. If a full pass makes **no swaps at all**, every neighbour is already in order — so the whole array is sorted, and we can stop. Try it with `1, 2, 3, 4, 5, 6` and watch it quit after a single pass.

### Analysis

- **Worst case** (reverse-sorted input): every comparison causes a swap. $n(n-1)/2$ comparisons and $n(n-1)/2$ swaps. $O(n^2)$.
- **Best case** (already sorted, with the `swapped` flag): one pass of $n - 1$ comparisons, zero swaps, stop. **$O(n)$.**
- **Average case:** $O(n^2)$.

Without the flag, bubble sort is $O(n^2)$ even in the best case. That flag is the difference between a correct answer and a full-marks answer on "what is the best case of bubble sort?"

<Callout tone="orange" label="Which one is better?">
Neither, really — both are $O(n^2)$ on typical input. Selection sort does far fewer swaps. Bubble sort can stop early on nearly sorted data. In real code you'd use neither; you'd use `Arrays.sort`. You learn them because they make the cost of an algorithm *visible*.
</Callout>

## Stability

A sort is **stable** if equal elements stay in the same relative order they started in. Bubble sort is stable: it only swaps neighbours that are *strictly* out of order, so two equal values never jump over each other. Selection sort is **not** stable: its long-distance swap can fling an element past an equal one.

Why care? Sort a list of students by name, then sort it again by grade with a stable sort: students with the same grade are still in alphabetical order. With an unstable sort, that first ordering gets scrambled.

## Side by side

| | Selection sort | Bubble sort (with flag) |
| --- | --- | --- |
| Best case | $O(n^2)$ | $O(n)$ |
| Average case | $O(n^2)$ | $O(n^2)$ |
| Worst case | $O(n^2)$ | $O(n^2)$ |
| Swaps (worst) | $n - 1$ | $n(n-1)/2$ |
| Extra space | $O(1)$ | $O(1)$ |
| Stable? | No | Yes |

## The lab version

Drop these into your `AlgoLab` class from the previous lesson, then sort a random array of 1,000 numbers and time it.

```java
public static void selectionSort(int[] array) {
    for (int i = 0; i < array.length - 1; i++) {
        int currentMin = i;
        for (int j = i + 1; j < array.length; j++)
            if (array[j] < array[currentMin])
                currentMin = j;
        swap(array, i, currentMin);
    }
}

public static void bubbleSort(int[] array) {
    for (int i = 0; i < array.length - 1; i++) {
        boolean swapped = false;
        for (int j = 0; j < array.length - 1 - i; j++)
            if (array[j + 1] < array[j]) {
                swap(array, j, j + 1);
                swapped = true;
            }
        if (!swapped) break;
    }
}
```

Then run the experiment: time both at 2,000 and 4,000 elements. Doubling $n$ should roughly quadruple both times.
