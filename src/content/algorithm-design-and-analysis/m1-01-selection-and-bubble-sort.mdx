# Selection Sort and Bubble Sort

A **sorting algorithm** puts the elements of a list in order: numerical order for numbers, lexical (dictionary) order for strings, ascending or descending. The problem looks small, but sorted data is what makes fast searching possible (module 2), sorting is the first step of many data-analysis and machine-learning pipelines, and it has been studied so thoroughly that it's the standard way to *teach* algorithm analysis.

We start with the two simplest sorts. Both are slow, and you can see and count exactly where the time goes, which makes them good practice for analysis.

## Selection sort: find the smallest, put it first

The idea fits in one sentence: **find the smallest element and swap it into position 0, find the smallest of what's left and swap it into position 1, and repeat.**

The array is split in two: a sorted part on the left that grows by one each pass, and an unsorted part on the right that shrinks. Press **Play**, or **Step** through it one comparison at a time and watch the highlighted line of Java underneath move with you.

<SortVisualizer algorithm="selection" initial={[3, 7, 8, 5, 2, 1, 9, 5, 4]} />

That input is the kind of list exam questions ask you to sort "in steps." The answer looks like this, one line per pass:

| Pass | Smallest of the rest | Array after the swap |
| --- | --- | --- |
| start | | 3 7 8 5 2 1 9 5 4 |
| 1 | 1 | **1** 7 8 5 2 3 9 5 4 |
| 2 | 2 | **1 2** 8 5 7 3 9 5 4 |
| 3 | 3 | **1 2 3** 5 7 8 9 5 4 |
| 4 | 4 | **1 2 3 4** 7 8 9 5 5 |
| 5 | 5 | **1 2 3 4 5** 8 9 7 5 |
| 6 | 5 | **1 2 3 4 5 5** 9 7 8 |
| 7 | 7 | **1 2 3 4 5 5 7** 9 8 |
| 8 | 8 | **1 2 3 4 5 5 7 8 9** |

Nine elements take eight passes. After pass 8 the last element is already in place, since there's nothing left to compare it with.

The notes use a smaller example, 6, 2, 11, 7, 5. Pass 1 finds 2 and swaps it with 6, giving 2, 6, 11, 7, 5. Pass 2 finds 5 and swaps it with 6, giving 2, 5, 11, 7, 6. Pass 3 swaps 6 with 11, giving 2, 5, 6, 7, 11. Pass 4 finds that 7 is already the smaller of 7 and 11, so nothing moves.

The notes write the algorithm in the textbook's pseudocode, where `←` means "gets" (assignment) and `A[0..n − 1]` is an array of $n$ elements:

```text
ALGORITHM SelectionSort(A[0..n − 1])
for i ← 0 to n − 2 do
    min ← i
    for j ← i + 1 to n − 1 do
        if A[j] < A[min]  min ← j
    swap A[i] and A[min]
```

The outer loop stops at $n - 2$, the second-to-last index, for the reason above: by then the last element has nowhere else to go.

### Analysis

The input size is $n$, the number of elements. The basic operation is the **key comparison** `A[j] < A[min]`. How often it runs depends only on $n$, not on the values. On pass 1 it runs $n - 1$ times, on pass 2 it runs $n - 2$ times, and so on down to 1:

$$
(n-1) + (n-2) + \dots + 1 = \frac{n(n-1)}{2}
$$

That's $\Theta(n^2)$, and it's the same number **whatever the input looks like**. An already sorted array still costs $n(n-1)/2$ comparisons, because selection sort never checks whether it could stop early. Best, average and worst case are all $O(n^2)$. (Step through the visualizer with `1, 2, 3, 4, 5` to watch it do all that useless work.)

Where selection sort does well is **swaps**: at most $n - 1$ of them, one per pass. If writing to memory is expensive, as on flash storage that wears out, that's a real advantage.

It's also **in place**. It needs no extra array, only a couple of index variables, so its [space complexity](/courses/algorithm-design-and-analysis/counting-steps#space-is-a-cost-too) is $O(1)$.

## Bubble sort: fix the neighbours

Bubble sort only ever looks at **two neighbours at a time**. If they're in the wrong order, it swaps them. One walk across the array, called a **pass** (the notes also say a **scan**), carries the biggest element all the way to the end. People say it "bubbles up"; the notes say it "bubbles down" to its correct position. Both mean the same move. Then the next pass does the same for the next biggest, and so on.

Here is the notes' example, 6, 2, 11, 7, 5. On each pass `i`, the index `j` walks from 0 and compares `A[j]` with `A[j + 1]`:

| Pass | j | Compare | Array after |
| --- | --- | --- | --- |
| i = 0 | 0 | 6 > 2, swap | 2 6 11 7 5 |
| | 1 | 6 < 11, no swap | 2 6 11 7 5 |
| | 2 | 11 > 7, swap | 2 6 7 11 5 |
| | 3 | 11 > 5, swap | 2 6 7 5 **11** |
| i = 1 | 0, 1 | 2 < 6, 6 < 7 | 2 6 7 5 **11** |
| | 2 | 7 > 5, swap | 2 6 5 **7 11** |
| i = 2 | 0 | 2 < 6 | 2 6 5 **7 11** |
| | 1 | 6 > 5, swap | 2 5 **6 7 11** |
| i = 3 | 0 | 2 < 5, no swap | **2 5 6 7 11** |

Each pass compares one pair fewer, because the end of the array is already done: 4 + 3 + 2 + 1 = 10 comparisons and 4 swaps. Pass `i = 3` swaps nothing, since 2 and 5 are already in place.

The notes' pseudocode:

```text
ALGORITHM BubbleSort(A[0..n − 1])
for i ← 0 to n − 2 do
    for j ← 0 to n − 2 − i do
        if A[j + 1] < A[j]  swap A[j] and A[j + 1]
```

<SortVisualizer algorithm="bubble" initial={[5, 1, 4, 2, 8, 3]} />

That pseudocode always runs all $n - 1$ passes, even when the array is sorted after the first one. The notes call the fix the **optimization of bubble sort**, and the visualizer uses it: a `swapped` flag. If a full pass makes **no swaps at all**, every neighbour is in order, so the whole array is sorted and we can stop. Try it with `1, 2, 3, 4, 5, 6` and watch it quit after one pass.

### Analysis

- **Worst case** (reverse-sorted input): every comparison causes a swap. $n(n-1)/2$ comparisons and $n(n-1)/2$ swaps. $O(n^2)$.
- **Best case** (already sorted, with the `swapped` flag): one pass of $n - 1$ comparisons, zero swaps, stop. **$O(n)$.**
- **Average case:** the notes reason that it needs about $n/2$ passes of $O(n)$ comparisons each, and $n/2 \times n$ is still $O(n^2)$.

Without the flag, bubble sort is $O(n^2)$ even in the best case. The notes give the best case as $O(n)$ right after the pseudocode without the flag, and that pseudocode can't stop early, so it does $n(n-1)/2$ comparisons on sorted input too. The $O(n)$ answer belongs to the optimized version. On "what is the best case of bubble sort?", mentioning the flag is what gets full marks.

<Callout tone="orange" label="Which one is better?">
Neither, really, since both are $O(n^2)$ on typical input. Selection sort does far fewer swaps, and bubble sort can stop early on nearly sorted data. Real code uses `Arrays.sort` instead of either. You learn them because they make the cost of an algorithm easy to see.
</Callout>

## Stability

A sort is **stable** if equal elements keep the relative order they started in. Bubble sort is stable: it only swaps neighbours that are *strictly* out of order, so two equal values never jump over each other. Selection sort is **not** stable, because its long-distance swap can move an element past an equal one.

Step through the first visualizer to see the moment it happens: in pass 4, swapping the minimum 4 into index 3 throws 5ᵃ to the far end, behind 5ᵇ.

Here's why that matters. Sort a list of students by name, then sort it again by grade with a stable sort, and students with the same grade stay in alphabetical order. An unstable sort can scramble that first ordering.

## Side by side

| | Selection sort | Bubble sort (with flag) |
| --- | --- | --- |
| Best case | $O(n^2)$ | $O(n)$ |
| Average case | $O(n^2)$ | $O(n^2)$ |
| Worst case | $O(n^2)$ | $O(n^2)$ |
| Swaps (worst) | $n - 1$ | $n(n-1)/2$ |
| Extra space | $O(1)$ | $O(1)$ |
| Stable? | No | Yes |

## The lab version

Add these to your `AlgoLab` class from the previous lesson, then sort a random array of 1,000 numbers and time it.

```java
public static void selectionSort(int[] array) {
    for (int i = 0; i < array.length - 1; i++) {
        int currentMin = i;
        for (int j = i + 1; j < array.length; j++)
            if (array[j] < array[currentMin])
                currentMin = j;
        swap(array, i, currentMin);
    }
}

public static void bubbleSort(int[] array) {
    for (int i = 0; i < array.length - 1; i++) {
        boolean swapped = false;
        for (int j = 0; j < array.length - 1 - i; j++)
            if (array[j + 1] < array[j]) {
                swap(array, j, j + 1);
                swapped = true;
            }
        if (!swapped) break;
    }
}
```

The lab sorts **the same** random numbers with both: it fills `array_1`, makes `array_2 = array_1.clone()`, and times each sort with `System.currentTimeMillis()`. Without the copy, the second sort would get an array the first one had already sorted, and bubble sort would look unfairly fast.

Then run the experiment: time both at 2,000 and 4,000 elements. Doubling $n$ should roughly quadruple both times.

<Callout tone="orange" label="Errors in the lab sheet">
The lab's `main` calls `Selection_Sort(array_1)`, but the method is named `SelectionSort`, so it won't compile until the names match. Its `BubbleSort` loops `i <= array.length - 1`, one pass more than needed: the last pass compares nothing, so the result is still right. Its `swap` takes `(x, y, array)`, with the array last. The version above uses the toolkit's `swap(array, i, j)`.
</Callout>
