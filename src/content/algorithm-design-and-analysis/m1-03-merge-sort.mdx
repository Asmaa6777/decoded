# Divide and Conquer: Merge Sort

Selection, bubble and [insertion sort](/courses/algorithm-design-and-analysis/insertion-sort#the-idea) all work the same basic way: fix one element at a time, and to fix each one, look at (almost) everything else. That's where the $n^2$ comes from: $n$ elements, $n$ work each.

A cleverer loop won't beat $n^2$. You need a different *strategy*, and the first one we'll study is the most important design idea in this course.

## Divide and conquer

Three steps:

1. **Divide** the problem into smaller subproblems of the same kind.
2. **Conquer** each subproblem by solving it recursively. Once a subproblem is small enough, solve it directly. That's the **base case**.
3. **Combine** the sub-solutions into a solution for the whole problem.

If that sounds like recursion, it is. Divide and conquer is recursion where you make the problem smaller *in a way that makes combining cheap*.

The notes describe it twice. Once as two parts, **divide** (split into subproblems and solve them recursively) and **conquer** (build the answer from the sub-answers), and once as the three steps above. The two-part version folds "solve" into divide and calls the combine step "conquer". If an exam asks for the steps, give the three: divide, conquer, combine.

The notes list three places the strategy is used: the **maximum and minimum problem** (find the largest and smallest of each half, then compare the two winners), [binary search](/courses/algorithm-design-and-analysis/linear-and-binary-search#binary-search-throw-away-half), and sorting, with merge sort and quick sort.

## Merge sort in one paragraph

To sort an array: split it in half, sort the left half, sort the right half, then **merge** the two sorted halves into one sorted array. How do you sort each half? The same way: split it, sort the halves, merge. Keep splitting until the pieces have one element each. A one-element array is already sorted, so that's the base case, and everything else is merging.

## The merge step

Merging two sorted lists is easy, and it's where merge sort does its work. Think of two sorted piles of exam papers, smallest on top. Look at the top paper of each pile, take the smaller one, and put it on the output pile. Repeat. When one pile runs out, put the rest of the other pile on top, since it's already sorted.

Each comparison places exactly one element, so merging two halves with $n$ elements in total takes **$O(n)$** time. (The notes write $\Theta(n)$: the merge fills all $n$ output slots, so it can't take less either.)

The notes merge `L = 2, 6, 11` and `R = 4, 5, 7` into `A` with three indexes: `i` for the left list, `j` for the right, `k` for the output.

| Step | Compare | Take | A so far | i, j, k after |
| --- | --- | --- | --- | --- |
| 1 | 2 vs 4 | 2 | 2 | 1, 0, 1 |
| 2 | 6 vs 4 | 4 | 2 4 | 1, 1, 2 |
| 3 | 6 vs 5 | 5 | 2 4 5 | 1, 2, 3 |
| 4 | 6 vs 7 | 6 | 2 4 5 6 | 2, 2, 4 |
| 5 | 11 vs 7 | 7 | 2 4 5 6 7 | 2, 3, 5 |
| 6 | R is empty | 11 | 2 4 5 6 7 11 | 3, 3, 6 |

At step 6 the right list has run out, so the rest of the left list (just 11) is copied over without comparing. That's safe because the left list is already sorted.

The notes give the textbook's pseudocode for the merge. A past exam asked for exactly this, so it's worth being able to write it:

```text
ALGORITHM Merge(B[0..p − 1], C[0..q − 1], A[0..p + q − 1])
// merges two sorted arrays B and C into one sorted array A
i ← 0; j ← 0; k ← 0
while i < p and j < q do
    if B[i] ≤ C[j]
        A[k] ← B[i]; i ← i + 1
    else
        A[k] ← C[j]; j ← j + 1
    k ← k + 1
if i = p
    copy C[j..q − 1] to A[k..p + q − 1]
else
    copy B[i..p − 1] to A[k..p + q − 1]
```

`B` has $p$ elements and `C` has $q$. When `i = p`, `B` is used up, so the rest of `C` goes to the end; otherwise the rest of `B` does.

## Analysis: where $n \log n$ comes from

Look at the split diagram again as layers.

- **How many layers?** Each layer halves the pieces. Starting from $n$, you can halve about $\log_2 n$ times before reaching size 1. For a million elements, that's only about 20 layers.
- **How much work per layer?** Every element gets merged exactly once on each layer. That's $O(n)$ work per layer.

$$
\underbrace{\log_2 n}_{\text{layers}} \times \underbrace{n}_{\text{work per layer}} = O(n \log n)
$$

Merge sort *always* splits exactly in half, whatever the data looks like, so best, average and worst case are all **$O(n \log n)$**. No input makes it slow.

Go back to the [growth table](/courses/algorithm-design-and-analysis/counting-steps) and compare $n^2$ with $n \log n$ at a million. One takes hours and the other a fraction of a second.

<Callout tone="orange" label="The price">
Merge sort is **not in place**. The merge step needs a temporary array as big as the piece being merged, which is $O(n)$ extra memory. When memory is tight, that matters. ([Quick sort](/courses/algorithm-design-and-analysis/quick-sort#the-idea), next lesson, avoids it.)
</Callout>

Two more properties:

- **Stable.** When the two fronts are equal, the merge takes from the *left* half first (`a[i] <= a[j]`). Equal elements keep their original order.
- **Great for huge data.** Merging only ever reads each list front to back, so it works even when the data is too big for memory and lives on disk.

Advanced Algorithms applies the same strategy to powering numbers and multiplying matrices, in [divide and conquer](/courses/advanced-algorithms/divide-and-conquer).

## The lab version

Labs often write merge sort slightly differently. Instead of passing index ranges, each call copies its halves into **new** arrays. It's the same algorithm and a bit easier to read:

```java
public static void mergeSort(int[] input) {
    int n = input.length;
    if (n < 2) return;                      // base case

    int mid = n / 2;
    int[] left = new int[mid];
    int[] right = new int[n - mid];
    for (int i = 0; i < mid; i++) left[i] = input[i];
    for (int i = mid; i < n; i++) right[i - mid] = input[i];

    mergeSort(left);                        // conquer
    mergeSort(right);
    merge(input, left, right);              // combine
}

private static void merge(int[] input, int[] left, int[] right) {
    int i = 0, j = 0, k = 0;
    while (i < left.length && j < right.length) {
        if (left[i] <= right[j]) input[k++] = left[i++];
        else                     input[k++] = right[j++];
    }
    while (i < left.length)  input[k++] = left[i++];
    while (j < right.length) input[k++] = right[j++];
}
```
