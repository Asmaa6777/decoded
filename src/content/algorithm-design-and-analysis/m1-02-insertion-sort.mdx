# Insertion Sort: Sorting Like a Card Player

Insertion sort mirrors how people commonly organize playing cards in hand. A person holds sorted cards in one hand, picks the next card from the table, shifts larger cards aside to make space, and places the card in its sorted spot. Repeating this procedure until no cards remain completes the sort.

## The idea

In **insertion sort**, the algorithm maintains two contiguous partitions of an array:

- **Left partition:** elements that are already sorted relative to each other.
- **Right partition:** elements awaiting placement.

Each step extracts the first element of the unsorted partition, known as the **key**, and inserts it into its proper position within the sorted segment. To make space, every sorted element larger than the key **shifts one position right**.

In the visualizer above, watch the purple **key** indicator. As elements larger than the key shift right, they leave open the target slot. When the comparison encounters an element less than or equal to the key, or reaches the beginning of the array, the key drops into place.

The notes walk through 6, 2, 11, 7, 5. The first element counts as already sorted, so the work starts with the second:

| Key | Compared with | What moves | Array after |
| --- | --- | --- | --- |
| 2 | 6 | 2 < 6: shift 6 right, put 2 in front | **2 6** 11 7 5 |
| 11 | 6 | 11 > 6: nothing shifts | **2 6 11** 7 5 |
| 7 | 11, 6 | 7 < 11: shift 11; 7 > 6, stop | **2 6 7 11** 5 |
| 5 | 11, 7, 6, 2 | 5 < 11, 7, 6: shift all three; 5 > 2, stop | **2 5 6 7 11** |

Comparisons proceed backwards from the end of the sorted prefix. Because 11 is greater than 6 (the largest value in the sorted prefix), it requires only a single comparison.

The notes' pseudocode, in the textbook's notation:

```text
ALGORITHM InsertionSort(A[0..n − 1])
for i ← 1 to n − 1 do
    key ← A[i]
    j ← i − 1
    while j ≥ 0 and A[j] > key do
        A[j + 1] ← A[j]
        j ← j − 1
    A[j + 1] ← key
```

The assignment `A[j + 1] ← key` executes once per outer iteration, immediately after the inner `while` loop finishes.

### An exam answer in steps

Exams frequently ask for step-by-step traces showing each shifted key. For the sequence 1, 12, 46, 6, 37, 5, 46, 3, 32, values that are already larger than the preceding prefix (12, the first 46, and the second 46) remain in place:

| Key | Smaller than | Array after |
| --- | --- | --- |
| 6 | 46, 12 | 1 **6** 12 46 37 5 46 3 32 |
| 37 | 46 | 1 6 12 **37** 46 5 46 3 32 |
| 5 | 46, 37, 12, 6 | 1 **5** 6 12 37 46 46 3 32 |
| 3 | 46, 46, 37, 12, 6, 5 | 1 **3** 5 6 12 37 46 46 32 |
| 32 | 46, 46, 37 | 1 3 5 6 12 **32** 37 46 46 |

The duplicate value 46 remains behind the first 46 because the condition shifts only values strictly greater than the key. This strict inequality preserves stability. Each step shifts an element leftward into position, which distinguishes an insertion sort trace from [selection sort](/courses/algorithm-design-and-analysis/selection-and-bubble-sort#selection-sort-find-the-smallest-put-it-first), where each pass swaps the minimum value forward.

Additionally, insertion sort **shifts** elements rather than performing repeated swaps like [bubble sort](/courses/algorithm-design-and-analysis/selection-and-bubble-sort#bubble-sort-fix-the-neighbours). Shifting requires one assignment per step rather than three, making insertion sort noticeably faster in practice despite sharing the same [Big-O](/courses/algorithm-design-and-analysis/counting-steps#the-three-notations) worst-case class.

## Analysis

The basic operation is the comparison `a[j] > key` in the `while` condition.

- **Worst case** (reverse-sorted input): each incoming key is smaller than all preceding elements, shifting all the way to the front. The $i$-th element requires $i$ comparisons, producing:

$$
1 + 2 + \dots + (n-1) = \frac{n(n-1)}{2} = O(n^2)
$$

- **Best case** (already sorted input): every key is greater than the preceding element. The `while` condition fails immediately on its first check, leaving the key in place. This requires one comparison per element, yielding **$O(n)$** comparisons.

- **Average case**: for randomly ordered input, each key travels roughly halfway through the sorted prefix. This requires approximately $n^2 / 4$ comparisons, which remains $O(n^2)$.

Insertion sort is inefficient for large random datasets due to its quadratic worst and average cases. However, it requires significantly fewer operations when the array is already partially sorted.

Test this behavior in the visualizer: enter `1, 2, 3, 4, 5, 6, 7` to count the minimal comparisons, and then enter `7, 6, 5, 4, 3, 2, 1` to observe the worst case.

## Why it's the best of the simple sorts

The execution time of **insertion sort** depends directly on the initial order of input elements. If every item is within a few positions of where it belongs (a nearly sorted array), each key shifts only a few places, allowing the sort to complete in nearly linear time.

Real-world datasets often exhibit this property, such as transaction logs with occasional delayed entries or leaderboard updates where only a few scores change.

Key characteristics:

- **In place:** it uses only temporary variables `key` and `j`, requiring $O(1)$ auxiliary memory.
- **Stable:** it shifts only elements strictly greater than the key (`a[j] > key`), ensuring equal elements maintain their relative order. Changing `>` to `>=` disrupts stability, which is a frequent question on exams.
- **Online:** it can process streaming data as items arrive incrementally, without needing the entire collection in advance.

<Callout tone="sky" label="The headline facts">
Insertion sort: $O(n^2)$ average and worst, $O(n)$ best, in place, stable. Highly effective on small or nearly sorted input.
</Callout>

## The lab version

```java
public static void insertionSort(int[] array) {
    for (int i = 1; i < array.length; i++) {
        int key = array[i];
        int j = i - 1;
        while (j >= 0 && array[j] > key) {
            array[j + 1] = array[j];
            j--;
        }
        array[j + 1] = key;
    }
}
```

Saving `key = array[i]` before the loop is required. The first shift operation, `array[j + 1] = array[j]`, overwrites index `i`. Without saving the value first, that element is overwritten and lost.

In the `while` condition, `j >= 0` must precede `array[j] > key`. Java evaluates boolean `&&` with short-circuit evaluation: once `j >= 0` evaluates to false at index `-1`, execution stops before evaluating `array[-1]`. Reversing this condition causes an `ArrayIndexOutOfBoundsException` whenever an element belongs at index 0.

Compare its performance against [selection sort](/courses/algorithm-design-and-analysis/selection-and-bubble-sort#selection-sort-find-the-smallest-put-it-first) on 5,000 random integers. Then test both algorithms on an already sorted array. Selection sort takes the same time as before, whereas insertion sort finishes almost instantaneously.
