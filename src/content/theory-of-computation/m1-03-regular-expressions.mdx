# Reading and Writing Regular Expressions

The Language of Languages defined regular expressions with three rules: union, concatenation and star. This lesson is about using them. Exams ask three kinds of question about regular expressions, and you'll practice all three here:

1. **Describe the language** of a given expression in words.
2. **List the first words** of its language.
3. **Write an expression** for a language described in words.

## The notation, and what binds tighter

Course notes and exams use textbook notation, which differs from the regex in your editor in one important way: **$+$ means "or"**. In `grep` or JavaScript, `+` means "one or more", but here $a + b$ is the language $\{a, b\}$.

| Notation | Means | Example | Language |
| --- | --- | --- | --- |
| $r_1 + r_2$ | union: $r_1$ or $r_2$ | $a + b$ | $\{a, b\}$ |
| $r_1 r_2$ | concatenation: $r_1$ then $r_2$ | $ab$ | $\{ab\}$ |
| $r^*$ | zero or more repetitions of $r$ | $a^*$ | $\{\varepsilon, a, aa, \ldots\}$ |
| $\varepsilon$ (or $\lambda$, $\Lambda$) | the empty string | $a + \varepsilon$ | $\{\varepsilon, a\}$ |

Star binds tightest, then concatenation, then union. So $ab^*$ is $a$ followed by any number of $b$'s, while $(ab)^*$ repeats the pair. And $a + bc$ is $\{a, bc\}$, not $\{ac, bc\}$. When in doubt, add brackets.

## Reading an expression

Read from the outside in. Find the top-level operator, say what each part contributes, then combine. Some examples from past exercise sheets:

- $a^* + b^*$ is "only $a$'s, or only $b$'s": $\varepsilon$, $a$, $b$, $aa$, $bb$, and so on. A word like $ab$ mixes the two, so it's **not** in the language. This is the most common trap: $a^* + b^*$ is not $(a + b)^*$.
- $a^*ab^*$ forces at least one $a$ (the one in the middle), followed by any number of $b$'s: $a$, $aa$, $ab$, $aaa$, $aab$, $abb$...
- $(a + b)^*ba(a + b)^*$ is "anything, then $ba$, then anything", so every word that **contains** $ba$ somewhere.
- $ab^*ab^*a$ has exactly three $a$'s, starts and ends with $a$, and allows any number of $b$'s in the two gaps.

## Listing the first words

When a question asks for "the first 10 words", list them **shortest first, and alphabetically within the same length**. To find them, choose the cheapest option at every part of the expression, then make one part longer at a time.

For $(ab + ba)^*aa$: the star can repeat zero times, which gives the shortest word, $aa$. One repetition gives $abaa$ and $baaa$. Two repetitions give four words of length 6. Check that against the tool below, then try the other exercise expressions: `ab*ab*a`, `(ab)*+(ba)*`, `bb(a+b)*aa`, `(ab+ba)*(bb+aa)`.

## Writing an expression

Most exam languages are built from a handful of patterns over $\Sigma = \{a, b\}$:

| The language | Pattern |
| --- | --- |
| Words that **end** with $w$ | $(a + b)^*w$ |
| Words that **start** with $w$ | $w(a + b)^*$ |
| Words that **contain** $w$ | $(a + b)^*w(a + b)^*$ |
| Words with **exactly one** $a$ | $b^*ab^*$ |
| Words of **even length** | $((a + b)(a + b))^*$ |

When two different shapes are allowed, write each as its own expression and join them with $+$. Then test your answer from both sides: list a few words it generates and check each belongs, and think of a word that belongs and check your expression generates it. The checker below does the second half for you by trying every word up to length 8 and reporting the shortest one where your answer and the language disagree.

## Where this shows up today

<ApplicationsGrid>
  <PracticalApplication title="Translating to tool syntax" tool="GREP">
    Textbook union $+$ is `|` in tools, so $(a + b)^*bbb$ becomes `(a|b)*bbb`. Tools add shorthands like `a+` for $aa^*$ and `a?` for $(a + \varepsilon)$, but every one of them can be rewritten with the three textbook operators.
  </PracticalApplication>
  <PracticalApplication title="Input validation" tool="WEB">
    Patterns in HTML `pattern` attributes and validation libraries are regular expressions. Writing them with the "starts with / contains / exactly one" patterns above, then testing the empty string first, catches most bugs before users do.
  </PracticalApplication>
</ApplicationsGrid>
