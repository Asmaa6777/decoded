# NFA: Nondeterministic Automata

In a DFA, every state has exactly one arrow out for every symbol: one input, one output.

Now remove that constraint. What if a state could have two arrows for the same symbol, and the machine took both paths at once? What if an arrow could fire without consuming any symbol? What if some states had no arrow for a given symbol, and the machine simply stopped there?

That is an **NFA**, a nondeterministic finite automaton. It looks like a DFA with the rules loosened. Even so, Rabin and Scott proved in 1959 that NFAs recognize exactly the same class of languages as DFAs, even though the two can look completely different.

## What Changes

The formal definition of an NFA is almost identical to a DFA's. Only the transition function δ changes:

**DFA:** $\delta : Q \times \Sigma \rightarrow Q$

**NFA:** $\delta : Q \times \Sigma_\varepsilon \rightarrow \mathcal{P}(Q)$

The signature has two differences. First, $\Sigma_\varepsilon = \Sigma \cup \{\varepsilon\}$: the machine can transition on the empty string, moving to a new state without consuming any symbol. That can feel strange at first, and an example below makes it concrete.

Second, $\mathcal{P}(Q)$ is the **power set** of $Q$, the set of all subsets of states. So δ no longer returns a single next state. It returns a *set* of possible next states, which may be $\emptyset$, meaning there's no transition at all.

Everything else ($Q$, $\Sigma$, $q_0$, $F$) means exactly what it meant for a DFA.

<Callout tone="violet" label="The one change summarized">
  A DFA's δ returns one state, and an NFA's δ returns a set of states. Returning a set instead of a single value is the whole definition of nondeterminism.
</Callout>

## How to Read an NFA

When an NFA is in state $q$ and reads symbol $a$, it does not pick one next state. It **splits into copies**, one per state in $\delta(q, a)$, and all the copies run simultaneously. If *any* copy ends in an accept state when the input runs out, the string is accepted.

Another way to think about an NFA is as a machine that always guesses right: if any path through it leads to acceptance, the NFA finds that path.

Here is a small NFA over $\Sigma = \{a, b\}$ that accepts strings ending in $ab$:

  ]}
  initial="q0"
  accepting={["q2"]}
/>

From a DFA's point of view, something is wrong here: $q_0$ has *two* arrows labeled $a$, one looping back and one going to $q_1$. A DFA can't have that. An NFA handles it by splitting: when you read $a$ from $q_0$, the machine simultaneously stays at $q_0$ and moves to $q_1$.

Also, $q_1$ has no $a$-arrow and $q_2$ has no arrows at all. Both are illegal in a DFA. In an NFA, a missing transition means that copy dies while the others keep going.

Let's trace the string $aab$:

| Step | Read | Active states |
| --- | --- | --- |
| start | | $\{q_0\}$ |
| 1 | $a$ | $q_0$ splits → $\{q_0, q_1\}$ |
| 2 | $a$ | $q_0$ splits again → $\{q_0, q_1\}$. $q_1$ has no $a$-arrow, that copy dies |
| 3 | $b$ | $q_0$ on $b$ → $q_0$. $q_1$ on $b$ → $q_2$ → $\{q_0, q_2\}$ |
| end | | $q_2 \in F$ → **Accepted** |

Now trace $ba$:

| Step | Read | Active states |
| --- | --- | --- |
| start | | $\{q_0\}$ |
| 1 | $b$ | $q_0$ on $b$ → $\{q_0\}$ |
| 2 | $a$ | $q_0$ splits → $\{q_0, q_1\}$ |
| end | | neither $q_0$ nor $q_1$ is in $F$ → **Rejected** |

The machine accepts exactly the strings ending in $ab$: anything can come before, as long as the last two symbols are $a$ then $b$.

Try building the equivalent DFA in your head. You'd need states for "I just saw an $a$", "I just saw $ab$" and "neither", with every transition filled in. The NFA also has three states, but it was much easier to design: you describe the ending you want and let nondeterminism handle whatever comes before it.

## ε-Transitions

NFAs have one more feature: the **ε-transition**. An arrow labeled ε is a transition that happens without consuming any symbol, and the machine can take it freely at any point.

It's a design convenience and adds no new power. It lets you connect machines together without redesigning either one. For example, if you have a machine that accepts $a^*$ connected by an ε-transition to another machine that accepts $b^*$, you get the combined behavior of $a^*b^*$ with no extra work.


<Callout tone="orange" label="ε-transitions do not add power">
  Every NFA with ε-transitions can be converted to an equivalent NFA without them. They're a convenience for the designer and give the machine no new capabilities. The subset construction below shows why.
</Callout>

## The Theorem: NFA = DFA

Here is what Rabin and Scott proved in 1959:

> Every NFA has an equivalent DFA that recognizes exactly the same language.

The proof is constructive and gives you a mechanical procedure called the **subset construction** for building the DFA directly from the NFA.

The idea: if an NFA can be in several states at once, build a DFA where each state stands for a set of NFA states, namely all the states the NFA could currently be in.

For an NFA with $n$ states, the DFA has at most $2^n$ states, one per subset of $Q$. In practice most subsets are unreachable and the DFA ends up much smaller, but the worst case is exponential.

Let's convert the NFA above to a DFA.

NFA states: $Q = \{q_0, q_1, q_2\}$. DFA states are subsets of $Q$. Start: $\{q_0\}$.

From $\{q_0\}$:
- on $a$: $q_0$ goes to $\{q_0, q_1\}$ → DFA state $\{q_0, q_1\}$
- on $b$: $q_0$ goes to $\{q_0\}$ → DFA state $\{q_0\}$

From $\{q_0, q_1\}$:
- on $a$: $q_0$ → $\{q_0, q_1\}$, $q_1$ has no $a$-arrow → $\emptyset$ → union is $\{q_0, q_1\}$
- on $b$: $q_0$ → $\{q_0\}$, $q_1$ → $\{q_2\}$ → union is $\{q_0, q_2\}$

From $\{q_0, q_2\}$:
- on $a$: $q_0$ → $\{q_0, q_1\}$, $q_2$ has no $a$-arrow → $\{q_0, q_1\}$
- on $b$: $q_0$ → $\{q_0\}$, $q_2$ has no $b$-arrow → $\{q_0\}$

That's three reachable states out of $2^3 = 8$ possible subsets. The accept states are the DFA states containing $q_2$, which here is just $\{q_0, q_2\}$.

$$
\begin{array}{c|cc}
\delta_{DFA} & a & b \\
\hline
\{q_0\} & \{q_0, q_1\} & \{q_0\} \\
\{q_0, q_1\} & \{q_0, q_1\} & \{q_0, q_2\} \\
\{q_0, q_2\} & \{q_0, q_1\} & \{q_0\} \\
\end{array}
$$

It's the same language, now as a complete DFA with every cell filled.

<Callout tone="sky" label="Why this matters in tools you already use">
  Regex engines convert your pattern into an NFA first, because NFAs map onto regex syntax one piece at a time. Then they either simulate the NFA by tracking the set of active states, or convert it to a DFA for faster repeated matching. Both are direct applications of Rabin and Scott's result, running in tools you use every day, like your terminal.
</Callout>

## NFA vs DFA: Which One to Use When

Because of the equivalence theorem, you can use whichever representation is more convenient. In practice it depends on the task:

**Design in NFA:**
- When describing patterns like "strings containing `aba` as a substring," an NFA is natural. You guess when the pattern starts and verify the rest.
- Building the equivalent DFA directly forces you to track multiple conditions in one state, which can be harder to reason about from scratch.

**Execute as DFA:**
- A DFA processes input in exactly $n$ steps for a string of length $n$, with one state transition per symbol and no branching.
- An NFA simulation must maintain a set of active states at each step. For regex engines processing millions of strings, the DFA is faster.

The standard pipeline followed by most serious regex engines:

1. Write regex
2. Convert to NFA
3. Convert NFA to DFA via subset construction
4. Minimize the DFA
5. Simulate

This is what tools like `lex`, `flex` and `ripgrep`'s regex engine do, so the theory here is also the pipeline inside your toolchain.

<Callout tone="mint" label="Where you stand">
  NFAs and DFAs are two faces of the same model. The NFA is the design tool: compact, readable, and close to regex syntax. The DFA is the execution tool: deterministic, fast, and implementable as a lookup table. The subset construction converts one into the other mechanically. The next lesson shows how regex syntax maps onto NFA construction, operator by operator.
</Callout>
