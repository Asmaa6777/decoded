# Practical: Building Regex from Automata

A **regular expression** is just a human-readable notation for a finite automaton. When you write `\d{3}-\d{4}`, the engine compiles that pattern into a state machine, then walks it across your input one character at a time. The "regex" feels magical because the underlying math is exactly powerful enough to do this — and exactly weak enough to do it in linear time.

In this practical, you'll write regex patterns that match the same languages as the automata you just learned to trace.

## Exercise C: The ReDoS trap

This exercise teaches catastrophic backtracking (ReDoS) by example. The pattern `(a+)+$` is intentionally pathological — try it against a long string of `a`'s followed by a single non-matching character (e.g., `"aaaaaaaaaaaaaaaaaaaaaaaaa!"`). Watch what happens: the regex engine will try exponentially many ways to match the nested `+` quantifiers before finally giving up. In real code, this can hang your application.

<RegexPlayground
  prompt="Try the ReDoS trap: (a+)+$ with overlapping quantifiers. Type a pattern, then test it against long strings of 'a' followed by a non-matching character to see catastrophic backtracking."
  testCases={[
    { string: "aaa", shouldMatch: true },
    { string: "aaaaaaa", shouldMatch: true },
    { string: "a".repeat(20), shouldMatch: true, note: "20 a's, should match but may be slow" },
    { string: "a".repeat(25) + "!", shouldMatch: false, note: "25 a's then !, watch the timeout" },
  ]}
  placeholder="(a+)+$"
  solutionHint="This is a demonstration, not an exercise to 'solve'. Try (a+)+$ and watch it hang on the long string with a '!' at the end. Then try a*.* as a non-catastrophic alternative."
/>

<Callout tone="sky">
<strong>The senior-engineer move:</strong> Knowing automata changes how you read regex. When catastrophic backtracking blows up production (the classic ReDoS attack), you can explain *why*: someone wrote a pattern that the engine had to simulate as an NFA with exponential paths. The fix isn't guessing — it's rewriting toward a pattern the engine can compile to a deterministic DFA. That's the difference between using a tool and understanding one.
</Callout>
