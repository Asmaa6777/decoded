# The Language of Languages

Before any CPU or GPU was built, and before any automaton or algorithm, mathematicians needed to agree on what they were talking about. They kept running into the same problem: how do you precisely describe an infinite collection of strings with a finite set of rules?

Natural language fails here. "All strings that start with *a* and end with *b*" describes a language well enough for a person, but a machine needs something it can check mechanically. Every symbol in the notation you're about to learn exists to remove that vagueness. In short, we need a precise language for describing languages.

## The Three-Level Hierarchy

Everything in [formal language theory](https://en.wikipedia.org/wiki/Formal_language) is built on three linked concepts, and the rest of the course rests on them.

### Alphabet: $\Sigma$

An alphabet is a **finite, non-empty set of symbols**. 

$$
\Sigma = \{a, b\}
$$

$$
\Sigma = \{0, 1\}
$$

$$
\Sigma = \{x\}
$$

The symbol $\Sigma$ (sigma) is just the conventional name. The alphabet is the raw material: the only symbols your machine is allowed to see. Think of it as the keys on a keyboard. If your keyboard only has two keys, those are the only characters you can type.

### String (Word)

A string is a **finite sequence of symbols drawn from the alphabet**. You concatenate letters, left to right, and you get a string.

$$
\Sigma = \{a, b\} \implies ab,\ bba,\ aaab\ \text{ are all valid strings}
$$

Two things to know right away. The length of a string $w$ is written $|w|$, so $|abb| = 3$ and $|a| = 1$.

The other is the string that confuses everyone: the **empty string** $\varepsilon$ (epsilon), a string of zero symbols. Be careful, because it isn't "nothing". It exists, it has length zero, and it will show up constantly.

$$
|\varepsilon| = 0
$$

<Callout tone="orange" label="The ε mistake">
  The empty string $\varepsilon$ is not the empty set $\emptyset$. The empty set contains nothing. The empty string is a real string that happens to contain no symbols. A language that contains $\varepsilon$ is different from a language that does not. This distinction will matter in every module that follows.
</Callout>

### Language: $L$

A language is a **set of strings** over some alphabet.

$$
L = \{ab,\ ba,\ aba\}
$$

$$
L = \{w \in \Sigma^* \mid w \text{ starts with } a\}
$$

Both of those are valid languages. One is finite and listed explicitly. The other is infinite and described by a rule. Since you can't list an infinite language, formal language theory is almost entirely about finding compact, mechanical rules that describe one.

## Kleene Star: $\Sigma^*$

You'll see this operator more than any other in the course.

$\Sigma^*$ means **all possible strings over $\Sigma$, including the empty string**: every string of every length, made from any combination of the alphabet's symbols.

$$
\Sigma = \{a, b\} \implies \Sigma^* = \{\varepsilon,\ a,\ b,\ aa,\ ab,\ ba,\ bb,\ aaa,\ aab,\ \ldots\}
$$

$\Sigma^*$ is always infinite (unless $\Sigma$ itself is empty). It is the universe of all strings your alphabet can produce.

The $+$ variant, $\Sigma^+$, is the same thing **without** $\varepsilon$:

$$
\Sigma^+ = \Sigma^* - \{\varepsilon\}
$$

So every language $L$ you will ever study is a subset of $\Sigma^*$:

$$
L \subseteq \Sigma^*
$$

That sums up the whole hierarchy: a language is a subset of the universe of possible strings.

<Callout tone="violet" label="Why Σ* exists">
  Think of $\Sigma^*$ as your entire string universe. Without it, you would have to define what a valid string is every single time you create a language. With it, you just write $L \subseteq \Sigma^*$, and everyone instantly knows your language is a piece of that universe.
</Callout>


## Concatenation

Concatenation is the operation of joining two strings end-to-end. If $u = ab$ and $v = ba$, then:

$$
uv = abba
$$

This extends to languages. The **concatenation of two languages** $X$ and $Y$ is:

$$
XY = \{uv \mid u \in X \text{ and } v \in Y\}
$$

Every string from $X$ paired with every string from $Y$, joined together. If $X = \{a,\ bb\}$ and $Y = \{c,\ dd\}$:

$$
XY = \{ac,\ add,\ bbc,\ bbdd\}
$$

Exponents abbreviate repeated concatenation:

$$
a^3 = aaa \qquad \Sigma^2 = \{aa,\ ab,\ ba,\ bb\}
$$

And $w^0 = \varepsilon$ for any string $w$, since concatenating zero times gives you the empty string.

## Regular Expressions: The First Compact Notation

You've probably met regular expressions through `grep`. They are also a formal mathematical notation for describing [regular languages](https://en.wikipedia.org/wiki/Regular_language), invented by [Stephen Kleene](https://en.wikipedia.org/wiki/Stephen_Cole_Kleene) in 1951, and based on exactly the three operations you just learned.

A regular expression over $\Sigma$ is defined by three rules:

**Basis.** These are the atoms:
- $\varepsilon$ is a regular expression, describing the language $\{\varepsilon\}$
- $\emptyset$ is a regular expression, describing the empty language $\{\}$
- Any single symbol $a \in \Sigma$ is a regular expression, describing $\{a\}$

**Recursion.** If $r_1$ and $r_2$ are regular expressions, so are:
- $r_1 r_2$: concatenation
- $r_1 + r_2$: union (either $r_1$ or $r_2$)
- $r_1^*$: Kleene star (zero or more repetitions of $r_1$)

**Closure.** Nothing else is a regular expression.

Those three rules generate every regular expression ever written. The regex in your editor, the pattern in your validation code and the search in your terminal are all instances of this recursive definition.

Here's a worked example. Given $\Sigma = \{a, b\}$:

$$
L = \text{language}(a^*b^*) = \{\varepsilon,\ a,\ b,\ aa,\ ab,\ bb,\ aaa,\ aab,\ abb,\ bbb,\ \ldots\}
$$

All strings of zero or more $a$'s followed by zero or more $b$'s. The regular expression $a^*b^*$ describes this infinite language in five characters.

$$
L = \text{language}((a+b)^*) = \Sigma^*
$$

That's every possible string over $\{a, b\}$. The $(a+b)^*$ pattern, which you may have seen in real regex, is the formal way of writing the entire universe of strings.

> **Note:** Throughout this course, $\Sigma = \{a, b\}$ and $\Sigma = \{0, 1\}$ are interchangeable examples, since both are just two-symbol alphabets. Do not read meaning into the symbols themselves. $a$ and $b$ are placeholders, exactly like $0$ and $1$.

## Quick Reference

| Symbol         | Name              | Means                                                    |
| -------------- | ----------------- | -------------------------------------------------------- |
| $\Sigma$       | Alphabet          | Finite, non-empty set of symbols                         |
| $\varepsilon$  | Empty string      | A string of zero symbols ($\lvert\varepsilon\rvert = 0$) |
| $\emptyset$    | Empty set         | The set containing no strings                            |
| $\Sigma^*$     | Kleene star       | All strings over $\Sigma$, including $\varepsilon$       |
| $\Sigma^+$     | Positive closure  | All strings over $\Sigma$, excluding $\varepsilon$       |
| $L$            | Language          | A subset of $\Sigma^*$                                   |
| $XY$           | Concatenation     | $\{uv \mid u \in X,\ v \in Y\}$                          |

<Callout tone="mint" label="What you just built">
  You now have the three primitives that everything else in this course rests on: an alphabet defines the symbols, strings are finite sequences of those symbols, and languages are sets of strings. Regular expressions are the first tool for describing those sets compactly. Every machine you study from here (finite automata, then pushdown automata) is a different mechanism for deciding which strings belong to a language and which don't.
</Callout>
