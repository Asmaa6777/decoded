# Transition Graphs

A DFA is strict: exactly one start state, exactly one edge per letter out of every state, and every edge reads a single letter. Those rules make it fast to run, but awkward to design. A **transition graph** (TG) drops all three, and in exchange it becomes much easier to draw.

## What changes

A transition graph has:

- a finite set of states, **at least one** of which is a start state (marked $-$), and some final states (marked $+$);
- an alphabet $\Sigma$;
- edges labelled with **words** over $\Sigma$, not just single letters. A label can also be $\Lambda$, the empty word, which lets the machine move without reading anything.

A word is **accepted** if you can cut it into pieces, $w = w_1 w_2 \ldots w_k$, so that some path from a start state to a final state has edges labelled $w_1$, $w_2$, ..., $w_k$ in that order. If no such cut and path exist, the word is rejected.

Nothing else is required. A state can have no edge for some letter, two edges with the same label, or both. The machine doesn't have to be told which path to take; a word is in the language as long as **some** path works.

<Callout tone="violet" label="Every FA is a TG">
  A finite automaton is a transition graph that happens to follow extra rules: one start state and single-letter labels, one edge per letter. So anything a DFA or NFA can do, a TG can do too. The question for the next lesson is whether TGs can do *more*.
</Callout>

## Words on edges

Here is a TG for all words over $\{a, b\}$ that end in $bb$. State 1 loops on $a$ and on $b$, and one edge labelled with the whole word $bb$ leads to the final state.

  initial="abbabb"

Try `abbabb`, then `abba` and `bb`. For an accepted word the runner shows the cut: `abbabb` becomes a | b | b | a | bb, four trips around the loop and then the $bb$ edge. The DFA for the same language needs three states and has to remember "I've just seen one $b$". The TG doesn't have to, because the edge reads both $b$'s at once.

## Several starts and free moves

This TG has two start states, $x$ and $y$, and a $\Lambda$-edge from $y$ to $z$:

<TgRunner
  tg={{
    states: ["x", "y", "z"],
    start: ["x", "y"],
    final: ["z"],
    edges: [
      { from: "x", to: "z", label: "ab" },
      { from: "y", to: "y", label: "b" },
      { from: "y", to: "z", label: "Λ" },
      { from: "z", to: "z", label: "aa" },
    ],
  }}
  layout={[{ id: "x", x: 0, y: -70 }, { id: "y", x: 0, y: 70 }, { id: "z", x: 240, y: 0 }]}
  initial="bbaa"
/>

From $y$, the machine reads any number of $b$'s, slips to $z$ for free, and then reads $aa$ any number of times. From $x$, it reads $ab$ once and then the same $aa$ loop. So the language is $(ab + b^*)(aa)^*$. Check that the empty word is accepted (start at $y$, take the $\Lambda$-edge) and that `ba` isn't.

<Callout tone="orange" label="Λ is not a letter">
  An edge labelled $\Lambda$ consumes nothing. It's a free move, not an edge that reads some symbol called lambda. In exam drawings, don't confuse it with a missing label.
</Callout>

## From a TG to a regular expression

Exams often draw a TG and ask for its regular expression. The method is **state elimination**: replace the TG by a *generalized* transition graph, where edges are labelled with regular expressions instead of words, and remove states one at a time until a single edge is left.

1. Add a new start state $-$ with $\Lambda$-edges into every old start state, and a new final state $+$ with $\Lambda$-edges out of every old final state. Now the machine has one way in and one way out.
2. If two edges join the same pair of states, merge them: labels $r_1$ and $r_2$ become one edge labelled $r_1 + r_2$.
3. Pick a state $q$ to remove. For every path $p \rightarrow q \rightarrow s$ through it, add an edge $p \rightarrow s$ labelled with the incoming label, then the loop on $q$ starred, then the outgoing label. If $p \rightarrow s$ already had an edge, join the two with $+$.
4. Repeat until only $-$ and $+$ are left. The label on the edge between them is the answer.

Step 3 is the one to understand. If you could go from $p$ to $q$ on $r_1$, circle around $q$ any number of times on $r_2$, and leave to $s$ on $r_3$, then the new edge $p \rightarrow s$ is $r_1 r_2^* r_3$.

Here is the finite automaton for "an even number of $a$'s" over $\{a, b\}$. State 1 is both the start and the only final state.

<StateEliminator
  tg={{
    states: ["1", "2"],
    start: ["1"],
    final: ["1"],
    edges: [
      { from: "1", to: "1", label: "b" },
      { from: "1", to: "2", label: "a" },
      { from: "2", to: "2", label: "b" },
      { from: "2", to: "1", label: "a" },
    ],
  }}
  layout={[{ id: "1", x: 0, y: 0 }, { id: "2", x: 220, y: 0 }]}
  order={["2", "1"]}
/>

Removing state 2 first turns the path $1 \rightarrow 2 \rightarrow 1$ into a loop on 1 labelled $ab^*a$, which merges with the existing loop $b$. Removing state 1 then gives $(b + ab^*a)^*$: any mix of single $b$'s and blocks that start and end with an $a$. Every word it generates has an even number of $a$'s.

<Callout tone="sky" label="Order changes the expression, not the language">
  Eliminating states in a different order usually gives a different-looking expression. Both are correct, because they describe the same language. If your answer doesn't match the solution sheet letter for letter, list the first few words of each before deciding you're wrong.
</Callout>

## Where this shows up today

<ApplicationsGrid>
  <PracticalApplication title="Literal prefilters" tool="RIPGREP">
    Fast search tools pull literal strings out of a pattern and scan for those first, only running the full automaton near a hit. Treating a fixed word as one step, like a TG edge labelled $bb$, is the same idea.
  </PracticalApplication>
  <PracticalApplication title="Lexer generators" tool="LEX / FLEX">
    A lexer generator joins one automaton per token type under a single new start state with $\Lambda$-edges, exactly like step 1 of state elimination, then converts the combined machine into one DFA.
  </PracticalApplication>
  <PracticalApplication title="Word segmentation" tool="TEXT">
    Splitting "thisisatest" into dictionary words is acceptance in a TG whose edges are labelled with dictionary words. Search engines and input methods for languages written without spaces do this constantly.
  </PracticalApplication>
</ApplicationsGrid>
