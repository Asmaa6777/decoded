# CFG = PDA

Module 1 ended with Kleene's theorem: regular expressions, finite automata and transition graphs describe the same languages. Module 2 has its own version, with grammars playing the part of regular expressions and pushdown automata playing the part of finite automata. The course states it as two theorems:

> **Theorem 1.** Given a language $L$ generated by a context-free grammar, there is a PDA that accepts exactly $L$.
>
> **Theorem 2.** Given a language $L$ accepted by a PDA, there is a context-free grammar that generates exactly $L$.

Together they say that the context-free languages are exactly the languages pushdown automata accept, which is the "pushdown automaton" entry in the type 2 row of the Chomsky hierarchy.

## From a grammar to a PDA

The proof of Theorem 1 is a construction, and you can carry it out by hand. Start from a grammar in Chomsky Normal Form, so every rule is $X \rightarrow YZ$ or $X \rightarrow a$. The PDA has one central POP box:

1. START, then **PUSH $S$**, then go to the POP.
2. For every rule $X \rightarrow YZ$: an edge labelled $X$ out of the POP, then **PUSH $Z$**, then **PUSH $Y$**, then back to the POP. $Z$ goes in first so that $Y$ ends up on top.
3. For every rule $X \rightarrow a$: an edge labelled $X$ out of the POP into a READ box, and an edge labelled $a$ from that READ back to the POP.
4. An edge labelled $\Delta$ out of the POP (the stack is empty) into a READ, and from there an edge labelled $\Delta$ (the input is used up) to ACCEPT.

Here it is for $S \rightarrow aSb \mid \Lambda$. The box converts the grammar to CNF first, then builds the machine.

<GrammarToPda grammar="S -> aSb | ε" initial="aabb" />

Step through `aabb` and watch the line beside the stack. Every time the run is back at the POP box, the letters read so far followed by the stack from the top down form one step of a leftmost derivation: $S$, then $T_1V_1$, then $aV_1$, and so on until $aabb$. (In between, while a rule is half applied, the line is greyed out.) The machine is running the derivation, with the stack holding the part of the sentential form that hasn't been turned into letters yet. That's why it works: a word reaches ACCEPT exactly when some leftmost derivation produces it.

Because each rule is applied by one POP, and a CNF derivation of a word of length $n$ uses exactly $2n - 1$ rules, the PDA pops exactly $2n - 1$ variables on an accepting run. For `aabb`, count seven.

Now edit the grammar to `S -> AbA | BaB`, `A -> aA | a`, `B -> bB | b` from the exercise sheet and build again. There are several edges with the same label out of the POP, so the machine is nondeterministic: it has to guess which rule to use, just as you do when you derive a word by hand.

<Callout tone="orange" label="When Λ is in the language">
  A CNF grammar can't generate $\Lambda$, so a PDA built from it rejects the empty word. The notes fix this by adding one more circuit to the PDA, a loop at the POP for $S \rightarrow \Lambda$. That loop is safe when $S$ never appears on a right-hand side. The box above uses a version that is always safe: a second branch out of START that reads $\Delta$ and accepts, so it accepts the empty word and nothing else.
</Callout>

## From a PDA to a grammar

Theorem 2 is the harder direction. The proof builds a grammar with one variable for each way of travelling between two points of the PDA while the stack goes up and comes back down to where it was; the rules glue such trips together. The construction is long, and exams usually ask for the statement and for the direction above, not for this one. What matters is the result: anything a PDA can do, a grammar can describe.

## What it means

Every context-free grammar comes with a machine that recognizes its language, using one stack. That machine is usually nondeterministic. Real parsers can't guess, so they restrict the grammar enough that the next input letter always tells them which rule to use. Then the same machine becomes deterministic.

Some languages need more than one stack. $a^nb^nc^n$ has to compare three counts, and a single stack can only compare two before it's used up. It's context-sensitive, not context-free. A machine with two stacks turns out to be as powerful as a Turing machine, the model behind everything a computer can compute. That's where the Chomsky hierarchy, and courses after this one, go next.

## Where this shows up today

  <PracticalApplication title="Top-down parsers" tool="LL PARSING">
    An LL parser is this exact machine: a stack that starts with the start symbol, expanding the variable on top or matching the terminal on top against the input. It decides which rule to use by looking at the next token in a table built from FIRST and FOLLOW sets, which is how a compiler course makes the construction deterministic.
  </PracticalApplication>
  <PracticalApplication title="Parser generators" tool="ANTLR / BISON">
    Hand a parser generator a grammar and it hands back a parser: a stack machine built from the rules. Theorem 1 is the reason that's always possible, and the restrictions these tools put on grammars are what make the machine deterministic.
  </PracticalApplication>
