# Practical: Building Regex from Automata

A **regular expression** is a human-readable way of writing down a finite automaton. When you write something like `\d{3}-\d{4}`, the computer turns it into a set of instructions it can follow, then goes through your input one character at a time to check whether it matches. Regular expressions can seem magical because they do this so efficiently.

In this practical lesson, you'll write regex patterns that match the same languages as the automata you just learned to trace.

## Exercise C: The ReDoS trap

This exercise shows catastrophic backtracking (ReDoS) by example. The pattern `(a+)+$` is deliberately pathological. Try it against a long string of `a`'s followed by one non-matching character (e.g., `"aaaaaaaaaaaaaaaaaaaaaaaaa!"`). The regex engine tries exponentially many ways to match the nested `+` quantifiers before it gives up, and in real code that can hang your application.

<RegexPlayground
  prompt="Try the ReDoS trap: (a+)+$ with overlapping quantifiers. Type a pattern, then test it against long strings of 'a' followed by a non-matching character to see catastrophic backtracking."
  testCases={[
    { string: "aaa", shouldMatch: true },
    { string: "aaaaaaa", shouldMatch: true },
    { string: "a".repeat(20), shouldMatch: true, note: "20 a's, should match but may be slow" },
    { string: "a".repeat(25) + "!", shouldMatch: false, note: "25 a's then !, watch the timeout" },
  ]}
  placeholder="(a+)+$"
  solutionHint="This is a demonstration, not an exercise to 'solve'. Try (a+)+$ and watch it hang on the long string with a '!' at the end. Then try a*.* as a non-catastrophic alternative."
/>

<Callout tone="sky">
<strong>The senior-engineer move:</strong> Knowing automata changes how you read regex. When catastrophic backtracking takes down production (the classic ReDoS attack), you can explain *why*: someone wrote a pattern the engine had to explore as an NFA with exponentially many paths. Instead of guessing at a fix, you rewrite it into a pattern the engine can compile to a deterministic DFA.
</Callout>
